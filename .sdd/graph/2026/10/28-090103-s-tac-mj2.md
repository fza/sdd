A graph whose `.sdd/meta.json` records schema 2 is still read by a build of this repository's `fza` branch, which refuses it only on a write. In the titles evaluation's smoke run (20261028-082723-s-tac-x07), on a scratch graph with meta.json set to 2, `sdd view` listed the entries, while `sdd new` stopped with `graph schema version 2: unknown to this binary` and wrote nothing. The schema check in `internal/cliapp/writegate.go` wraps only the write commands.

The titles directive (20261028-005411-d-tac-tit) expects a graph at 2 to be refused as unknown to the binary until it is set back to 1 by hand. As built, its owners learn of the refusal only on their first write, and reads of a graph recording a schema the binary does not know go unwarned.

Candidates, unsettled: refuse every command on an unknown schema; or keep reads running and print a warning that names the hand fix.
