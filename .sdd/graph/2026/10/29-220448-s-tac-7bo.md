`sdd config` now shows the `llm.extract_timeout` default and an extraction call that runs out its bound names the setting, on branch `pr/feat-verdict-extraction` in commit `09e8f47a`, closing the gap 20261029-220401-s-tac-6iv.

- The effective config lists `llm.extract_timeout` at its 1-minute default, written `1m0s`, until a layer sets it.
- An extraction call that runs out its bound fails with the bound and `sdd config set llm.extract_timeout <duration>` in its error; a deadline the caller set itself passes through unchanged.
- To make that naming reachable, the `claude-cli` adapter now keeps the deadline as the error's cause instead of `claude -p timed out (increase with --preflight-timeout)`: the same two-line change the `claude-cli` timeout fix (20261029-210859-s-tac-x9d) makes in `ce04ea58` on `pr/fix-claude-cli-timeout`, so the two branches change those lines alike.

The reasoning calls' `llm.timeout` stays as this branch had it: naming that setting belongs to the `claude-cli` timeout fix, and the fork's integration branch `fza-fork` carries both fixes together.
