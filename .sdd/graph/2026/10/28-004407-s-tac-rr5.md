Automatic graph sync has not been validated where it is meant to serve: inside a live engine session driven by an agent over MCP, and between two people working against one graph remote.

Actual: the engine path, a step's commit published before the step responds and upstream graph commits merged on every session call, is covered only by tests in `pkg/local`, `pkg/application` and `internal/cliapp` against bare remotes. The outer run of the sync evaluation (20261028-002921-s-tac-bb0) exercised the CLI alone, and the sdd serving the session that ran it was the installed release, not a build carrying the sync. No two participants have used it on a shared graph.

Expected: the sync directive (20260817-162701-d-cpt-r8k) exists so collaborating participants get immediate feedback on each other's movement, an outcome that only a session in real use, with a second participant capturing on the same remote, can confirm.

The gap closes with an outer evaluation that runs a build carrying the sync as the session's MCP server, with two participants on one remote under `sync.mode: auto`.
