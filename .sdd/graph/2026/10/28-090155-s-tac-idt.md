The titles evaluation (20261028-082723-s-tac-x07) found one fix, `fix(actor): check actor_kind against every chain an entry supersedes`, as three separate commits:

- b34e4fb2 on `feat/actor-kind`;
- bea6c9db, a cherry-pick on `feat/entry-title`;
- c06dfcb5, a cherry-pick on `feat/older-schema-writes`, which also merges `feat/entry-title` and so carries both copies.

The cherry-picks let those branches compile for the titles delivery (20261028-081657-s-tac-mdl): their shared base had removed a function their code still called. A pull request from either branch therefore carries a commit that also arrives with `feat/actor-kind`.

The expected state is that a pull request from a feature branch carries only that feature's commits, so `feat/entry-title` and `feat/older-schema-writes` each review and merge on their own. The project's git rules forbid rewriting history, so dropping the copies by rebase conflicts with them; how to remove the duplication is not settled.
