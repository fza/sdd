Entry titles are optional at graph schema 1 and schema 2 is gone, closing the titles-in-schema-1 directive (20261028-005411-d-tac-tit). Commit a926745c on `feat/entry-title` sets the binary's schema to 1 with no migration defined; merge 06621c26 and commit 6a3d653e on `feat/older-schema-writes` give schema 1 the Titles capability and drop the schema-2 row; merge 2ec4cade carries both into `fza` and sets this repository's `.sdd/meta.json` to 1.

Criteria:

- Schema 1 with titles, no schema 2: met by a926745c and 06621c26.
- A capture on a schema-1 graph writes a title and accepts `--title`: met, covered by `TestWritesOnASchemaOneGraphCarryTitles` and `TestSummarizeAllFillsTitlesOnASchemaOneGraph`, and by a capture with `--title` on a scratch graph.
- An untitled entry reads and title surfaces fall back to the summary: met. On a scratch graph an entry without a title shows in full, and the brief listing names it by its first summary sentence.
- A graph recording 2 is refused as unknown: met for writes, which stop with `graph schema version 2: unknown to this binary`. Reads still run, since the schema gate in `internal/cliapp/writegate.go` wraps only writes.
- This repository's `.sdd/meta.json` records 1: met by 2ec4cade.

Both branches failed to compile before this work: they called `parentActorChain`, which their shared base had removed. Each now carries a cherry-pick of b34e4fb2 (bea6c9db on `feat/entry-title`), so that fix exists as separate commits on several branches.

The tests for writes on a schema without titles are deleted: `internal/handlers/handler_older_schema_test.go`, `TestWritesOnAnOlderGraphPointAtMigrate`, and the schema-1 cases of the older-schema and info tests. The code paths that leave out a title and refuse an explicit `--title` on such a schema stay, but no schema reaches them now, so no test covers them.

Other graphs whose `.sdd/meta.json` records 2 stay refused for writes until their owners set it to 1 by hand.
