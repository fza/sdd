A merge conflict the automatic pull finds during an engine session reaches the agent as a notice in the serve: the conflicting paths, the upstream ref, and the instruction to resolve them with git and commit the merge with the message `sdd: merge <upstream>`. The engine serves no resolve step and does not commit the resolution itself.

This narrows the conflict criterion of the automatic sync plan (20261027-194536-d-tac-190). The aborted merge with a clean working tree stays; the `merge-resolve` base procedure, the `MergeConflicts` query and `ResolveMergeCmd` are dropped. Conflicts are rare in a graph repository, because new entries add new files and only edits to existing files collide, and a procedure, a query, a command and a two-parent commit path through the `GraphSync` port are a large maintenance surface for that rare case.

Rejected: the served resolve step as planned, for that surface; leaving conflicts unreported, which lets the agent keep working on a branch that silently stopped syncing, since the engine's sync warning reaches only the server log.

Accepted cost: resolution goes unguided. A merge committed with a message not matching `^sdd:` holds every later automatic push until someone repairs the branch; the notice names the exact message to make that unlikely.
