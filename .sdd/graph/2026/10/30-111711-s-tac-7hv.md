An `sdd` failing before `merge-entry` runs now ends an entry merge in git's text merge with markers: commit `49ea509d` on branch `pr/feat-merge-entry` gives a written conflict its own exit code and fixes six of the seven driver defects, closing the exit-code directive (20261030-105455-d-tac-zrc) and the defect gap (20261030-104530-s-tac-bz1).

All three criteria of the directive are met. A git-level test runs an `sdd` stub exiting 1 with a flag error and finds both summaries between markers, beside stubs exiting 3 and no `sdd` at all; another shows a file `merge-entry` wrote standing as written, merged on exit 0 and conflicted on exit 10. Both earlier driver values, the bare command and the exit-1 form, are upgraded.

Gap items:
1. Covered by the directive.
2. A repeat `sdd init` without `--graph-dir` takes `graph_dir` from the recorded config, an absolute value made relative to the repository, and creates no `.sdd/graph` beside it.
3. After a clean merge, a title or summary stated twice with identical lines keeps its first statement in file order, the same file from either side.
4. Driver setup left git's `Commit` and `RemovalCommitter`; the handler sets it up after the commit and its push, so a config it cannot write still fails the command but never costs the push. A failed write re-reads the key it was writing. The once-per-process cache is gone: setup costs two git calls per commit and init and commits share one method.
5. Not fixed, and not fixable: a build predating the driver runs its own startup, sync check included, before answering `merge-entry` with an unknown-command error, and no flag or environment value reaches that startup. Builds carrying the driver already skip startup for `merge-entry`.
6. A merge-driver finalizer runs last on local mutation targets, so a capture through `sdd serve` or MCP sets the driver up, the retry of a finished publication included.
7. The routing pattern is checked before init writes anything; a graph directory with whitespace or a leading quote is written C-quoted and glob characters are escaped, each confirmed by `git check-attr`; absolute paths, `..` and `../` stay refused. A leading `#` or `!` is refused earlier by the `.gitignore` check.

25 new guards broken and caught. One guard no test reaches: the re-read after a concurrent config write, a race between two git calls. A three-clone smoke run on the rebuilt binary merges two different summaries clean and leaves both between markers with an `sdd` exiting 3. Not yet merged into `pr/core` or `fza-fork`.
