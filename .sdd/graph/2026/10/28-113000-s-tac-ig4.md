Up to release v0.18.0-alpha.2, the `claude-cli` LLM provider runs the `claude` CLI inside the caller's project tree with the caller's full environment, so each sdd call carries that project's agent setup and may answer on a credential other than the signed-in account.

Expected, as a natural expectation: an sdd LLM call runs on the prompt sdd composed and nothing else, and the `claude-cli` provider answers on the signed-in Claude account, the reason to pick it over `provider: anthropic`, which sends an API key deliberately.

Actual, in v0.18.0-alpha.2: the provider starts `claude -p --model <model> --output-format json` with neither a working directory nor an environment of its own. Started inside a project, the CLI loads that project's instruction files, skills, hooks and configured MCP servers into a call that needs none of them. An inherited `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_BASE_URL`, `CLAUDE_CODE_USE_BEDROCK` or `CLAUDE_CODE_USE_VERTEX` redirects the call away from the signed-in account, and nothing in the output says which credential answered.
