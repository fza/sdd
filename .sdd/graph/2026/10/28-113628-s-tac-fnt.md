Up to release v0.18.0-alpha.2, sdd reads and writes the machine-local config layer only at `.sdd/config.local.yaml` inside the checkout, so a run cannot take that layer from anywhere else.

Expected, as a natural expectation: a sandbox, a CI runner or a second identity working in the same checkout can supply its own machine-local layer (participant, API keys, endpoints) without writing a file into the checkout, as the layer holds per-machine, per-run facts.

Actual, in v0.18.0-alpha.2: every read of the layer and every `sdd config set --local` / `unset --local` resolve the path as `.sdd/config.local.yaml` under the checkout's `.sdd/` directory, and `sdd init --participant` writes the participant there. No flag or environment variable names another file. Without a `.sdd/` directory there is no machine-local layer at all.
