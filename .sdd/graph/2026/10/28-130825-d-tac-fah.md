An LLM operation that expects structure may run on an endpoint that refuses a response schema, provided the endpoint returns a JSON object on request and sdd validates the answer against the schema itself. Everywhere else the restriction of 20261004-135748-d-tac-ndh stands: no free-text JSON, and a failure is loud.

This is the revisit that directive provides for: some OpenAI-compatible services that users need serve a model in `json_object` mode only and refuse a `json_schema` request for it, while another service accepts `json_schema` for the same model. Refusing them rules out structured checks on those services entirely.

What holds on such an endpoint:
- The request asks for a JSON object and states the schema in the system prompt.
- sdd validates the answer against the schema. An answer that does not validate goes to the one reformat call the structured checks already have; if that answer does not validate either, the check fails.
- `json_schema` stays the default: `auto` sends the schema and switches to `json_object` only for an endpoint and model that refused it, and logs the switch.

The guarantee on these endpoints is validation by sdd rather than enforcement by the provider: a model can still produce an answer that misses the schema, which costs a reformat call or a failed check instead of a malformed result reaching the graph.

Rejected: requiring `json_object` to be set explicitly with `json_schema` as the only default, which leaves users on schema-refusing services with failing checks until they find the setting; removing these modes from the upstream branch, which keeps those services unusable for structured checks; and leaving the conflict to branch review, which ships code that contradicts an active directive.
