Ownership of a blocked graph sync is a lease: it lapses when the owning session makes no sdd call for 15 minutes or ends, and the next agent to call then owns the fix. The first caller still claims an unowned block and only the owner gets the fix steps, as the blocked-state directive (20261028-201909-d-tac-fxp) sets out; the lease applies to each branch's record (20261028-231901-d-tac-kr9).

Without a lapse the first caller keeps ownership for as long as the block lasts. When that caller is a short subagent, or a session that ended, went idle or crashed, every other agent is told to leave the fix to it, and a conflict keeps automatic sync paused for all of them until someone runs `sdd sync` by hand. An independent code review of the timed sync implementation (branch `pr/feat-timed-graph-sync`) traced this: the record carries its owner forward each round, a claim fills only an empty owner, and a session's last call still claims.

The record holds the owner and when the owner last called; each owner call renews it, and a session that concludes or is abandoned releases what it owns.

Rejected: passing ownership only when the owner session ends, since an idle or crashed session never ends and keeps the fix stranded. Rejected: the lease without the release on session end, since others would wait up to 15 minutes after an owner that already concluded. Accepted cost: an owner resolving a long merge with git alone, calling no sdd tool, can lose ownership mid-fix, so two agents may briefly work on the same block.

## Acceptance criteria

- [ ] A block whose owner made no sdd call for 15 minutes is claimed by the next calling session, which gets the fix steps.
- [ ] Each call by the owner renews its lease.
- [ ] A session that concludes or is abandoned releases the blocks it owns, and the next caller claims them.
