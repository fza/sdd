Contribution mode works in a project_dir layout. Every command resolves its config from the project's repository, the committed layer plus that checkout's `.sdd/config.local.yaml`, and the guard judges the branch the project's checkout has checked out, where the graph's commits land. `contribution` is therefore set in the project repository's checkout. The work repository's machine-local config accepts only `project_dir` and refuses the key, which is correct: no graph write lands there. Commit 976f719b on branch fix/contribution-project-dir tests the layout: a capture run from the work repository is refused while the project is on its default branch and lands once the project's checkout is on a feature branch cut from the ref.

Commit dfac6f54 on branch feat/contribution-mode adds a capture driven through MCP (`start_procedure`, `next`, `bind_branch`) over the production repository targets. The agent is served the refusal's cause on the default branch, and the capture lands on the feature branch after `bind_branch`.
