Timed graph sync (20261028-175735-d-tac-k4y) is decomposed across the CQRS layers as the planning contract requires (20260413-142536-d-cpt-ah1), and the fetch moves out of the `SyncStatus` finder into a handler, so no sync path keeps a side effect in the read layer.

The finder fetches today: `Finder.SyncStatus` runs `git fetch` and stamps `.sdd/tmp/last-fetch` (`internal/finders/sync.go`), a side effect the contract names a structural gap. The timer would make a third caller of it. Rejected: reusing the finder and recording the leak as a gap, since new code would build on a known violation and the later fix would touch the timer too. Accepted cost: the shipped CLI and engine sync paths and their tests are reworked on this branch.

- **model:** `SyncConfig.Interval`; `ResolveSyncInterval` returns the interval or off when unset, malformed or below `MinSyncInterval` (one minute); `IgnoredSettings` reports `sync.interval` set in the committed layer, malformed or below the floor. A `SyncConflict` type (upstream, head, paths, delivered-to session) with pure decisions: whether a call may claim it, and whether a landed merge resolves it.
- **command:** `FetchGraphCmd` (respect cooldown; callback with the resulting sync state), `SyncRoundCmd` (one timed or per-call round), `ClaimSyncNoticeCmd` (session; callback with the notice text).
- **query:** `SyncStatusQuery` loses its cooldown flag; nothing new.
- **handlers:** `FetchGraph` (cooldown, fetch, stamp); `SyncRound` (try the sync lock, fetch, pull and publish, record or clear the conflict); `ClaimSyncNotice` (under the lock, mark delivered, return the notice through the callback); `PublishGraph` waits for the sync lock. Lock and conflict store are interfaces declared beside the handlers.
- **finders:** `SyncStatus` reads only: commit counts and merge prediction over refs already fetched, no fetch, no file write.
- **adapters:** `pkg/local` implements the lock with `gofrs/flock` and the conflict store as a file, both under the graph repository's common git directory so its worktrees share them; the sync lock is always taken before the graph lock.
- **application:** the project runtime owns the timer loop, running `SyncRound` per interval until its context ends; every read and every served step runs `ClaimSyncNotice`, replacing the notice held on the workflow session.
- **mcpapp:** search, show, view, info, registry and read_attachment results gain `sync_notice`, listed in their output schemas.
- **cliapp:** `serve` starts the timer with the server's context; `sdd config set sync.interval` refuses the committed scope, malformed values and values below the floor; the CLI sync check calls `FetchGraph`, then `SyncStatus`.

## Acceptance criteria

- [ ] `Finder.SyncStatus` performs no fetch and writes no file, shown by a test whose fake git surface fails on any fetch.
- [ ] Every fetch on the CLI, engine and timer paths runs through `Handler.FetchGraph`.
- [ ] The sync lock and conflict marker live in the graph repository's common git directory, and two worktrees of it share them.
