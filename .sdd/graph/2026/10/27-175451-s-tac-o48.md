An evaluation of the code-span titles delivery (20261027-161207-s-tac-5nk) on both lenses finds the change sound and working in use for generated titles, while agents writing a title themselves are not told the code-span rule.

Inner, a review of commit dce26ef3 against `AGENTS.md`: the prompt change is one sentence in `internal/llmops/summary_templates/title.tmpl`. The `model.CapitalizeTitle` doc comment points at the plan by ID instead of restating it. The new tests sit in external test packages at the layer owning each assertion: casing in model, storage in handlers, prompt text in llmops. Each test failed on its own assertion when its guard was removed. Every code path that writes a title passes through `model.CapitalizeTitle`. The rule reaches only the model generating a title. The 32-character limit is stated in the prompt alone and checked nowhere, a cost the plan accepted.

Outer, a live run: `sdd summarize` on four entries in a scratch graph, through the openai provider with model glm-5.3-flash, one call each. The titles were "`sdd lint` title length check", "`CapitalizeTitle` forced casing", "`replace` directive removal" and "Fork release notes omissions". Each title naming a code term writes it as a code span in its own casing, each reads as a sentence-case noun phrase within 32 characters, and the entry whose subject is no code term got a capitalized title as before. One sample per entry on one model; other providers and models were not run.
