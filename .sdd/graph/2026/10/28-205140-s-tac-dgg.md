---

When the configured graph directory does not exist, the sync check runs against another repository and reports its state as the graph's: a command in a project whose `graph_dir` names a missing path prints `sync: no remote configured` before failing on the missing directory.

Actual: with `graph_dir: ../missing-graph-dir` in a fresh project without a remote, `sdd view` printed `sync: no remote configured`, then failed with `walking graph dir: lstat …: no such file or directory`. `git.RepoRootFor` resolves the repository from the nearest ancestor of the path that exists (`internal/git/git.go`), so a missing graph directory resolves to whatever repository encloses its parent, or to none, and the sync check fetches, counts and reports there. Observed with a probe script against `bin/sdd` built from branch `fza` at `50bc2670`, and confirmed in the code.

Expected: a missing graph repository is itself a blocked sync state, named as such (20261028-201909-d-tac-fxp); sync never inspects, fetches, merges or pushes a repository other than the one holding the graph.

Candidate remedy, unsettled: resolve the graph repository only from an existing graph directory and report its absence instead of falling back to an ancestor.
