Under the default LLM setup a long entry cannot be captured: with no `llm` block in any config layer the provider is `claude-cli`, every call is bounded by a 2-minute default, and the writing guide on a directive of about 5 KB runs past it, while a short entry passes in seconds.

Actual: a project running sdd through agents on v0.18.0-alpha.2.fza.35 reported a capture of a long directive failing at the writing guide with `claude -p timed out (increase with --preflight-timeout)`, and the pre-flight on such an entry failing the same way through a capture wrapper on three retries; the timed-out child's transcript held only the prompt, with no tool call and no hook. Reproduced in a scratch project with no `llm` configuration, on a 5.3 KB directive, with both fza.35 and stock v0.18.0-alpha.2, each running `claude -p` with `claude-sonnet-4-6`: the MCP capture's writing guide timed out at 2 minutes in both, and the pre-flight through `sdd new --dry-run` passed in 72 and 93 seconds. Stock runs `claude -p` without `--safe-mode` or an isolated working directory, so the fork's isolation is not the cause. Read in the code: the 2-minute default is `defaultTimeout` in `internal/llm/factory/factory.go`; the error text sits in the claude-cli runner and names a flag only `sdd new` has, not the config key `llm.timeout` that reaches every path, MCP included; and the config defaults `sdd config` shows list the other `llm` values but neither `llm.timeout` nor `llm.extract_timeout`, so `sdd config get llm.timeout` reports no value although 2 minutes apply.

Expected: the default setup captures a long entry, and a timeout names what to change wherever it occurs. The LLM boundary directive (20260830-234501-d-cpt-q6n) makes the deadline host configuration that the local factory always composes, so the configured value is the lever, and it is neither shown nor named.

Suspected contributors, unmeasured: the `claude -p` child starts with the full Claude Code tool set and default effort for a pure text review, and returns nothing until its turn completes.

Workaround: `sdd config set llm.timeout 5m`, in the user-global config or with `--local`.
