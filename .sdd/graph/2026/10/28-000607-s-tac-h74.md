Opt-in automatic graph sync is implemented on branch `feat/graph-repository`: with `sync.mode: auto`, every graph commit from a CLI command or an engine step is pushed to the branch's upstream, and upstream graph commits are merged on the cooldown-gated sync check and on every engine session call, always in the repository holding the graph. It closes the automatic sync plan (20261027-194536-d-tac-190) and the directives that refined it during the work (20261027-211908-d-tac-l8j, 20261027-221041-d-tac-8b7, 20261027-231225-d-tac-n5o, 20261027-235201-d-tac-hkq).

Acceptance criteria of the plan, as amended by those directives:

- `sync.mode` takes `manual`, the default, or `auto`; per l8j only the user-global config and `.sdd/config.local.yaml` may set it, and a committed or unknown value leaves sync manual with a warning naming the file and key (`5feacaa6`, `4c45d084`).
- With `manual`, nothing pushes or pulls, in the CLI or the engine.
- With `auto`, a CLI graph commit reaches the upstream before the command returns (`e8cf9f23`); an engine step's commit does so before the step responds, through a finalizer that runs after the commit and publishes on a retry whose commit already landed (`eeb2887e`).
- An unpushed commit not matching `^sdd:` holds the push with a "captured but unpublished" report; a branch without an upstream is reported; a failed push fails the command with the entry and its commit kept (`e8cf9f23`). Graph commits are recognised by their subject line only (`0dcfc3ee`). Per 8b7, a push the upstream rejected is retried once after merging upstream graph commits (`5b8874ee`).
- Upstream commits all matching `^sdd:` merge with an `sdd: merge <upstream>` commit, and the next push succeeds (`d73fdb32`, `eeb2887e`). Incoming commits not all matching `^sdd:`, a dirty tree, or, per hkq, a net diff reaching beyond the graph directory, `.sdd/meta.json`, the skill folders and `.gitignore` hold the pull and are reported (`d73fdb32`, `ffc57be7`, `7ac1837f`).
- Per n5o, a conflicting merge is never started, the tree stays clean, and the CLI log and the next engine serve carry a notice naming the conflicting paths, quoted and capped, and the merge message to commit (`4ff850ff`, `cb5fcc93`). The served resolve step, `MergeConflicts` query and `ResolveMergeCmd` of the plan were not built.
- In a project_dir layout the work repository's HEAD, refs, index and remote-tracking branches stay unchanged while the graph repository syncs (`6ff0dc42`).

An independent review of the finished branch found defects that are fixed: the push now names the tracked branch so a configured push refspec cannot publish other branches, a merge no longer overwrites ignored local files, non-ASCII paths no longer hold the pull, a started merge outlives a cancelled request, engine sync and publish take the graph lock, and a capture into a graph outside the project stays manual (`d4376bb2`, `47245014`). The `SyncStatus` finder was not extended with unfiltered totals as the plan named; the handlers count them through their own git interfaces.

Still open: a notice raised on a read-only engine call (show, search, info) is dropped until the next fetch after the cooldown, and a held push reports its line twice in one command, once from the sync check and once after the commit. The work is not yet merged into `fza`, the fork's integration branch.
