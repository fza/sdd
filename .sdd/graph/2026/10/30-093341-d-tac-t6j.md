The `sdd-entry` merge driver falls back to git's text merge whenever `sdd merge-entry` cannot merge, so an old or missing `sdd` on PATH leaves a conflict with markers, as before the driver existed, never a file holding only one side. The driver directive (20261030-085158-d-tac-vyt) accepted a markerless conflict when `sdd` is missing; the more common case is an older `sdd` first on PATH, which answers `merge-entry` with an unknown-command error (exit 3) and leaves git's file as our side alone, marked conflicted with the other side's changes invisible.

**Command.** The configured driver becomes `sdd merge-entry %O %A %B %L %P; s=$?; [ $s -le 1 ] && exit $s; git merge-file -L ours -L base -L theirs --marker-size=%L %A %O %B`. Git runs merge drivers through `sh`, which Git for Windows ships as well.

**Exit codes.** `sdd merge-entry` exits 0 when merged, 1 only for a conflict it wrote markers for, and 2 for every other failure. It writes git's file only with a finished merge result, so after any failure the fallback merges the untouched original.

**Upkeep.** The driver shipped in 20261030-092427-s-tac-lx2 keeps any existing driver value, which would strand clones on the earlier command. A value starting with `sdd merge-entry` is one sdd wrote and is replaced by the current command; any other value stays as configured.

Rejected: writing the absolute path of the `sdd` binary (an upgrade that moves or deletes it gives the same markerless conflict); the absolute path plus the fallback (most complex, and a stale path then turns every merge into a silent text merge); accepting the risk (an older `sdd` first on PATH is the ordinary state on a machine running a dev build beside a release). Accepted costs: the configured driver is a POSIX `sh` snippet; exit 1 of `merge-entry` is reserved for conflicts.

## Acceptance criteria

- [ ] With an `sdd` lacking `merge-entry` first on PATH, or no `sdd` at all, an entry whose summary both sides changed merges to a conflict with git's markers.
- [ ] `sdd merge-entry` exits 1 only for a conflict with markers written; any other failure exits 2 and leaves git's file byte-identical.
- [ ] A clone whose driver value starts with `sdd merge-entry` but differs from the current command gets the current command from the next sdd commit, merge, merge-pull or init; any other value is kept.
