Up to release v0.18.0-alpha.2, sdd's release configuration names the `networkteam` GitHub owner literally for the release, the Homebrew tap, the curl installer and the documentation site, so a fork cannot cut its own release or publish its own docs without editing those files.

Expected, as a natural expectation: a release workflow run in a repository publishes to that repository, and the installer and docs site it ships point back at it; forking an open-source tool to release a modified build is ordinary use.

Actual, in v0.18.0-alpha.2, read from the release files at that tag: `.goreleaser.yaml` sets owner `networkteam` for the GitHub release and for the tap repository, and the cask homepage to `github.com/networkteam/sdd`. The committed `install.sh` downloads from `networkteam/sdd` releases and is attached to the release as is. `website/astro.config.mjs` sets the site to `networkteam.github.io` and its GitHub link to `networkteam/sdd`.
