Commit 9ead170f, merged into the fork's mainline, makes every field description in the structured-output schemas reach the provider whole. The schema library (`invopop/jsonschema`) splits a `jsonschema` struct tag at every unescaped comma and drops the text after it, so four descriptions in `internal/llmops/schema.go` were cut short: the pre-flight observation lost "ending in a conclusion", the writing guide's reasoning and quote fields lost their second halves, and the summary field reached the model as "at most three sentences".

Each comma is now escaped as `\\,` in the tag, which the library joins back into the description. `TestSchemaDescriptionsReachTheSchemaWhole` in `internal/llmops/schema_internal_test.go` compares every schema's descriptions with the text written in the response types' tags, so a description written later with an unescaped comma fails it. It is an internal test because the response types are unexported. It failed on all four cut descriptions before the fix, and on a single comma left unescaped.

A live `sdd summarize` and two `sdd new --dry-run` pre-flights through the openai provider with model glm-5.3-flash, which receives the schemas, completed without error. The pre-flight drew no findings, so the observation text was not seen in a response.
