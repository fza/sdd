title: Embedding sizing from provider token counts with self-calibration
summary: Embed inputs are sized by the provider's reported token count, calibrated per fingerprint with three probes; a 2048-rune cap applies when no count is reported.
---

Embedding input size comes from the provider's reported token count when the provider reports one. Without a count, every input is capped at 2048 runes, Entry preamble included.

Calibration runs once per embedding fingerprint (provider, model, dimensions, document template, endpoint path) with three single-input probes:
- about 1000 runes of Latin text: tokens per rune for ordinary text
- about 1000 runes of CJK text: worst-case tokens per rune
- about 20000 runes of Latin text: the input limit. A provider that truncates silently reports a count that stops growing at the limit. A provider that rejects over-limit input is bisected between the last accepted size and the first error.

The result is stored with the fingerprint and recalibrated when the fingerprint changes.

Chunk size in runes is the limit divided by the worst observed tokens per rune, with a margin. Each batch's reported prompt_tokens refines that ratio. A batch whose count reaches the limit is split until the truncated entry is isolated.

Rejected:
- A config key for limits. sdd measures the provider; users do not tune it.
- A tokenizer inside sdd. Tokenizers differ per provider, which breaks provider-agnostic sizing.
- Sizing from runes alone. Wrong for CJK and code, where one rune costs about one token.
- Learning from batches only. Early batches would run unsized.

Costs: about three requests once per fingerprint, plus about six bisection requests for providers that only error. A provider that neither errors nor reports counts keeps the 2048-rune fallback, and truncation stays invisible for it.

## Acceptance criteria

- [ ] Inputs are sized from the calibrated limit when the provider reports prompt_tokens.
- [ ] Without reported counts, no input exceeds 2048 runes, Entry preamble included.
- [ ] Calibration probes run once per fingerprint and are stored with it.
- [ ] A changed fingerprint triggers recalibration.
- [ ] A batch whose count reaches the limit is split until the truncated entry is isolated.
