The `llm.extract_timeout` setting, which bounds the second call that reformats an unparseable pre-flight or writing-guide response (20261028-114300-s-tac-72b), is invisible where a user looks for it: `sdd config` lists no default for it and `sdd config get llm.extract_timeout` answers that it has no value, though a 1-minute default is in effect on every such call. On branch `pr/feat-verdict-extraction`, where the setting lives, an extraction call that runs out that bound also fails without naming the setting, and under `claude-cli` the error reads `claude -p timed out (increase with --preflight-timeout)`, naming a flag only `sdd new` has and dropping the deadline as its cause.

Expected: the same treatment the `claude-cli` timeout fix (20261029-210859-s-tac-x9d) gave `llm.timeout`, the shown default being the one a call runs under and a timeout naming the setting that raises it. That fix left this setting out because upstream `main` lacks it. The fork build names `llm.extract_timeout` in the error only through the conflict resolution in merge commit `4d1cc9ef` on `fza-fork`, which no `pr/` branch carries.
