Pre-flight and the writing guide now ask `openai` and `ollama` to constrain their responses to a JSON schema, and fall back to one reformat call when a response does not parse, closing 20261028-113801-s-tac-fi8, in commits `93caff97`, `1e8f72fc` and `c91723e5` on branch `pr/feat-verdict-extraction`.

On `openai` the request carries `response_format` with a strict `json_schema`; on `ollama` the schema goes in `format`. The schema is reflected with `github.com/invopop/jsonschema` from the same Go structs the responses are parsed into (`internal/llmops/schema.go`). `anthropic` and `claude-cli` send no schema, and summarize stays unconstrained. The factory's purpose mux holds one gollm client per schema-carrying purpose.

When the first response does not parse, the check sends that text in a second call under the new purpose `preflight-extract` or `writing-guide-extract`. Its prompt carries only the target shape and the severity scale and asks for the JSON alone, so the model reformats and cannot reach a new verdict. Both responses failing returns an error naming both attempts. The second call has its own deadline: `llm.extract_timeout`, default 60s, or `sdd new --preflight-extract-timeout`.

Three parts of the structured-output directive (20261004-134853-d-cpt-sw8) stay open: `llm.Request` carries no schema, the claude CLI's `--json-schema` is not wired, and adapters that cannot enforce a schema are not refused as 20261004-135748-d-tac-ndh directs.
