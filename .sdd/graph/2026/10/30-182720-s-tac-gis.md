`sdd init` now refuses an uncommitted-path record it cannot trust: commit `c87ece22` on branch `pr/fix-init-uncommitted-record`, merged into `pr/core` and `fza-fork`, on top of the delivery 20261030-182052-s-tac-t2c.

A record that git tracks or does not ignore did not come from this checkout's own failed run. A repository can ship one by force-adding it, and its paths would then sweep the user's untracked files, such as a `.env`, into an `sdd:` commit that graph sync may push. Init now refuses such a record, and refuses any record line that is not a clean relative path inside the repository, or names the repository root. Both refusals commit nothing and name the record to delete.

`TestInitRefusesARecordItCannotTrust` covers the root, a path outside the repository, an absolute path, an unclean path and a tracked record. Five guard breaks each failed it on its own assertion. With the inside-the-repository check broken, the outside-path case still fails, because git refuses a pathspec outside the repository.
