The blocked-sync record is kept per branch, so a sync round on one branch never overwrites, clears or pauses another branch's record, and an agent or CLI command sees only the block of the branch it works on. The sync lock stays one per graph repository, since every branch talks to the same remote.

The decomposition (20261028-192101-d-tac-16h) put the lock and the record in the graph repository's common git directory, shared by all its worktrees. What blocks sync is a fact about one branch: its upstream, its commits ahead and behind, its merge with upstream. With worktrees on several branches, which the engine checks out per bound branch, one shared record lets a round on `side` replace `main`'s held-push record with its own no-upstream state, lets a worktree whose HEAD already holds `main`'s conflicting upstream commit lift `main`'s conflict pause unresolved, and shows `main`'s banner and fix steps to agents on `side`. An independent code review of the timed sync implementation (branch `pr/feat-timed-graph-sync`) reproduced the first two.

Each branch's record is its own file under the common git directory (`sdd/sync-blocked/<branch>.json`). The banner of the blocked-state directive (20261028-201909-d-tac-fxp) reaches every agent and CLI command working on that branch, and ownership is claimed per branch.

Rejected: one shared record covering only the base branch, with work branches never syncing automatically, since graph commits on a work branch would then stay local until merged or synced by hand. Rejected: one shared file keyed by branch, with every agent seeing every branch's block, since agents on `side` would get `main`'s banner and steps they cannot act on. Accepted cost: an agent on `side` is not told that `main` is blocked.

## Acceptance criteria

- [ ] Two worktrees on different branches of one graph repository keep separate records: a round on one never writes, clears or lifts the pause of the other's.
- [ ] An agent bound to a branch, and a CLI command run in its worktree, see that branch's banner only.
- [ ] Two worktrees on different branches still never fetch, merge or push at the same time.
