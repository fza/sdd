The check that a staged body file's header agrees with the capture's fields moves to the confirm: re-staging a file a capture uses, and reporting a field the header also states, are accepted in either order, and a confirm is refused while header and fields disagree, naming the key.

As delivered (20261030-154336-s-tac-me6), a field that the header also states cannot change once a capture uses the file. Re-staging the file with the new value is refused because its header contradicts the field the capture holds, and reporting the new value is refused because it contradicts the header of the file still staged. Pre-flight and the writing guide routinely ask for such a change, a ref kind or a topic, and each refusal points at the other. The only way through is staging the edited file under a new name and reporting the new handle with the field in one answer.

The staged-body directive (20261030-120506-d-tac-l2b) wants a report that drifted from the reviewed file noticed. Checking at the confirm still guarantees that no entry is written while they differ, and lets the two halves of one edit arrive one after the other. A re-stage still serves playback again, so the user sees the new body before any confirm.

Rejected: explaining the new-name workaround in the served text and both refusals, which keeps the two-file sequence for every header edit; refusing at the report but accepting the re-stage, which fixes only one order and leaves a refusal an agent cannot resolve without knowing the other order.

Accepted cost: between the two steps a capture briefly holds a header and fields that disagree, and the disagreement is reported only at the confirm.

## Acceptance criteria

- [ ] Re-staging a file a capture uses, with a header contradicting the capture's fields, is accepted and serves playback again.
- [ ] Reporting a field that contradicts the header of the staged file in use is accepted.
- [ ] A confirm while header and fields disagree is refused, the refusal names the key, and nothing is written.
- [ ] Changing a header field by re-staging and reporting, in either order, ends in a confirm that writes the entry.
