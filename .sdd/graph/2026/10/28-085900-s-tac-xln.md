Code for writing at a graph schema without titles is reachable by no schema and covered by no test. Since schema 1 gained the Titles capability (20261028-005411-d-tac-tit), the binary knows only that schema, so the branches taken when `Titles` is false never run: they skip the title model call and omit the title in `internal/handlers/handler_new_entry.go` and `internal/handlers/handler_summarize.go`, and they refuse an explicit title in `pkg/application/capture.go` and `pkg/application/document_publication.go` through `refuseTitle` in `internal/handlers/write_schema.go` and `pkg/application/graph_schema.go`. The inner review of the titles evaluation (20261028-082723-s-tac-x07) found these branches; a search of the test files finds no test that reaches either refusal; the tests that did were deleted with the schema they exercised.

The expected state is that every code path is either covered by a test or removed. The directive kept the capability table so a later schema bump could use it, which leaves these branches without a case to run.

Candidates, unsettled: remove the Titles-false branches and both `refuseTitle` functions, keeping the table for the next capability; or keep them and drive them from a test-only capability row, which would add production surface that exists only for tests.
