Two clones summarizing one entry differently merge clean; a clone with an `sdd` exiting 3 gets both summaries between markers.

2. Medium: an error before the `merge-entry` action, such as a malformed `SDD_TIMING` value, exits 1 from `main`; the driver reads 1 as a written conflict and skips the text-merge fallback, leaving ours only, no markers.
3. Low-medium: a field absent in base and added on both sides at different lines survives twice; the merge exits 0 and the entry then fails to load on the duplicate key.
4. Low: a config-write failure after a landed commit returns an error, so auto-sync skips the push; the lock re-read checks only the `driver` key.
5. Low: an older `sdd` runs its full startup, sync check included, inside git's merge; the merge result is still correct.
6. Low: the commit path used by `sdd serve` and the MCP application never sets the driver up.
7. Low: init refuses a graph directory with a space only after writing `.sdd/config.yaml`, leaving a half-initialized project; gitattributes accepts quoted patterns.
