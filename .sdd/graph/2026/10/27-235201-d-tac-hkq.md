The automatic pull merges only when every incoming commit matches `^sdd:` and every path those commits change is in the graph directory (the config's `graph_dir`, `.sdd/graph` by default), `.sdd/meta.json`, `.claude/skills/`, `.agents/skills/` or `.gitignore`, each relative to the repository holding the graph and judged with the `graph_dir` in effect before the merge; any other path holds the pull and is reported, as a commit without the prefix is. This refines the automatic sync plan (20261027-194536-d-tac-190), whose pull rule judged a commit by its subject alone, and applies equally to the merge in the rejected-push retry (20261027-221041-d-tac-8b7).

It replaces the earlier path rule (20261027-222018-d-tac-ue8), which allowed all of `.sdd/`. That admitted `.sdd/config.yaml`, and an incoming config change alters sdd itself: `graph_dir: .` counts every path as graph and switches the path check off for all later pulls, and an LLM or embedding endpoint change sends the participant's API keys from the user-global config to another server. It also admitted a tracked `.sdd/config.local.yaml` or files under `.sdd/sessions/` and `.sdd/index/`, which a merge writes over the participant's own ignored copies.

A subject is written by whoever commits: anyone with push access can put `sdd:` on any commit, so the allowed paths are the ones whose content sdd treats as data rather than configuration: entries, summaries, WIP markers and lint fixes in the graph directory, the schema record in `.sdd/meta.json`, and the rendered agent skills and `.gitignore` from `sdd init`.

Accepted costs: a teammate's change to `.sdd/config.yaml`, from `sdd repo` commands or by hand, holds every participant's automatic pull until someone pulls by hand; and an automatic pull can change the skill files that instruct a participant's agents without review, the same exposure as reading graph entries. Rejected: also holding the skill folders, which stops automatic pull after every participant's sdd upgrade refreshes the skills; and keeping `.sdd/config.yaml` while holding only changes to listed keys such as `graph_dir`, `project_dir`, `llm` and `embedding`, because that list must grow with every new config key and one missed key reopens the hole.

## Acceptance criteria

- [ ] With `auto`, incoming commits all matching `^sdd:` and changing only paths in the graph directory, `.sdd/meta.json`, `.claude/skills/`, `.agents/skills/` or `.gitignore` are merged.
- [ ] With `auto`, an incoming commit matching `^sdd:` that changes `.sdd/config.yaml`, any other `.sdd/` path, or any path outside those holds the pull, nothing is merged, and the report names the path.
