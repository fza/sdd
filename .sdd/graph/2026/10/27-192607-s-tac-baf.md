In a project_dir layout, the project repository holding the graph works as an ordinary sdd project with its work repository absent from disk. The pointer runs one way: only the work repository's `.sdd/config.yaml` names the project, and the project's config carries no key naming a work repository. Run inside the project, `meta.ResolveProject` resolves the project to that repository itself (`internal/meta/project.go`), captures commit there, and `sdd wip done` checks merged branches in the repository the command runs in. The one refusal involving a missing repository is the reverse case: a command in a work repository whose project_dir names a directory without an sdd project fails with "run `sdd init` there first". Both follow from every project setting and graph write living in the project repository.

Commit 44d8df2a on branch feat/graph-repository pins it with `TestProjectWorksWithoutItsWorkRepository` in `internal/cliapp/pointed_project_test.go`: it builds the layout, captures from the work repository, deletes it, then captures, shows and views in the project. A project resolution made to require the work repository failed that test at its capture step, while the existing layout tests stayed green.
