Up to release v0.18.0-alpha.2, the sdd repository tells GitHub secret scanning no paths to skip, so the synthetic credential samples a contributed credential scanner is tested against would raise leaked-secret alerts and trip push protection.

Expected, as a natural expectation: test samples whose tokens are synthetic do not report as leaked credentials. GitHub secret scanning closes alerts as "ignored by configuration", and leaves the paths out of push protection, for every path listed under `paths-ignore` in `.github/secret_scanning.yml`.

Actual, in v0.18.0-alpha.2: the repository has no `.github/secret_scanning.yml`. The credential scanner contributed on branch `pr/core` (`internal/secrets`) brings credential-shaped samples under `test/fixtures/secrets/`, among them gitleaks' own per-rule samples, and nothing excludes that directory from scanning.
