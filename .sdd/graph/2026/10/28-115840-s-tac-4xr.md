sdd's LLM path now has all five pieces the gap names, closing 20261028-114812-s-tac-906, in commits `af62d51b`, `bf95985c`, `342dd651`, `3e9ce32f`, `4efaaefc`, `c4fdcd30`, `efd841d4`, `26836a89` and `f1e67cdf` on branch `pr/llm`.

The branch carries the changes of `pr/feat-openai-compatible-system-role` (`af62d51b`: role `system` to every endpoint other than `api.openai.com`, through the `github.com/fza/gollm` fork) and of `pr/feat-verdict-extraction` (`bf95985c`, `342dd651`, `3e9ce32f`: a reflected JSON schema on pre-flight and writing-guide requests to `openai` and `ollama`, and one reformat call under purpose `preflight-extract` or `writing-guide-extract` when a response does not parse, bounded by `llm.extract_timeout`).

On top of those:
- `llm.structured_output` picks how a schema-carrying request asks for JSON. `json_schema` sends the schema. `json_object` asks for any JSON object (`response_format: {"type": "json_object"}` on `openai`, `format: json` on `ollama`), states the schema in the system prompt and validates the answer locally. `auto`, the default, sends `json_schema`; when the endpoint answers 400 refusing schema mode for the model, it retries once in `json_object` mode and keeps that provider, endpoint and model on it for the rest of the process (`4efaaefc`).
- A `json_object` answer that fails local validation reaches the check as an `llm.MalformedAnswerError` carrying the text, and goes to the reformat call instead of failing the check (`efd841d4`).
- `llm.max_tokens` sets the output cap, default 4096. `0` sends none, except on `anthropic`, whose API requires one and gets 32000; a negative value is refused. An answer ended at the cap fails with `ErrAnswerCut`, and a whole response without an answer with `ErrNoAnswer`, each naming the finish reason and the reasoning tokens spent (`26836a89`).
- `SDD_USAGE_LOG` names a file to which every LLM call, chat and embedding, appends one JSON line: step, provider, endpoint host, model, token counts including reasoning and cached tokens, finish reason, the provider's billing object where the reply carries one, and success. No key, prompt or answer reaches it; the line shape is `llmstats.UsageRecord`. `pkg/llm` gains `Identity.Host`, `Usage.ReasoningTokens`, `Usage.BillingCost` and `Result.FinishReason`, and `llm.Error` carries the usage of a reply that was delivered but rejected (`f1e67cdf`).
- `c4fdcd30` pins the fork revision that logs a returned API error at debug level.

Deviation, left open for decision: `json_object` mode and the `auto` switch run structured checks on endpoints that do not enforce the schema, where 20261004-135748-d-tac-ndh directs refusal. That directive names this case as its trigger for revisiting the restriction: a provider a user needs that cannot enforce a schema. This done records the code as built and takes no position on the restriction; whether these modes stand, change, or go behind the refusal is a decision for the maintainers reviewing the branch, and it needs its own entry.
