Two paths still ignore the global `--local-config <path>` flag that 20261028-113856-s-tac-sxc delivered, though the flag promises to replace `.sdd/config.local.yaml` for the whole invocation. `sdd --local-config <path> init --participant <name>` writes the participant into the repository's own `.sdd/config.local.yaml`, because the CLI never sets `InitCmd.LocalConfigPath` while the init handler honors it. And the graph readers and write targets `sdd serve` and the CLI's capture path open through `pkg/local.NewRepositoryTargets` resolve each checkout's config with no override, so project identity and graph location come from the checkout's own file under the flag.

Expected: every read and write of the machine-local layer in a run that passes `--local-config` uses the named file, as the flag's description and its delivery state; the delivery itself records these two paths as left unwired.
