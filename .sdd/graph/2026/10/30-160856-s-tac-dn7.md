The staged-body delivery in commit `64f4cd91` (20261030-154336-s-tac-me6) was not sound as first delivered: a fresh code review found two high and three low defects, all fixed in commit `1e31a0e8` on `pr/feat-staged-body`; a live MCP run with the real `claude` CLI passes before and after the fixes.

Inner lens. A fresh code review read the diff `pr/core...pr/feat-staged-body` at `64f4cd91` against `AGENTS.md` and the staged-body, hash and field directives (20261030-120506-d-tac-l2b, 20261030-121523-d-tac-isy, 20261030-122829-d-tac-1nq), not the claims of 20261030-154336-s-tac-me6, and each finding was reproduced by a failing test before it was reported. The defects:
1. High: a re-stage after playback was served but before the confirm let the confirm bind a body nobody was shown, against the staged-body directive's rule that a re-stage after playback serves playback again.
2. High: a chooser answer naming `bodyHandle` wrote the new body before the engine validated the answer, so a refused answer left the switch behind and the next confirm wrote it unseen.
3. Low: a re-stage during an unfinished write replaced the staged file and then reported failure.
4. Low: a byte order mark in a file without a header landed in the entry body.
5. Low: a re-stage after the entry was written still rewrote that capture's state and reported it bound.

Sound per the review: replay after a restart, the header comparison against stored values, the refusals, the raw-byte hash, layer and test placement. After `1e31a0e8` the full suite and example module pass, lint is clean apart from 47 existing `testpackage` warnings, and 23 of 25 guard breaks each failed on their own assertion; the other two target code the fixes removed.

Outer lens. The branch binary served over MCP stdio in a scratch repository, driven as an agent would, with the real `claude` CLI for the writing guide, pre-flight and summary. A draft file whose header uses another tool's key shapes, staged by path, reaches playback showing a hash equal to its raw bytes; a body patch is refused with the staging-patch hint; re-staging the edited file names the capture as bound, and the next playback shows the new body and hash; the confirm writes an entry carrying the revised body without the header, and the draft file stays untouched. One rerun was needed after the `claude` CLI timed out in the writing guide. Not covered: a real agent with a client-side capture hook, a remote server staging by content, Windows.

Verdict: ready to land with the fixes in `1e31a0e8`.
