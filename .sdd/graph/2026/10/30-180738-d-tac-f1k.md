When the commit at the end of `sdd init` fails, init records the paths it wrote and left uncommitted in `.sdd/tmp/init-uncommitted` of the repository whose commit failed, a path init already keeps out of git. The next run adds those paths to the paths it touched itself, commits them together, and deletes the record once that commit succeeds. If the commit fails again, the run exits with an error and keeps the record. This applies to both repositories of a split setup.

The gap (20261029-143251-s-tac-kic) is a re-run that reports success while the first run's files stay uncommitted, because init commits only what the current run touched. With the record, a later run either completes the earlier commit or fails as loudly as the first run did.

Rejected: committing every init-managed path that is untracked or modified on each run, which sweeps the user's own pending edits to `.gitignore` or agent settings into an `sdd:` commit; refusing to run while any managed path is uncommitted, which also blocks on those unrelated edits, which are common, and leaves the commit to the user.

Accepted cost: a local state file, with code to write, read and clear it in each repository init commits to. A path in the record that the user has since committed or reverted is dropped from the commit, not reported.

## Acceptance criteria

- [ ] After a refused init commit, a re-run that touches nothing commits the files the first run left uncommitted and exits 0.
- [ ] A re-run whose commit is refused again exits with an error and keeps the record.
- [ ] A successful commit deletes the record.
- [ ] The user's own uncommitted edits to an init-managed file that no run of init wrote are not committed.
- [ ] In a split setup, a refused commit in the graph repository is completed by a re-run the same way.
