An entry merge with an old or missing `sdd` on PATH now ends in git's text merge with conflict markers: `800c163e` on branch `pr/feat-merge-entry` ships the driver's text-merge fallback and the setup and frontmatter fixes, closing the fallback directive (20261030-093341-d-tac-t6j) and the review-defect gap (20261030-093806-s-tac-voj).

Fallback directive criteria:
- With an `sdd` that answers `merge-entry` with exit 3, or none on PATH, a doubly changed summary merges to a conflict with both sides between markers; covered by a git-level test and a three-clone smoke run.
- `sdd merge-entry` exits 1 only for a written conflict and 2 for any other failure; it merges in temporary files and renames the finished result over git's file, so a failure leaves that file byte-identical.
- A driver value starting with `sdd merge-entry` is replaced by the current command; another value is kept.

Gap items: the driver setup runs after `Commit` lands and after `RemovalCommitter.Commit`, and a failed config write re-reads the value before reporting; the repository check reports git failures instead of reading them as no repository, and the once-per-process cache keeps only repositories it found; frontmatter detection resolves a requote-only pair by its lines from either side, accepts a leading BOM and a closing delimiter with trailing spaces, and refuses a flow-style mapping; init refuses glob, absolute and parent graph directories, and the append helper reports write and close errors.

Noted in the doing: a file hook strips the literal BOM character, so source and test write it as a Go Unicode escape. Two guards no test reaches: the re-read after a concurrent config write (a race between two git calls), and the append helper's write and close errors.

Not yet merged into `pr/core` or `fza-fork`.
