Commit dce26ef3 on branch `feat/title-code-spans`, merged into `fza`, makes the title prompt ask for commands, identifiers, file and package names as backtick code spans, closing the code-span titles plan (20261027-132914-d-tac-dcy).

The prompt (`internal/llmops/summary_templates/title.tmpl`) now asks for such terms as code spans in their own casing, with "`sdd` info JSON output" as its example of a title opening on one.

`model.CapitalizeTitle` needed no change, contrary to the plan's first behaviour item. It upper-cases only the first character, and a backtick has no capital form, so a title opening with a code span already kept its casing. An added exception for a leading backtick could not alter any result and was dropped; its doc comment now states the behaviour.

Acceptance criteria:

- `CapitalizeTitle` leaves "`sdd` info JSON output" and "`go.mod` replace directive" unchanged and still capitalizes other titles (`internal/model/title_test.go`).
- `sdd new` and `sdd summarize` with an explicit "`sdd` info JSON output" store exactly that title (`internal/handlers/handler_new_entry_test.go`, `internal/handlers/handler_summarize_test.go`).
- The frontmatter round trip keeps a title opening with a backtick (`internal/model/title_test.go`).
- The rendered title prompt carries the code-span rule and its example, and no longer shows "Daemon project removal" inside a code span (`internal/llmops/summary_test.go`).

Removing the prompt rule and putting the example back into backticks each failed its own test. Whether a live model follows the new rule was not checked.
