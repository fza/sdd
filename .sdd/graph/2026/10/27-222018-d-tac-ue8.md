The automatic pull merges only when every incoming commit matches `^sdd:` and every path those commits change lies in the graph directory (the config's `graph_dir`, `.sdd/graph` by default), `.sdd/`, `.claude/skills/`, `.agents/skills/` or `.gitignore`, each relative to the repository holding the graph; any other path holds the pull and is reported, as a commit without the prefix is. This refines the automatic sync plan (20261027-194536-d-tac-190), whose pull rule judged a commit by its subject alone, and applies equally to the merge in the rejected-push retry (20261027-221041-d-tac-8b7), which follows the pull's rules.

A subject is written by whoever commits: anyone with push access can put `sdd:` on a commit changing code, and a subject-only rule would merge that code into each participant's working tree without asking. The allowed paths are the ones sdd's own commits write: entries, summaries, WIP markers and lint fixes in the graph directory, `.sdd/config.yaml` from repository commands, and `.sdd/`, `.gitignore` and the rendered agent skills from `sdd init`.

The accepted cost: an automatic pull can change the skill files that instruct a participant's agents without anyone reviewing them first. Rejected: the graph directory and `.sdd/` alone, which holds every pull after a participant's `sdd init` refreshes the skills until someone pulls by hand; and the subject alone, as built, for the code-merging risk above.

## Acceptance criteria

- [ ] With `auto`, incoming commits all matching `^sdd:` and changing only paths in the graph directory, `.sdd/`, `.claude/skills/`, `.agents/skills/` or `.gitignore` are merged.
- [ ] With `auto`, an incoming commit matching `^sdd:` that changes any other path holds the pull, nothing is merged, and the report names a path outside those.
