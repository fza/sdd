In this repository the installed sdd release writes graph entries without titles and cannot replace a stored summary, because that release defines schema 1 without titles while this repository's graph now records schema 1 with them (20261028-005411-d-tac-tit). The release serves this repository's MCP tools; the titles evaluation (20261028-082723-s-tac-x07) observed the following through them. It wrote 20261028-081657-s-tac-mdl and 20261028-082723-s-tac-x07 with an empty generated title. At the capture's summary-check step, replacing the summary of 20261028-081657-s-tac-mdl failed twice with `the graph is at schema 1, which has no entry titles; leave out the title or run sdd migrate`, the second time with no title supplied. A build of this repository's `fza` branch (`./bin/sdd summarize --text --title`) wrote both fields.

The expected state is that every capture here gets a title and that the summary check can replace a drifted summary. This holds once a release carrying the change is installed. Entries written untitled until then keep listing by their first summary sentence, and `sdd summarize --all` fills their titles afterwards.

Why the replacement fails without a title is not established; one candidate is that the release's replace path regenerates or carries a title regardless.
