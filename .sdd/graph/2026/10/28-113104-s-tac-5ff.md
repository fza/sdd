Up to release v0.18.0-alpha.2, the `openai` provider sends the system prompt under role `developer` to every endpoint, so an OpenAI-compatible service that accepts only the classic roles refuses sdd's calls with HTTP 400.

Expected, from the commitment to reach any service speaking the OpenAI chat-completions protocol through a configured base URL (20260921-181638-d-cpt-cnu): a request sent to a configured `endpoint` uses message roles that service accepts, the system prompt included.

Actual, in v0.18.0-alpha.2: the pinned `networkteam/gollm` fork builds the system message with role `developer` unconditionally (`providers/openai.go`, `PrepareRequest`). OpenAI's own API accepts that role; OpenAI-compatible services commonly know only `system`, `user` and `assistant` and answer 400. sdd's summaries, pre-flight and writing guide all send a system prompt, so none of them runs against such a service.
