Commit 7647f7cb on branch `fix/write-schema-version`, merged into `fza`, makes `sdd info` and every write agree on a `meta.json` without a valid schema version, closing the mismatch gap (20261027-130917-s-tac-ahg).

`model.ParseSchemaMeta` refuses a `graph_schema_version` below 1, so `sdd info` (text and JSON) and every write now fail on such a file with "graph_schema_version must be at least 1". `model.WriteSchemaVersion` holds the rule choosing the write schema (the recorded version, else the binary's for a graph without `meta.json`), and the info finder, the write handler and the filesystem graph store all call it. The application layer reads the version from that store and needed no change. `model.CapabilitiesFor` reports an unknown version through the sentinel `model.ErrUnknownSchemaVersion`; the info finder treats only that error as a graph newer than the binary, with `capabilities` null, and returns every other error. `RenderInfoJSON` now wraps its encode error.

Tests cover a missing, 0 and negative version at parse, the rule for both cases, the sentinel, and info refusing `{}` and version 0 in both formats. Each new guard was broken once and failed its own assertion. The finder's remaining `return nil, err` after the sentinel check has no test reaching it: `CapabilitiesFor` returns no other error today.
