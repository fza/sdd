The per-person `dialogue.mode` setting (20261029-150854-d-tac-b2f) shipped on branch `pr/feat-autonomous-dialogue` in commits `1835c446` (the setting), `034e7b61` (engine, application, MCP surface and base procedures), `03f18c94` (`sdd init`), `eeb22b54` (mode normalization left to the engine) and `972efd95` (further guard tests); every acceptance criterion is met.

- The setting: `dialogue.mode` takes `guided` or `autonomous` in the user-global config and `.sdd/config.local.yaml`, unset is `guided`, the local layer wins; a committed or unknown value is ignored with a warning naming file and key; `sdd config set` refuses other values.
- Bound at open: the session log's opening event carries the mode and the path of the config file that set it, only for an autonomous session, so a guided session's log is unchanged; replay restores both.
- Which choices: a step declares `delegable: true`, and the spec load refuses it on anything but a user choice. Eleven base user choices carry it; capture's pre-flight override does not.
- Answers: at a delegable choice in an autonomous session the served schema offers `userWords` and `reason`, neither required, and the engine takes exactly one; the answer event records `answeredBy` and the reason. A reason is refused in a guided session, at a choice not marked delegable, and at a choice that is not the user's.
- Wording: every step's text receives `dialogueMode`, a procedure field of that name is refused, and a delegable choice's goal in an autonomous session asks the agent to decide with a reason. The nine base procedures branch their text on it; the session shell serves no briefing, no move proposals and no wrap-up offer, and lets the agent conclude. A test fails when a delegable choice's text never names the mode. Beyond the base procedures, the resume and open-thread texts the MCP surface serves branch the same way.
- `sdd init` asks for the mode when no layer sets it, writes it to the `config.local.yaml` of the project holding the graph, and takes `--dialogue-mode` without a terminal.

The application resolves the mode through an optional port that the CLI shell supplies; a host without it opens every session guided.
