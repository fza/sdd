Up to release v0.18.0-alpha.2, pre-flight and the writing guide send no response schema to any provider and fail on the first response that does not parse, so one malformed answer stops the capture.

Expected, from the structured-output directive (20261004-134853-d-cpt-sw8): an LLM operation that expects structure declares a response schema, and each provider adapter enforces it through the provider's native mechanism or declares that it cannot. Further, as a natural expectation: when a response carries the checker's findings but breaks the JSON shape, the check still yields those findings instead of an error.

Actual, read from the code at tag v0.18.0-alpha.2 (`internal/llm/gollm/gollm.go`, `internal/llmops/preflight.go`, `internal/llmops/writingguide.go`): the gollm adapter sends neither `response_format` on `openai` nor `format` on `ollama`, though both APIs accept a schema there. Pre-flight and the writing guide each make one call, parse its text, and return a parse error when that fails, which fails the capture at the pre-flight gate. The structured-output directive records four such parse failures, each from a model writing JSON as free text.
