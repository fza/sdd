A project's graph can now live in an sdd project of its own beside the work repository, with every graph commit made in the repository holding the graph, closing 20261028-114509-s-tac-k7g, in commits `67c45f22`, `1826aff2`, `095caa46` and `3c646e72` on branch `pr/feat-graph-repository`.

The git adapter now carries the repository it runs in, so entry, summary and WIP-marker commits, merges and the sync check address the repository holding the graph, while `sdd init` commits and `sdd wip start` branches stay in the work repository.

A work repository points at its project with `project_dir` in `.sdd/config.yaml`, or per machine in `.sdd/config.local.yaml`: the folder holding the project's `.sdd/`, relative or absolute. `sdd init --project-dir ../project-sdd` writes that config, and a repeat run leaves it byte-identical. Every command run in the work repository then acts on the project: captures commit there, `sdd serve` serves it and binds branches checked out there, and the write gate reads its `meta.json`; skills, the MCP registration and closure evidence stay with the work repository. The pointing config may set only `project_dir`, `skill_scope` and `supported_agents`, the local file only `project_dir`; any other key, a target that is not an sdd project, a target that itself sets `project_dir`, or a `graph_dir` leading into another repository is refused, naming the file and key. The pointer runs one way, so the project works with its work repository absent (20261027-192607-s-tac-baf). The automatic sync plan (20261027-194536-d-tac-190) builds on this routing.
