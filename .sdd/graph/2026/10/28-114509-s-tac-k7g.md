Up to release v0.18.0-alpha.2, sdd cannot keep a project's graph in a repository of its own beside the repository where the work happens: every git operation runs in the directory sdd was started in, and a work repository has no setting that names the project holding its graph.

Expected, as a natural expectation: a team that wants its code history free of `sdd:` commits keeps the graph in a separate repository and still runs sdd from the code checkout, with captures committed in the graph's repository. `graph_dir` already accepts an absolute path, which suggests a graph outside the project is meant to work.

Actual, in v0.18.0-alpha.2, read from the git adapter and config code at that tag: the git adapter carries no repository of its own and runs `git add`, `git commit`, `git pull` and the other operations in the process working directory. With `graph_dir` pointing into another checkout, the entry file is written there while the commit runs in the code repository, which refuses a path outside itself. The per-repository config has no key that names another sdd project, so all settings, `meta.json`, sessions and stats sit in the repository sdd runs in.
