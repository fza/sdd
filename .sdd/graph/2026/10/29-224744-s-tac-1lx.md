Both paths that ignored `--local-config` now use the named file, on branch `pr/feat-local-config` in commit `6c046daa`, closing the gap 20261029-224649-s-tac-n6x.

- `sdd --local-config <path> init --participant <name>` writes the participant into `<path>` and leaves the repository's `.sdd/config.local.yaml` untouched.
- `pkg/local.NewRepositoryTargets` takes the override as a new fourth parameter and resolves every checkout's config with it; `sdd serve` and the CLI's local application pass the flag's path. The new parameter changes the signature of an exported function in `pkg/local`; existing callers pass an empty string to keep their behaviour.

The two call sites in `internal/cliapp` that pass the flag's path have no test of their own; the tests cover the init write and the repository targets reading the override.
