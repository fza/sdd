title: Title guidance for agents
summary: Title guidance on code spans and the 32-character limit reaches only the model prompt, not agents writing titles themselves. It builds on the code-span titles delivery (20261027-161207-s-tac-5nk) and was surfaced by its evaluation (20261027-175451-s-tac-o48). The capture procedure's summary check, sdd new --title, and sdd summarize --title all let agents write titles without either rule, and nothing checks title length.

An agent writing an entry title itself gets none of the guidance the title prompt gives the model: not that code terms go in backtick code spans, and not how long a title should be. Its titles can read "Sdd info JSON output" where a generated title reads "`sdd` info JSON output".

The code-span titles delivery (20261027-161207-s-tac-5nk) put the code-span rule beside the length guidance of 32 characters in the title prompt (`internal/llmops/summary_templates/title.tmpl`), and that prompt reaches only the model, as its evaluation (20261027-175451-s-tac-o48) found. An agent writes a title in three other places, and none of them states either:

- the capture procedure's summary check, which collects a corrected title (`internal/baseprocedures/entries/20260703-094500-d-prc-cap.md`: the `correctedTitle` field description and the verifySummary instructions), saying only that a title names the subject in a few plain words;
- `--title` on `sdd new`, whose help reads "Store this title verbatim instead of the generated one" (`internal/cliapp/app.go`), though `model.CapitalizeTitle` still upper-cases a first letter that is not a backtick;
- `--title` on `sdd summarize`, whose help reads "Write the supplied text as the title, bypassing the LLM".

Nothing checks a title's length, so the prompt's guidance is the only place the length is stated at all.
