Commit `1e31a0e8` on branch `pr/feat-staged-body` fixes all five staged-body capture defects of the gap 20261030-161142-s-tac-ftl:

1. An answer at a step whose draft changed since it was last served is not applied: the engine serves the change instead, with a note to play it back and answer again. A re-stage between playback and confirm therefore reaches the user before any confirm binds it.
2. A chooser answer carries the body resolved from `bodyHandle` in its own fields, so the engine validates and applies it with the answer or not at all; every capture option collecting a body also collects `bodyHash`.
3. A re-stage of a handle bound to a capture is refused while an operation of the session is unfinished, before anything is staged.
4. A leading byte order mark is cut before the header split, so it never reaches the body; the staging hash still covers it, as the hash directive (20261030-121523-d-tac-isy) demands.
5. A capture holding a written entry is no longer bound to its handle, so a later re-stage leaves its state alone and does not name it.

Each fix has a test that fails when the fix is removed from the code. A live MCP run on the fixed binary writes a revised staged body after a re-stage. Not yet merged into `pr/core` or `fza-fork`.
