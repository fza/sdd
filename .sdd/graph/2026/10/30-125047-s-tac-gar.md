Five low-severity defects remain in the `sdd merge-entry` driver as of commit `49ea509d`, found by the evaluation 20261030-123319-s-tac-24p against the driver directive 20261030-085158-d-tac-vyt:

1. Setup writes `merge.sdd-entry.name` before `merge.sdd-entry.driver`. A failed second write leaves a named driver without a command, and git refuses to merge entry files.
2. `graph_dir: .` routes `*.md` to the driver, so every Markdown file in the repository passes through it, and a file with `title` or `summary` frontmatter that is no entry merges as one.
3. The lines of a resolved `title` or `summary` run up to the next key, so a comment line below them is dropped or replaced by the other side's.
4. The step writing resolved fields into all three versions is pure logic in `internal/handlers`; `AGENTS.md` places such logic in `internal/model`.
5. A driver setup failing after the commit and its push returns an error that does not say the write landed, so a caller retrying it captures the entry twice.
