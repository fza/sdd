A per-person setting, `dialogue.mode: autonomous`, lets the agent take the choices an engine session otherwise puts to the user, and makes the engine serve wording for an agent that decides rather than one that asks. The default, `guided`, leaves every session as it is today. Felix Zandanel decided the shape, at the request of a project that runs sdd sessions through agents working on their own, where a user is not at hand for every confirmation.

**The setting.** `dialogue.mode` takes `guided` or `autonomous` and, like `sync.mode` (20261027-211908-d-tac-l8j), is set per person: only the user-global config and `.sdd/config.local.yaml` may set it. A value in the committed config, or an unknown value, is ignored with a warning naming file and key, leaving the mode `guided`; `sdd config set` refuses other values (20260921-174543-d-cpt-tv9). `sdd init` asks for it when no layer sets it, as the init questions foresaw (20261029-132422-d-tac-2sn), and `--dialogue-mode` answers without a terminal.

**Bound at session open.** The session log's opening event records the mode and the config layer that set it, so a resumed session keeps its mode and a changed setting affects new sessions only (20260914-113737-d-cpt-qst).

**Which choices.** A procedure step hands a user choice over by declaring `delegable: true`. An unmarked user choice stays the user's in every mode, so a new or user-written procedure fails safe. In the base procedures every user choice is marked except capture's pre-flight override (20260703-094500-d-prc-cap): overriding a failed quality check before writing stays the user's call.

**Answers.** In an autonomous session, an answer at a delegable choice carries either `userWords`, the user's relayed words, or a one-line `reason`, the agent's own; exactly one. The answer event records which, as answered by user or by agent. At a choice that is not delegable, a `reason` is refused and the user's words are required. Guided sessions keep today's answer form. This neither permits nor closes the agents answering user choices unasked (20260924-232456-s-tac-f09): in a guided session that remains wrong.

**Wording.** The engine gives every step's text the session's mode and, at a delegable choice, a goal to decide and answer with a reason. The base procedures branch on it: no briefing the user on resume, the agent starts moves instead of proposing them, the session shell drops its wrap-up offer and the agent concludes the session itself, parking or recording open threads first (20260704-100000-d-prc-dlg); paragraphs written for the user are left out, so serves shrink. A test fails when the text of a delegable choice never branches on the mode.

Dialogue stays the default (20260422-122136-d-stg-beb): the switch is opt-in per person, and the record shows every choice an agent took.

Rejected, with the reasoning: a list of grants per kind of choice (the kinds become a config contract every procedure must map onto); three levels (the middle boundary must be held per choice); the key spelled `dialogue` alone (a later dialogue setting would force a breaking reshape) or as a boolean `agent_autonomy`; reading the mode live on every step (a session could switch mid-move); an optional `userWords` without a reason (why the agent chose is lost); the agent writing its words into `userWords` (they read as the user's); marking reserved choices instead of delegable ones (a new procedure would hand its choices over unless its author remembered); hardcoding the override in the engine (no procedure could reserve a choice of its own); a note appended by the engine (the served text would still say ask the user); a second text per step (eleven duplicates drifting apart); the switch passed when the session starts (the agent opens the session, so it would grant itself); proof of human answers through the client's elicitation (many clients lack it); a hash of the served text checked on every answer (brittle).

Accepted costs: the switch is all or nothing per person; a changed setting reaches only new sessions; every procedure author must mark the choices they hand over; nine procedure entries carry mode conditionals, each with two paths to read.

## Acceptance criteria

- [ ] `dialogue.mode` takes `guided` or `autonomous` in the user-global config and `.sdd/config.local.yaml`, unset means `guided`, the local layer overrides the global; a committed or unknown value leaves `guided` with a warning naming file and key; `sdd config set dialogue.mode` refuses other values.
- [ ] A session records the mode and its source layer when it opens; a resumed session keeps it after the setting changes.
- [ ] A step may declare `delegable: true` only on a user choice; every base user choice carries it except capture's pre-flight override.
- [ ] In an autonomous session, an answer at a delegable choice takes exactly one of `userWords` and `reason`, the served schema says so, and the answer event records who answered; a `reason` at a non-delegable choice is refused. Guided sessions accept and serve answers as before.
- [ ] Every step's text receives the mode; at a delegable choice in an autonomous session the served goal asks the agent to decide with a reason; the base procedures serve autonomous wording without user briefing, move proposals or wrap-up offers; a test fails when a delegable choice's text never branches on the mode.
- [ ] `sdd init` asks for the mode when no layer sets it, writes the answer to the `config.local.yaml` of the project holding the graph, and `--dialogue-mode` answers without a terminal.
