Commit `15384aba` on branch `pr/fix-dead-title-branches`, merged into `pr/core` and `fza-fork`, removes every branch taken when a graph schema has no titles, closing the gap 20261028-085900-s-tac-xln.

Gone: the title refusals in new-entry, summarize and summary replacement, both `refuseTitle` functions, and the `Titles` conditions on title generation and title writes in new-entry, summarize and engine capture. The schema helpers kept only one job, refusing a write to a graph whose schema the binary does not know, and say so in their names: `checkWriteSchema` in `internal/handlers`, `checkGraphSchema` and `checkTargetGraphSchema` in `pkg/application`. That refusal had no test at either layer; `TestWritesRefuseAGraphSchemaUnknownToTheBinary` now covers new-entry and summarize in `internal/handlers`, capture and title correction in `pkg/application`, and each of the four checks broken in the code fails its own case.

The capability table and `titles: true` in `sdd info --format json` stay, as the titles directive (20261028-005411-d-tac-tit) keeps the table for later schema changes, so no public output changes. The owner chose this scope among the gap's candidates. Rejected: dropping the `Titles` field too, a breaking change to that JSON key that leaves an empty capabilities object; keeping the branches driven by a schema row that exists only for tests, production surface no user path reaches. Accepted cost: the `Titles` field stays in the table while no code reads it, until a schema without titles exists.

The full suite, the example module and lint pass.
