One sdd invocation reports a blocked sync at most once, so a command that runs the sync check and then commits no longer prints the captured-but-unpublished warning twice (20261028-004141-s-tac-4k8). The timed sync plan (20261028-175735-d-tac-k4y) reworks the same sync paths, so the fix lands with it.

A held push is one of the blocked states whose banner every invocation prints (20261028-201909-d-tac-fxp); the banner replaces the held-push warning. It goes through a reporter scoped to one invocation: one CLI command, one engine call, or one timer round in `sdd serve`. A repeat within that scope is dropped; the next invocation prints it again while the state lasts. Rejected: leaving publishing to the commit when the command is about to commit, because the sync check runs in the root hook for every command but `init` (`internal/cliapp/app.go`) and cannot tell whether the command will commit; a list of writing commands there would drift as commands are added.

## Acceptance criteria

- [ ] A capture behind a commit not written by sdd prints the blocked-sync banner once, shown by a CLI test against a bare remote.
- [ ] Two consecutive invocations each print a still-held push once.
