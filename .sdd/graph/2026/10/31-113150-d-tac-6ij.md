This entry supersedes 20261031-112948-d-tac-k2y in three points.

1. The vector fingerprint (provider, model, dimensions, document template hash) excludes the endpoint and path. Vectors depend on the model and its output settings, not on the route.

2. Calibration (the input token limit and tokens per rune) belongs to the serving endpoint, not to the vectors. It is stored per (vector fingerprint, endpoint URL, endpoint path), outside the vector store. A changed endpoint recalibrates with three probes and re-embeds nothing by itself.

3. The batch-split rule is withdrawn. A request's prompt_tokens is the sum over all its inputs, so a batch total cannot be compared with a per-input limit. Sizing guarantees that each input fits. Silent truncation is therefore prevented by sizing, not detected per batch.

Sizing, probes and the 2048-rune fallback stand as stated in k2y.

## Acceptance criteria

- [ ] The vector fingerprint is unchanged by endpoint or path.
- [ ] Calibration is stored outside the vector store, keyed by fingerprint, endpoint URL and path.
- [ ] A changed endpoint or path recalibrates without re-embedding stored vectors.
- [ ] No code path splits a batch on its summed prompt_tokens.
