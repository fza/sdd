`sdd search` and the MCP server now search an unchanged graph and index without reloading either, and an index fill no longer locks readers out during its embedding calls, closing 20261028-114254-s-tac-vcy, in commits `fd0194c6`, `a2729067`, `82721145`, `6d2da8c9`, `872b5843`, `da83c00c`, `c525ceb9`, `0ed39a43`, `3e60426c`, `ed333e36` and `385c2d43` on branch `pr/search-and-index`. The branch carries the changes of `pr/feat-graph-load` (`a2729067` is the same patch as its `dd129ac2`) and `pr/feat-graph-revision` (`c525ceb9` is the same patch as its `16386d95`).

- Fill locking: a fill holds a separate fill lock for its run and takes the store's exclusive lock only to commit each embedded batch. The lazy fill before a search skips at once when another process is filling; `sdd index` waits for it. A search waits a bounded time for the store lock, then falls back to text search.
- Search segments: each fill folds the published rows into a few immutable `.seg` files under the store's `segments/` directory, which a search scans exactly, so results equal a chromem query over the same rows. A row not yet in a segment is read from its gob file. A refresh merges segments and removes temporary files a killed writer left and segments in a format the binary does not write.
- Shared mapping: on unix the segments are mapped read-only and shared. A process keeps one view per store across searches and MCP requests and maps only segments that appeared since; a truncated segment fails the search, not the process; an idle view is dropped once the store changed, so deleted segments free their disk space.
- Graph load: entry files are read and parsed concurrently. The graph revision is answered from file stamps (`internal/filestamp`: size, mtime, ctime, inode) while no graph file changed, and computed from content after a change within the last two seconds or on platforms other than darwin and linux. An unchanged graph loads from one cache file under the user cache dir, used only when every file's stamp matches; `SDD_GRAPH_CACHE=off` reads every graph from its files.
- Search phases: the query embedding and the index preparation run while the graph loads, and the lazy fill reuses the loaded graph. `--timing` or `SDD_TIMING` prints one stderr line per phase.
- The index manifest decodes in one pass.
