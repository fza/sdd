Up to release v0.18.0-alpha.2, sdd loads the graph by reading and parsing every entry file one after another, and looks for each entry's attachment directory with a filesystem call of its own, so the load every command and every MCP read performs runs that work for one file at a time.

Expected, as a natural expectation: a load that every read repeats uses the available cores for work that is independent per file, and skips a lookup whose answer the directory walk already holds.

Actual, in v0.18.0-alpha.2, read from the graph source and graph build code at that tag (no load was timed): the graph source walks the graph directory and, inside the walk, reads each entry file and lists its attachment directory before moving to the next file; most entries have no attachment directory, so most of those lookups find nothing. The graph build then parses the collected entries in a single loop.
