Commit 2797b247, merged into the fork's mainline, makes the title field description in the structured-output schema point at the title rule instead of stating its own. It closes the schema title wording gap (20261027-184353-s-tac-6ny).

In `internal/llmops/schema.go` the `title` field of both `summaryResponse` and `titleResponse` now reads "the entry's title written to the title rule the instructions state", so `model.TitleRule`, rendered into the prompt, is the only statement of the rule. The description carries no comma: the schema library splits `jsonschema` struct tags on unescaped commas and would cut the text there. `TestTitleSchemasPointAtTheTitleRule` checks that both schemas point at the rule and state no length guidance of their own; each check failed when its guard was removed.

A live `sdd summarize` run through the openai provider with model glm-5.3-flash, which receives the schema, produced "`sdd view` shows superseded entries from unsynced graphs" and "Old React pin in web viewer `npm` package", each within the rule's length and code-span guidance.
