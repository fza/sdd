Commit 8bde63bc on branch feat/older-schema-writes, merged into the fork's mainline, delivers 20261027-092049-d-tac-7gz. The sdd binary and its MCP server read and write a graph older than the binary at the graph's own schema, and only a confirmed `sdd migrate` upgrades it.

`model.CheckCompatibility` accepts a graph older than the binary and still refuses a newer graph or a binary below `minimum_version`. A per-version table in `internal/model` (`schemaVersions`, read through `CapabilitiesFor`) states what each schema supports and what a migration to it adds. CLI handlers resolve the graph's schema per write through `Reader.SchemaStatus`. The engine reads it per write from the target checkout's `meta.json` through the `GraphSchemaReader` store capability, so a `bind_branch` target in another worktree answers for itself. Reads carry it on the snapshot (`Snapshot.SchemaVersion`). On a schema-1 graph `sdd new`, `sdd summarize`, `sdd summarize --all` and MCP capture write no `title` and make no title-only model call. An explicit title through `--title` or a summary correction is refused with a message naming the graph's schema. `sdd info`, `mcp__sdd__info` (`graphSchema`, `binarySchema`) and the session framing name the graph's schema.

Every acceptance criterion has a test at the layer that owns it: model, handlers, the filesystem store, the application, the production repository targets, and `sdd serve` with `info` on a schema-1 graph. Each new guard was broken once and its test failed on its own assertion. The full suite and lint pass on the branch and on the merge.

Two choices differ from the plan's decomposition. `CompatibilityResult` carries no write schema, because only tests would read it. The combined summary call stays at schema 1 and its title is dropped, because the plan rules out title-only calls, not the paired call.
