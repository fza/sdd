`sdd info --format json` prints the session framing as one JSON object, including the graph's schema and the capabilities that schema supports, so a tool driving sdd can tell before a write what the graph accepts.

## Behaviour

1. `sdd info` takes `--format text|json`, default `text`, as `sdd config` does. Text output stays as it is.
2. The JSON object has snake_case keys, as `sdd export`, `sdd stats` and `meta.json` use: `participant`, `language`, `search`, `graph_schema`, `binary_schema`, `capabilities`, `contribution`. Every key is present on every run, except `graph_schema`, which is absent when no graph schema is known (outside a project, or a graph without `meta.json`).
3. `capabilities` holds one boolean per field of `model.SchemaCapabilities`, today only `titles`. It describes the schema writes use: the graph's recorded schema, else the binary's, the same rule the write path applies.

## Why

A tool that maps its own input onto `sdd new` flags needs to know whether the graph accepts a title, because a schema-1 graph refuses an explicit `--title`. Today the schema reaches the CLI only as the text line `Schema: graph 1, binary 2 (...)`, and as JSON only through the MCP `info` tool. Such a tool reads `.sdd/meta.json` itself and copies sdd's version-to-feature table. That copy goes stale at the next schema version.

## Rejected alternatives

- Schema versions only, without `capabilities`. Smaller output, but every consumer carries its own copy of which version brings which feature.
- A separate `--json` flag. No sdd command has one; `--format json` is the existing convention.
- camelCase keys as in the MCP `info` tool. The CLI's other JSON outputs use snake_case.

## Accepted costs

Each field added to `SchemaCapabilities` becomes a public JSON key that consumers may depend on, so removing or renaming one is a breaking change.

Out of scope: the MCP `info` tool keeps its current shape and gains no `capabilities`.

## Acceptance criteria

- [ ] On a schema-1 graph, `sdd info --format json` prints one JSON object with `graph_schema` 1, the binary's `binary_schema` and `capabilities.titles` false.
- [ ] On a graph at the binary's schema, `capabilities.titles` is true.
- [ ] On a graph without `meta.json`, `graph_schema` is absent and `capabilities` matches the binary's schema.
- [ ] Every `SchemaCapabilities` field appears under `capabilities`; a test fails when a field is added to the struct without a JSON key.
- [ ] `sdd info` without `--format` prints the same text as before, and an unknown `--format` value is an error.
