Up to release v0.18.0-alpha.2, sdd's local graph store works out the graph's revision by reading and hashing every file under the graph directory each time it needs one, so every snapshot, document read and write re-reads the whole graph's content even when no file changed.

Expected, as a natural expectation: a check whose answer only changes when a file changes costs, for an unchanged graph, no more than looking at each file's metadata.

Actual, in v0.18.0-alpha.2, read from the local graph store code at that tag (no read was timed): the revision function walks the graph directory, reads every file and hashes path and content. Taking a read snapshot calls it twice, before and after loading; a current-graph read, a document read and an entry or document publication each call it at least once. Nothing remembers a previous result.
