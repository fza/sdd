`sdd init` cannot run in a project that manages its own agent configuration, because it always writes the sdd MCP server registration, the tool allowance and the skill renders, and commits them under the `sdd:` prefix.

Init's per-agent registration (20260706-180158-s-tac-vhh) is add-if-missing, so a project that removed the `sdd` entry from `.mcp.json` on purpose, and denies the `mcp__sdd__*` tools in `.claude/settings.json`, gets the entry written back on every run. The skill render also deletes renders it no longer ships. In a project whose commit-msg hook admits the `sdd:` prefix only for commits under `.sdd/`, the init commit is refused and init exits 1 with its files staged. Such a project cannot use init even for the parts it would want, such as the `.gitattributes` line of the merge driver (20261030-085158-d-tac-vyt), and adds that line by hand.

Expected: a project can tell init which of these surfaces it manages itself, and init leaves them alone. Commit subject and scope for the rest (`.gitignore`, `.gitattributes`) are unsettled: the hook would still refuse them under `sdd:`.

Rejected: running sdd's git calls without hooks (`--no-verify` or an empty `core.hooksPath`). It would commit exactly the writes such a project reverts, and skip every project's own commit checks on every sdd commit, captures included.
