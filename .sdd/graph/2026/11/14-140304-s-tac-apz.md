The three race fixes of 20261114-120345-d-tac-6n4, two in staged-file freeing and the sweep and one in the log catch-up they rely on, are built on branch `pr/fix-staged-freeing` and merged into `fza-fork` as `d98b01fc`; each of its acceptance criteria holds under a test, and the full suite passes on the merge.

- Publication reads the log before it deletes (commit `674d1bbd`): it catches up with the session log, computes the claims again, records the release of unclaimed files and deletes them only after that append lands. A release append beaten by another attach's write catches up and computes the claims again; a second conflict fails the publication with the usual reorientation message. `TestCapture_PublicationKeepsAnAttachmentAReportNamedMeanwhile` names a file through a second attach, publishes from the stale first attach, which takes that conflict path, and the second capture still finds its file; `TestCapture_ACaptureNamingAReleasedAttachmentRefusesIt` covers a file already released.
- Every catch-up checks for an unfinished write again (same commit): `TestCapture_AStaleAttachCannotReportDuringAnotherAttachsUnfinishedWrite` opens an operation through a second attach, and the stale first attach's report is refused with the unfinished-operation message, with no report logged after the opened operation.
- The sweep reads in-repo session logs (commit `5255a202`): sdd records each checkout path it opens a project from, and the sweep reads `<checkout>/.sdd/sessions` of each. `TestStateSweepKeepsTheStagedAttachmentsOfOpenInRepoSessions` keeps the files of an open in-repo session, also in a second recorded checkout and when the in-repo log cannot be read, which counts as open, and removes them once the session ended or the checkout is gone; `TestTheSweepKeepsTheStagedAttachmentsOfAnOpenInRepoSession` covers the same through the CLI. The configuration reference describes the recorded checkouts. The freeing rules of 20261114-095140-d-cpt-ad4 stand as decided; these fixes only close the races in them.
