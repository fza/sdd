An unknown value of `verify.mode`, `verify.skip`, `verify.runner` or `verify.claude.effort`, and an unknown kind or mode under `verify.kinds`, is ignored on read: every command warns `ignoring config setting` with the key and the file, and the value of the layer below applies, or the default.

A value one sdd version writes must never make another version fail every command. A binary reading a mode or runner a newer version added cannot tell it from a typo, and refusing it turns one config line into a dead binary for every project the file configures. The tolerant-read rule (20260921-174543-d-cpt-tv9) already keeps an unknown key from failing a read; this extends it to an unknown value of these keys, whose allowed values form a closed set, as `sync.mode` already reads an unknown value past (20261027-211908-d-tac-l8j). Writes still refuse a value outside the set (20261110-022557-s-tac-dax), since the writing binary knows its own schema, and the warning keeps a typo visible.

Rejected: failing every command on an unknown value, since an older binary can then never read a file a newer one wrote. Accepted cost: a mistyped value, or one an older binary does not know, runs on the layer below until the warning is read; for a committed `verify.mode` or `verify.skip` that layer is the user-global config, which may check less strictly than the project set.
