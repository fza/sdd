When `sdd init` removes lines from an ignore or attributes file and that leaves a block holding only comment lines, init removes those comments too, with the blank line that separated the block. A block is a run of non-blank lines between blank lines or the file's edges; the rule touches only a block that lost a line in the same rewrite.

Init removes the legacy root `.gitignore` lines by exact match (20261109-004305-s-tac-mp1). A project that wrote its own heading over them, such as `# sdd`, was left with that heading over an empty block after the cleanup. Removing a comment-only block the cleanup emptied leaves the file as it would read had the project never carried the lines.

Rejected, with the reasoning: leaving the heading for the project to remove (every repository that headed the lines needs a manual edit); removing a comment reading exactly `# sdd` (a hardcoded match on text the project wrote, and blind to any other heading). A block the rewrite did not touch keeps its comments, so a project's standalone comment survives.

Accepted cost: a comment that headed the removed lines and also described something else goes with them. A repository whose cleanup already ran keeps its orphaned heading, since no later rewrite removes a line from that block.

## Acceptance criteria

- [ ] A block of `# sdd` and legacy lines, all removed, leaves no `# sdd` and no doubled blank line.
- [ ] A comment-only block the rewrite did not touch stays.
- [ ] A block keeping a non-comment line keeps its comments.
- [ ] A rewrite that removes nothing returns the content unchanged.
