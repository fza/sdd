Deep verifier findings only the user can settle now reach the capturing agent in a block of their own, kept out of its accept-or-contest answer: commits `90803a35` and `a4f021ce` on `pr/fix-capture-eval-defects`, merged into `fza-fork` as `72a33d5e`. Before, they were listed with the findings the agent answers, and in a Codex eval run the agent put one into a contest that sdd refuses.

- The capture procedure's deep-answer step lists answerable findings first, then a block headed "Going to the user after the proposal, not yours to accept or contest:" with the owner-marked ones; with none answerable it tells the agent to accept. Covered by `TestCaptureDeep_AnswerableFindingsAreListedApartFromTheUsers` and `TestCaptureDeep_OwnerFindingGoesToTheUser` in `internal/proctest/capture_deep_test.go`.
- Live check: three Codex capture runs through Opper (gpt-5.3-codex) on a `fza-fork` build, the verifier as headless Claude. In two runs the verifier marked two and three findings as the user's; each deep-answer serve carried them in that block, the agent accepted without a contest, no refusal occurred, and the user saw them before the entry was written. The third run's verifier raised no finding, so it did not exercise the fix. The two runs also answer the open point of 20261113-213512-s-tac-mz1, which made such owner-marked findings deliverable: a real agent run has now shown one reaching the user.
