The fork released v0.18.0-alpha.3.fza.48 on 2026-11-17 as a prerelease of `fza/sdd` (https://github.com/fza/sdd/releases/tag/v0.18.0-alpha.3.fza.48), built from `fza-next` at d546cec4 on upstream v0.18.0-alpha.3 (20261107-123225-s-prc-vgd): binaries for macOS and Linux (amd64, arm64), checksums and `install.sh`, with the Homebrew cask `fza/tap/sdd` at the same version. No test of the merged tree started a real `claude`, `codex` or `sdd`, and upstream `main` had no newer commits at the tag.

The release brings in the open `next/*` branches and fixes for defects that reviews of the upstream pull request branches found in code the fork shares: git commits refusing an empty path list and taking paths literally, init checking its uncommitted-path record before writing, a missing graph folder loading as an empty graph, project setup refusing a misplaced project folder or graph directory before any write, inherited `GIT_DIR` and its siblings stripped from git calls addressed by path, relevance reranker hardening, graph clone sync and widening under the clone's locks, the cache sweep dropping removed worktrees, the staged-body header rule, the verification review fixes, and the removal of the hold-next line (20261117-093307-d-tac-5mq).

The owner also took four features held back from the fork until then: the per-machine allow record for repository hooks (`sdd hooks allow`), which replaces the per-hook hash confirmation and refuses when git tracks none of the hooks folder's files; a per-call config pin in `sdd serve`; one config read per build; and `llm.claude_cli.credentials` for passing Anthropic credentials to `claude -p`, which now runs isolated from its parent session. Existing hook confirmations are not read, so every project's hooks wait for one allow per checkout.
