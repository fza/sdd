`sdd init --graph-repo` now switches a code repository that points at its graph through `project_dir` to `graph_repo` in one run, delivering the three fixes of 20261110-134112-d-tac-42w in commit 672c1aa8, merged into `fza-fork` as 253036d6. That closes the three failures the gap 20261110-112750-s-tac-a31 records.

1. **Resolution from the flag.** `init --graph-repo` resolves the working directory's project as the named graph repository for the whole run, so the code repository's machine-local settings pass. A repository configuring a project of its own still resolves as itself and meets init's refusal. Every other command keeps the `project_dir` check.
2. **Sync before refresh.** An existing, set-up clone runs its sync round before init refreshes it, and init fails when the round reports a blocked sync. Without the round, the test reproduces the gap's `fetch first` rejection.
3. **Push only with commits waiting.** Publishing a clone with nothing ahead of its upstream pushes nothing and meets no cooldown; this also holds for `sdd move`, which publishes the same way.

Each fix carries a test, and each new guard was broken once and caught by its test, except the failure on a blocked round, which no test reaches: the test remotes never conflict. The test remotes are local paths the git gate never holds back, so only the unit test of `repos.GraphClones`, which owns sdd's clones, covers the push cooldown.

Deviation: the branch `pr/fix-init-graph-repo-switch` is cut from `pr/feat-init-commit-subject`, not `pr/feat-graph-repository`, because the latter lacks the git gate the fixes build on.
