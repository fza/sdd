`sdd init` commits only those of its paths that differ from the last commit: before committing, it asks git status which of them changed, and makes no commit when none did. A skill file that init restores identical to the committed one then counts as no change, instead of failing with `nothing to commit` (20261110-000819-s-tac-q3a). Paths carried over from the retry record (20261030-180738-d-tac-f1k) pass through the same filter, so a leftover that a later commit already holds clears the record without a commit.

Rejected: treating git's `nothing to commit` reply as success. It depends on git's English message text, breaks under a translated git, and can hide a commit that staged nothing for another reason.

Accepted cost: one more `git status` call per init run.

## Acceptance criteria

- [ ] Deleting an installed, tracked skill file and running `sdd init` restores the file and exits 0 without a new commit.
- [ ] A path init creates or changes is still committed.
- [ ] A retry-record path that no longer differs from the last commit clears the record without a commit.
- [ ] No init code path reads git's message text to decide success.
