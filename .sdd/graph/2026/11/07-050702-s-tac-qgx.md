A graph repository named by `graph_repo` is now read and written through one sdd-owned partial sparse clone per machine, with the gates, upkeep, merge routing, conflict rules, protocol choice, init flow and stock guard of 20261106-202055-d-tac-eyl, closing it in commits `c31253c9` to `ce963200` on `pr/feat-graph-clone`, merged into `pr/core` as `87f32701` and into `fza-fork` as `7d4f85a0`.

Each acceptance criterion is met, each with its test: `TestCloneGraphIsBloblessAndSparse`, `TestConnectedWriteRefusal`, `TestConfigSetRepoOverride` and `TestConfigSetRefusesInbound`, `TestKeepGraphCloneDiscardsWhatSddDidNotMake`, `TestCloneMergesTitleChangesThroughTheEntryDriver`, `TestCloneLetsAnUpstreamDeletionWin`, `TestCloneMergesConfigPerKey` and `TestCloneFollowsAForcePush`, `TestGraphRepoForcePushReaddsOnlyARefiningEntry`, `TestCloneProtocolChoice`, `TestInitGraphRepoAndTheStockGuard`, `TestResolveProjectFollowsGraphRepo`. One guard, clearing the graph-repo pointer during project init, cannot be broken for a test because the break recurses without end. Capture into a declared dependency writes, commits and pushes through that dependency's clone when `connected.write` and `inbound.accept` both allow the pair, and is refused at `start_procedure` naming the gate otherwise (`TestConnectedCaptureWritesThroughTheClone`, `TestConnectedCaptureRefusedAtStart`).

Where the build differs from the decision:
- For a `graph_repo` project the local config layer is the code repository's untracked `.sdd/config.local.yaml`, since upkeep removes untracked files in the clone; `sdd config set --local` in the code repository writes there, and init writes the participant there and ignores the file in the code repository's `.gitignore`.
- `sdd init --graph-repo` also installs skills and the MCP registration in the code repository, which agents working there need; the decision named only the pointer and the guard.
- After a force push, re-deriving `title` and `summary` carries sdd's own change onto the rewritten entry without an LLM call, and an entry with a cross-repo ref is never re-added automatically.
- Timer rounds in a clone need `sync.mode` set; on-call and CLI rounds treat the clone as automatic.
- The stock-guard criterion is checked by running this build on a config without `graph_repo`, not a stock binary.

Reading connected graphs from the sdd-owned clone instead of the cache clone, part of 20261106-201216-d-cpt-aim, is not built: a dependency is read from its clone only once one exists for a write, otherwise from its read-only cache clone under `$XDG_CACHE_HOME`.
