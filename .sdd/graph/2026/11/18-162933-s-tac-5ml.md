An MCP read on an unchanged graph now reuses the graph snapshot instead of rebuilding it from disk, and leases it without the graph lock (c1623b01 on `fza-next`). `AcquireSnapshot` in `pkg/local` dropped the snapshot when its last lease ended, so every read rebuilt it, four times per verifier page turn, and waited on the graph lock a sync round holds across git fetch and push. The latest snapshot now outlives its leases and is leased lock-free while file stamps prove the graph unchanged. This extends the operation-scoped acquired reads of 20260907-102247-s-tac-0br.

On a 1,500-entry graph a page turn fell from 310ms to 60ms. One page turn that took 314s likely waited on the graph lock held by a sync round; it was not reproduced.
