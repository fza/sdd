One daily sweep keeps sdd's three per-user folders (cache, state, data) free of data nothing needs. The background `sdd cache prune` run of 20261101-131514-d-cpt-9ci, started at most once a day and detached from any command, with `sdd serve` checking hourly, widens from the cache folder to the state and data folders. Session collection under the rule of 20260914-113911-d-tac-wgw moves into it: today it runs only when `sdd serve` starts (`internal/cliapp/serve.go:102`, the trigger 20260731-080621-s-tac-jkw delivered), so a long-running server or CLI-only use never collects. The folders keep the placement of 20260708-184318-d-cpt-6cq; the sweep only decides when their data goes.

What changed: old data piles up where no cleaner reaches. Measured on one machine: the cache index 2.3 GB, state sessions 450 MB (849 logs), data clones 141 MB, graph snapshots 105 MB, 239 staged attachments older than 7 days. The daily cache prune touches the state folder only to drop hook confirmations no checkout declares, and session collection runs only at `sdd serve` startup.

## Rules

1. **Inline deletes where data stops being needed.** A staged attachment is deleted once the entry that used it is published. A session's staged attachments are freed when the session ends, except those a pending write still claims, which stay until that write is retried or cancelled, as 20260914-113911-d-tac-wgw requires. Gate trace files stay removed after each git operation, as today.
2. **Sessions.** The sweep never ends an open session. It removes an ended session once `sessions.retention` (default `14d`) has passed since it ended, with its staged attachments. Rejected: ending sessions after 30 or 7 idle days, sparing only parked ones. Accepted cost: open sessions and their attachments keep growing; this machine holds 228 open sessions, 88 of them idle for over a week.
3. **Per-project state of unused projects.** sdd stamps a project's state folder when it uses the project, refreshed at most once a day, as the index use stamps are. The sweep removes the project's relevance ledger, and its session folder once no session is left in it, after `cache.retention` (default `90d`) without use. Open sessions are always kept. Rejected: a separate `relevance.retention` of 365 days; removing only empty folders. Accepted cost: a project paused for over 90 days loses its calibration labels and pays for reranker calls again.
4. **sdd-owned clones.** The sweep removes only clones whose repository the user-global `repos` list no longer names, the rule of 20261101-131514-d-cpt-9ci, and as 20261107-095427-d-tac-yux and today's code require, never one holding unpushed commits or one whose remote the git gate reached within `cache.retention`, which keeps a project's own `graph_repo` clone that the list never names. It runs `git gc --auto` in each listed clone; the run is local and spends no git-gate budget. Rejected: removing a clone unused for 90 days while keeping its list entry, which makes the next read wait for a re-clone; removing the clone and its list entry, which has sdd edit the user-global config. Accepted cost: clones of listed repositories nobody reads stay.
5. **Search index.** A new user-global key, `index.replaced_retention` (default `14d`), sets how long replaced index data survives. The sweep drops it 14 days after its replacement or its last use, whichever is later: older versions of an entry, unless a checkout record of 20261101-153339-d-tac-pnl (the per-checkout file in the store naming the versions that checkout still reads) protects them; data in older index formats (v0, legacy); the store of a replaced embedding setup, judged from the stores' own use stamps (another store of the same repository used after it), never from embedding config, which a background process cannot see per repository. A whole unused store keeps `cache.retention` (90 days). This shortens the 90-day version retention of 20261101-131514-d-cpt-9ci; `sdd index gc` of 20260910-183941-d-tac-c9c stays for deliberate cleanup. Evidence: this repository's store under a replaced embedding setup holds 437 MB, last used 2026-11-01; the current store holds 344 MB, of which search reads 72 MB, 67 MB are older versions or other branches' and 51 MB older format. Rejected: 3 days; keeping 90 days. Accepted cost: one more key, and switching back to an embedding setup after two weeks re-embeds the graph, a paid run.
6. **Crash leftovers.** The sweep removes leftovers older than 1 day that no lock holds: gate trace files, `.adding-*` and `*.cloning` clone staging, index `.entry-*` temp files, retired index store folders with their lock files, empty legacy cache host folders.
7. **Other records.** The sweep removes readable graph snapshots of folders unused for `cache.retention`, `remotes.json` repository records and embedder calibration files unused for `cache.retention`, and orphan index rows. It keeps an unreadable session log and reports it, because it cannot tell whether the session ended.

Rule 6 and the rest of rule 7 follow from the frame of 20261101-131514-d-cpt-9ci without a choice between routes; rule 7 widens its snapshot rule, which today removes a readable snapshot only once its graph folder no longer exists, to folders unused for `cache.retention`. Every rule keeps that frame: the sweep adds no latency, output or lock wait to a command, skips what another process holds, and reports a failed run once.

## Fulfilled when

- A test per rule shows the sweep removes each kind of data after its period and keeps what the rule keeps: open sessions, ended sessions within `sessions.retention`, unreadable session logs, listed clones, unlisted clones holding unpushed commits or whose remote the git gate reached within `cache.retention`, versions a checkout record protects, store data used within `index.replaced_retention`, state of a project used within `cache.retention`, leftovers a lock holds or younger than 1 day.
- A test shows a staged attachment deleted once its entry is published, and a session's staged attachments freed when the session ends, except those a pending write still claims.
- `sdd serve` no longer collects sessions at startup; the sweep does, also with no server running.
- A measured run over this machine's three folders completes every rule inside its 5-minute cap (`CachePruneRunLimit`) instead of stopping at it.
- The configuration reference documents `index.replaced_retention`, the widened scope of `cache.retention` and the sweep as the trigger of `sessions.retention`.
