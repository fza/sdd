A saved search index now builds its published view once under a mutex, so concurrent first queries no longer race (4d6644a8 on `fza-next`, cherry-picked from 6016f922). Parallel summarize workers share one saved index and query it together; its lazily built published view was read and written without a lock, so concurrent first queries each built a full copy and raced on publishing it. This fixes the published-coverage search of 20260906-165355-s-tac-hjq under concurrent queries.
