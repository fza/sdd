Two delegate launch settings on `fza-fork` rest on documentation alone and never ran against a live harness. The headless `codex exec` round passes `-c project_doc_max_bytes=0` to skip the repository's AGENTS.md; the live probe could not run because Codex is not logged in on this machine. The `sdd_delegate` subagent definition `sdd init` installs for Claude Code (`.claude/agents/sdd_delegate.md`) carries `omitClaudeMd: true` and the install stamps under `metadata:` in its frontmatter; no live Claude Code session has loaded it to confirm the keys are read or ignored without error. The headless `claude` round itself was verified live after its flags were changed (20261109-055134-s-tac-f60), and both settings were written for the per-harness launch configuration (20261109-055022-s-tac-qpy).

Expected, from the dispatch handoff (20260829-122157-d-cpt-zpe): the shipped per-harness launch configuration lets a harness launch a delegate that reaches the engine's MCP tools and holds only its child handles, which a setting the harness ignores or refuses would break unnoticed.
