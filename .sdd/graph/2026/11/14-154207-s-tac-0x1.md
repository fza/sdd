sdd's credential scan now reads gitleaks' published `config/gitleaks.toml` as is, from a copy built into the binary and a copy the daily background pass fetches from gitleaks' latest release tag, as directive 20261114-134103-d-tac-73e commits. Commit `69089bb9` on `pr/feat-secret-rules-fetch` builds the scan side, merged into `fza-fork` as `435738d8`; commit `76eeb82a` adds the release step, merged as `b2d7e712`. The built-in copy is gitleaks v8.30.1 (commit `83d9cd68`).

Each acceptance criterion holds:

- Built-in file: `internal/secrets/gitleaks.toml` is embedded unchanged with its tag and commit in `gitleaks.source.json`; `rules.json` and `vendor-rules.py` are gone. Decoding uses `go-toml/v2` with unknown fields refused (`TestTheBuiltinRuleFileReadsStrictly`), and the loader lowercases keywords and stopwords and uppercases allowlist conditions as the deleted converter did (`TestParseRulesNormalizesAsGitleaks`); `TestScanGitleaksSamples` passes on the built-in file, and the `generic-api-key` narrowing still applies after a match (`TestGenericAPIKeyNeedsADigitOrMixedCase`).
- Release refresh: `devbox run refresh-secret-rules` fetches the file at gitleaks' latest release tag, and the release procedure runs it before tagging and commits a changed file.
- Daily fetch: the scheduled cache pass calls the updater while `secrets.rules_update` is `daily` (`TestCacheHandlerPruneFetchesSecretRulesPerSetting`); a newer tag's file lands in the machine-local cache (`TestUpdaterStoresANewerRelease`), and a running `sdd serve` picks it up without a restart (`TestUsePicksUpACopyFetchedAfterTheFirstScan`).
- Rejection: a file with an unknown key or a regex that does not compile is refused (`TestParseRulesRefusesAnInvalidFile`), as is one missing a built-in rule id (`TestParseFetchedRulesNeedsEveryBuiltinRule`). The copy in use stays and the failure is recorded with its time (`TestUpdaterKeepsTheCopyInUseOnAFailure`); the pass logs a warning, and `sdd info` shows the last failure with its reason and time, and the time of the last accepted fetch.
- A failed fetch never blocks a write: fetching runs only in the background pass, which goes on past a failure (`TestCacheHandlerPruneGoesOnPastAFailedFetch`); scans read only local copies.
- Switch: `off` stops the fetch and selects the built-in file (`TestInfoNamesTheSecretRulesInUse`); `sdd config set` refuses values other than `daily` and `off` and any target but the user-global config (`TestConfigSetSecretRulesUpdate`); a per-repo value is ignored with the `ignoring config setting` warning naming file and key (`TestIgnoredSettingsReadsSecretRulesUpdateFromTheGlobalConfigOnly`).
- Docs: the configuration reference lists `secrets.rules_update` and describes the fetch under the daily sweep; the working-modes page describes the built-in file and the daily fetch.
