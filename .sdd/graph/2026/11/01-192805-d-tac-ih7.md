`ShowResult.Entries` and `SearchResult.Results` in `pkg/application` are deprecated now and removed in the first release after the one that ships the deprecation; that removal closes 20261101-182713-s-tac-a00.

With the deprecation, nothing in this repository reads the fields any more: the MCP server renders its `show` and `search` text from `Items` and `Hits` with the shared renderer of 20261101-191250-s-tac-8lm, and the engine's `entryChains` inject renders its chains the same way. The application keeps filling the fields until their removal, so an outside caller keeps working for one release and learns of the change from the `Deprecated:` doc comment and the release notes. The release that removes them lists the removal under Breaking.

Rejected:
- Removing the fields at once. `pkg/application` is the public Go surface, and the outside callers it may have get no release in which to move.
- Keeping the fields. The public results would keep two forms of every read, against 20260928-080143-d-cpt-kv4.

`view` is not part of this: its result has no data form yet, so its text field stays; that is a gap of its own, which refers back to this entry.

Accepted cost: two changes instead of one, and one release in which the application renders text no in-repo caller reads.

Fulfilled when the fields are gone from `pkg/application`, the MCP server's text output is unchanged, and the removal release names it under Breaking.
