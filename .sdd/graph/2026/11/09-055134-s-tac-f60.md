The headless launch of the deep verifier (`verifier.launch: claude | codex`) has never run against a live agent CLI, and each launched round holds the calling engine request open. The flags in `internal/delegatelaunch` rest on two assumptions no probe confirmed: that a `claude -p` round keeps the one sdd MCP server passed through `--strict-mcp-config --mcp-config`, and that `codex exec` can run without reading the repository's AGENTS.md. A round is bounded by `RoundTimeout` (30 minutes), and the `start_procedure` or `next` call that launches it waits for the round to end.

Expected, from the draft verifier directive (20261109-004729-d-cpt-xs5): the deep mode's tool-using verifier works under every launch value, reaching sdd only through its own MCP server, and an engine call answers within what an MCP client waits for.

Candidates, unsettled: one bounded live probe per CLI before the launch values are documented; returning the call at launch and picking the round up on a later call, as a harness-launched subagent round already does: the dispatching call returns at once and a later `next` picks the delivery up.
