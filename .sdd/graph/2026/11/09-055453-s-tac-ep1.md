A chooser answer the engine refuses still leaves the fields it collected in the instance's store. The engine records an answer's `fields` before it runs the option's command, so when the command refuses the answer, the next serve and any later guard read the refused values as if they stood. The verifier build (20261109-054916-s-cpt-mn7) met it on a refused deep-verify answer and reported it from the code path; it was not reproduced in a test of its own.

Expected: a refused answer changes nothing, the instance holding exactly what it held before the call, as a refused report does.
