A sync of an sdd-owned clone fetches the full contents of the commits it brings, so the merge after it runs without reaching the remote, and every git command sdd runs in the clone outside a gate admission is barred from fetching contents on its own. This answers 20261107-132320-s-tac-2za.

The clone is partial (20261106-201216-d-cpt-aim): a fetch brings commits and trees, and git fetches file contents by itself when a command needs them. A merge that brings changes therefore opens connections outside the per-machine git gate (20261107-095427-d-tac-yux). Measured with a stand-in for ssh that counts connections, a sync round that brings changed entries opens three connections and the gate records one: the fetch, a batched fetch of the changed entries' contents during the merge, and a fetch of the changed code files' contents for the diffstat git prints after the merge. The [probe record](./07-224549-d-tac-r9q/lazy-fetch-probes.md) holds the numbers and scripts.

The rules:

- The fetch in the clone runs with `--no-filter`. It stays one connection and brings the full contents of the new commits only; older commits keep their contents on the remote. `remote.<protocol>.partialclonefilter` stays set, so the clone stays partial.
- The merge in the clone runs with `--no-stat`.
- Every git command sdd runs in the clone while a gate admission holds gets the admission's environment: the gate's `GIT_TRACE2_EVENT` file, plus `GIT_SSH_COMMAND` with `BatchMode=yes` and `ConnectTimeout=5` and `GIT_TERMINAL_PROMPT=0`, the settings 20261106-202055-d-tac-eyl gives the clone's fetches and pushes. This covers the checkout after a fresh clone and `sparse-checkout add`, which fetch contents themselves.
- Every other git command sdd runs in the clone carries `GIT_NO_LAZY_FETCH=1`. A command that needs contents the clone lacks fails with git's `could not fetch <oid> from promisor remote`, sdd returns that error, and no connection opens. Measured, such a merge exits 128 and leaves HEAD, index and working tree unchanged.

A sync round that brings changes then opens one connection, and the gate records it. The merge, the conflict prediction and the merge after a rejected push run offline.

This replaces an accepted cost of 20261106-201216-d-cpt-aim: contents outside the sparse set no longer come from the remote on first use. A read that needs them must run inside a gate admission. No such read exists today.

Rejected alternatives:

- Running the merge inside the fetch admission with the trace environment, as 20261107-132320-s-tac-2za proposes. It costs two connections per round instead of one, and the sync round must move its merge and conflict recording into the gate operation.
- Fetching the missing contents in a second step, by listing the blob ids that `HEAD...upstream` changes within the sparse set and fetching them by id. It costs two connections per round, and sdd would own a copy of git's internal promisor fetch.
- Counting only: the trace environment where an admission exists, no bar on lazy fetches. The sync round's merge runs outside any admission and stays uncounted, and nothing reports a fetch the gate missed.
- `--filter=blob:limit=<size>` on the fetch. Measured, a promisor fetch still followed it, two connections.

Accepted costs:

- A code repository holding its graph downloads the contents of every code file the new commits change. On this repository's history, 317 commits brought 4,475 KiB instead of 2,565 KiB and 773 commits 6,363 KiB instead of 3,430 KiB, about 1.8 times. A repository holding only its graph pays almost nothing extra.
- Git versions that do not know `GIT_NO_LAZY_FETCH` ignore it, and the bar is absent there.
- The connections were measured over ssh only.

## Acceptance criteria

- [ ] A sync round of an sdd-owned clone that brings changed entries and a changed code file opens one connection, and the gate records one.
- [ ] The merge in the clone runs with `--no-stat` and `GIT_NO_LAZY_FETCH=1` and succeeds after the fetch.
- [ ] Every git command sdd runs in the clone carries the admission's environment while an admission holds, and `GIT_NO_LAZY_FETCH=1` otherwise.
- [ ] A command outside an admission that needs contents the clone lacks returns git's error and opens no connection.
- [ ] The checkout of a fresh clone and a `sparse-checkout add` run inside the clone's admission, and the gate records their connections.
