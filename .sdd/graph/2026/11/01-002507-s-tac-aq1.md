A new entry is now created exclusively and never written over an existing file, which closes the overwrite gap 20261101-002159-s-tac-axk. Commit d17466de on branch `pr/fix-entry-writes` opens the entry file with `O_CREATE|O_EXCL`. When the ID is taken, the handler draws a fresh suffix with the same timestamp, type and layer, updates the entry's ID, and tries again, up to eight attempts. Attachment files are created exclusively too.

This is the candidate remedy the gap entry proposed, applied unchanged. Merging into `fza-fork` (merge dd96bb0a, not pushed) conflicted with the credential check added to the same handler on that branch; both sides were kept, and the handler tests pass on the merge.

A new test captures 1000 entries under a frozen clock and checks that every capture reports its own ID and that each reported file exists. Switching the exclusive open back to a truncating one turns it red. The attachment path has no test of its own.
