An `sdd init` run that keeps a user-edited skill file and changes nothing else now prints its full report, the `preserved:` notice included, closing 20261110-004731-d-tac-0g9 with both of its acceptance criteria met.

- a04b95dc, merged into `fza-fork` in 790bc922: the init command tracks whether the skill install kept a modified file or the orphan sweep kept an edited file the bundle no longer ships; such a run counts as not up to date, so the report prints and the one line does not. A run keeping nothing still prints `sdd: everything up to date, nothing changed`.
- Tests cover the edited installed skill (full report, no commit) and the edited orphan; the existing no-op tests still pass. Each of the three new guards was broken, seen failing its own test, and restored byte for byte.
- A run of the built binary in a scratch copy of a project with one edited skill printed both skill blocks and `preserved: 1 modified file(s) left untouched` with the path, and made no commit; after restoring the file, a run printed the one line.
- An edited skill of an agent dropped from the setup needs no check: it is kept only on the run that drops the agent, and that run rewrites the config, so it prints its full report already.
