The fork released v0.18.0-alpha.3.fza.51 on 2026-11-18 as a prerelease of `fza/sdd` (https://github.com/fza/sdd/releases/tag/v0.18.0-alpha.3.fza.51), built from `fza-next` at 255bb349 on upstream v0.18.0-alpha.3: binaries for macOS and Linux (amd64, arm64), checksums and `install.sh` from a release workflow run that succeeded, with the Homebrew cask `fza/tap/sdd` at the same version, installed on the owner's machine. It follows v0.18.0-alpha.3.fza.50 (20261117-213803-s-prc-6g1).

The release brings the deep verifier's reading ranked and tiered so it fits a verifier's context on a large graph: near 46k tokens where one reading had run to 84 pages, with calibration seeded from the graph's own refs (20261118-162919-s-tac-2t0, settled in 20261118-173708-d-tac-euf).

Its notes list five breaking changes. One ranking judge ranks both readings: `llm_prefilter.protocol` takes `cohere`, `systemone` or `chat`, the old values still read; without a configured `llm_prefilter`, a Claude client ranks with `claude-haiku-5-5` through the `claude` CLI, which needs a claude login; and `sdd grounding status` prints a compact view, the full detail under `--verbose` (20261118-162927-s-tac-pq5). Only directives and plans owe a reason, and assisted mode asks no separate reason question (20261118-162948-s-tac-kd7, settled in 20261118-173349-d-tac-8jh). `sdd grounding rescore` and `seed --from-refs` take `--judge <name>`, and in `pkg/application` `RescoreRelevance` and `SeedRefLabels` take a `RescoreRequest` and return one `RescoreResult`; both commands also finish past failing entries (20261118-162941-s-tac-450).

As other changes it ships reads on an unchanged graph reusing its snapshot without the graph lock (20261118-162933-s-tac-5ml), waiting instruction lanes that drain however a call proves (20261118-162937-s-tac-qdi), and parallel summarize runs that no longer race on a saved index's view (20261118-162954-s-tac-a50). A pre-flight kind-fit finding that names no other kind no longer blocks (032722e6); no entry records that fix.
