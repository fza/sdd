`sdd init` fails when it restores a skill file that is tracked in git and was deleted from the working tree: the restored file matches HEAD, init still passes it to `git commit -- <path>`, git answers `nothing to commit`, and init exits 1 with `git commit, which the next sdd init retries`, the retry record 20261030-182052-s-tac-t2c added.

Reproduced with the build of `fza-fork` at e954d96b in a scratch project: deleting the installed `.claude/skills/sdd/SKILL.md` and running `sdd init` exits 1 and leaves the file restored and clean. The next run prints the no-op line, so the failure clears itself, but a person who deletes a skill to have it reinstalled sees init fail.

Two candidate fixes, neither chosen: commit only paths that differ from HEAD after the write, or treat `nothing to commit` for init's own paths as success.
