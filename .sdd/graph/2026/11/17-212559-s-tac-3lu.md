Four follow-ups to the auto-mode agent decision marks (20261117-175601-s-tac-69f) and the first-clone fix (20261117-172339-s-tac-mga) are merged on `fza-next`: commits 407f0e47, b481cbff, 1e7425bf and 51ca2b89, with the configuration reference and the coding-agents guide updated in 6ac5763e.

- An auto-mode entry's participant is the actor of the client that started the capture, which the session log records per capture, not the client attached last.
- A client that sends no name cannot start or write an auto-mode capture; starting a session, reads and abandon still serve it.
- A decision drafted in auto mode and confirmed in guided playback returns to assemble for the user's `reasonWords` and, for a directive, `intentWords`; guards on the approval and write steps hold it there, and the written entry is the person's. The reopened playback of 20261117-173207-s-tac-up6 no longer writes such a decision without them.
- A failed first clone of a connected repo waits out its retry wait and cooldown like a failed fetch (`gitgate.CloneFailed`), instead of retrying on every read; a fetch in another data folder still never holds a first clone.

The first and third settle the two items the marks delivery left for follow-up. Each change has a test that failed before it.
