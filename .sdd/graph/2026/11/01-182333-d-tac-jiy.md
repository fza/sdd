`show` and `search` text is rendered by one renderer over public data types, for the CLI and the MCP server alike, while `Application.Show` and `Search` keep their `Entries` and `Results` text for now. It realizes the rendering split of 20260928-080143-d-cpt-kv4 for these two reads, up to the point of removing the text.

The public entry type carries the whole entry, since `show` prints every frontmatter field: refs, closes, supersedes, topics, participants, confidence, intent, time, procedure spec and pre-flight data, beside the identity, status, body and chains the partial types of 20261101-173830-s-tac-hnv already carry. Search hits carry their citations. The types live in `pkg/application/types`, because the renderers cannot import `pkg/application`, which imports them. The renderers in `internal/presenters` (`show.go`, `show_styled.go`, `search.go`) are rewritten over these types, the CLI converts finder results to them before rendering, and the application fills its text fields through the same renderer. Output stays byte-identical, pinned by the existing presenter snapshot tests and CLI tests.

Rejected:
- Renderers over public types for the MCP server only. The CLI would keep the old renderers, and one output would have two renderers to keep in step.
- Handing the raw finder result out of the application for the MCP server to render. The public API would carry internal types outside callers cannot use, against the point of 20260928-080143-d-cpt-kv4.
- Keeping text beside data with no change. The application would keep two renderings of every read it exports.
- Removing the text fields in the same change. That breaks every caller of `pkg/application` for no gain the shared renderer does not already bring; the removal stays open as a gap of its own.

`View` is out of scope: it has no data form yet.

Accepted cost: about 1,300 lines of renderer code reworked, a full public entry type to maintain alongside `model.Entry`, and the text still in the public API.

Fulfilled when `show` and `search` text, on the CLI and over MCP, comes from renderers over the public types with output unchanged, and the application's text fields are filled by that renderer.
