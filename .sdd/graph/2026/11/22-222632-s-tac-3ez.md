The verifier's rules pages leave out the rule text code decides, the contract code enforces and the ref-kind vocabulary, and an entry the drafter dismissed reaches the verifier as one line, as the plan 20261122-101625-d-tac-r0s decides. The commits bad8bd056, c083c83c1, 39773cbe4 and 46403fcc8 are merged on `fza-next` in c1e04603c. No release holds them yet. Every acceptance criterion of the plan is met.

## What is built

- `model.TypeSystemContractID` and `model.CodeEnforcesContract` (`internal/model/construction.go`) name the type-system contract 20260702-222259-d-cpt-7iy as the one code enforces. In rubric mode the contracts block leaves out each contract that value names.
- `model.StandardClose` (`internal/model/close_pattern.go`) is the matrix of the six standard close patterns, a pure function of the closing and the closed entry's type and kind.
- In rubric mode the rules text leaves out the acceptance-criteria rule of a plan with its `high` band, the applicability paragraph, and the close-pattern rule when every close of the draft is standard. The ref-kind vocabulary renders as one line that names the ref-kind fact and says when to open it. Pre-flight's own prompt is unchanged.
- An entry with a drafter's verdict is one line of the verifier's reading and no brief. `llmops.DeepReadingBlock` renders entries in full only. Since the plan 20261121-223938-d-tac-rqi merged (cedaba593), the line is that plan's marked line with the note `drafter: dismissed, <code>` (`pkg/application/workflow_deep.go:744`), and the verification procedure's line on dismissed entries says so.
