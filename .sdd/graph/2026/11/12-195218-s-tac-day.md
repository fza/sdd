The serve token-cost plan (20261112-075604-d-tac-t4r) is built and merged into `fza-fork` at be6829d6: anchor proofs replace `sessions.token_saving`, every MCP result stays within 18,000 characters, report schemas and framing shrink at the source, and the deep verifier continues on a changed draft. On a proctest capture with a deep verifier, total result bytes fell from 647,860 to 369,678 and exact repeats from 41.8% to 8.8%; the four source trims cut a further 20.6% of served bytes (189,933 to 150,789). The Codex evals behind the fixes below are in the [eval record](./12-195218-s-tac-day/eval-record.md).

**Built as planned.** Each served piece carries a `⟦xxxx⟧` tag; a call proves holding it with `held: ["tag:word"]` and gets a pointer, names a lost piece in `reread`, and gets full text on a missing or wrong proof; a subagent without tags gets full text. The proof guide carries a worked example. `sessions.token_saving` and its object result forms are gone; the key reads as ignored and is refused on write. No command installs a hook, and no serve asks the user about token saving. The rules page reaches the verifier whole across pages, without the draft, its referenced entries or sections whose guard fails; the regression tests for the cut page landed with the fix in 9723a292. Await-only steps serve no schema, revise schemas drop dispatch-received and single-option fields and `procedureSpec` outside procedure drafts, the properties block is its own piece, the verifier's fixed rules are their own lane, and the sync notice serves once per change. The full-or-pointer choice moved from the MCP shell into the engine, which records each issued tag and word as session events, so a restarted server keeps them; gather brief lines stay in full. An entry read in full counts as served, which closes the gap of the served-once memory ignoring the read ledger (20260827-224141-s-tac-6uf); the properties block serving apart from the per-step required list closes the gap of the schema stub that never fired across gate steps (20260827-224111-s-tac-vz9). A revision reaches the live verifier with the changed passages and, on later pages, the entries read since its reading, including a headless one, which resumes its agent session; a fresh verifier starts only when the child ended, after three revisions, or without a session to resume, and its dispatch says which. Accepting the proposal without draft fields writes it into the draft, and the proposal serves its hunks only (561109b3).

**Deviations.**

- The bound is 18,000 characters for every host, not 50,000, and verifier pages hold `MaxResultChars - 6000`, because Codex drops the middle of any result above about 19,000 characters. Lanes, framing and vocabulary that do not fit wait for the next call on the instance, which serves them whatever the call proves; the opening, the resume, a completed move and park or abandon landings stay within it.
- The four cuts that change what an agent reads (shorter field descriptions, only the failing fields' schema on a held gate, framing declared per step, recent movement capped at 5 with a count and `view` layout for the rest) landed without the paired eval the plan required: the comparison could not separate them from defects found in the same batch, and it was not repeated after those defects were fixed.
- The Codex half of the anchor spike was not run, because its harness needs a provider key this machine does not hold; the post-compaction criterion holds for Claude Code and simulated Chat only, on the plan's spike of 5 runs per arm recorded in its design record, and the Codex run stays owed before a release.
- That verdicts, findings and dialogue are unchanged against the earlier behaviour is not shown: the evals changed the capture's behaviour on purpose.

**Added from the evals.** Headless codex rounds run with sdd's tools approved, stop past `verify.round_timeout` (default 10m), and a round that ends without delivering fails into the retry, skip or abort step; a verifier sdd launched hands the drafter no handle; a wait serves one line with a 20-second recheck. The capture tells the drafter whether pre-flight's model judged, which findings the verifier withdrew or accepted without an edit, to name dismissed guide findings before proceeding, to ask the user for a missing why or intent and never supply one, to mark inferred reasoning at playback, to confirm only on the user's own words, and to put findings on facts only the user knows to the user. A capped listing ends with the count left out and the layout serving it; a store value's cut notice shows only where a lane reads it; a lane larger than the room serves alone.

**Open.** The base framing inside a move's result and its landings is composed whole, only its lanes wait. An agent sending no proofs still pays far more (37.7% repeats against 8.8%). Paged reads are held in server memory, so a restart or a stateless replica loses later pages.
