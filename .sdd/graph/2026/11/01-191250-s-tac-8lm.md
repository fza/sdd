`show` and `search` text now comes from one renderer over public types in `pkg/application/types`, for the CLI and for the application's `Entries` and `Results` text: commit `e6f5a545` on `pr/feat-shared-renderers`, merged into `fza-fork` as `e1e3594f`.

- One conversion from query results to the public types, `(*query.ShowResult).ShownEntries` and `(*query.SearchResult).Hits` in `internal/query/shown.go`, used by the CLI, the application and the presenter tests. It precomputes kind label, first sentence, derived status and supersede trail, unresolved repo, effective topics and the owning member graph, so the renderers read no graph and no `model.Entry`.
- The search entry line and `view`'s entry line share one formatter over a small value; `view` is otherwise untouched.
- Procedure spec sections travel as YAML text, keeping `pkg/application/types` free of non-standard imports; `RenderShow` and `RenderShowStyled` return the error of decoding them.
- MCP object output is unchanged: the new fields are not mapped into the MCP result types, and the tool contract snapshot is unchanged.

Output is byte-identical: plain, styled, with-summary, deep and search renderings of the whole graph (1,892 entries) match before and after, and no snapshot file changed. The full suite and the `examples/extendingsdd` module pass on `fza-fork`. Breaking the kind-label fallback fails the conversion test and a presenter test.

The application's text fields remain, as 20261101-182713-s-tac-a00 records.
