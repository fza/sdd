A connected graph repository is still read from its read-only cache clone, not from the one sdd-owned clone that 20261106-201216-d-cpt-aim names for both reads and writes; the graph-clone delivery 20261107-050702-s-tac-qgx left this part unbuilt.

Actual: the MCP server builds a dependency's runtime from the cache in `$XDG_CACHE_HOME` and switches to the sdd-owned clone only after a capture into that dependency has created one. A machine that only reads a connected graph keeps two copies once it writes there, and reads before the first write come from the cache.

Expected: every read of a connected graph repository goes through its sdd-owned clone, so one machine holds one checkout per graph repository and the cache clone is no longer needed for graph repositories.
