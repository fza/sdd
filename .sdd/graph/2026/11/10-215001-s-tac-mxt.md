A command run in a `project_dir` work repository now lays the work repository's `.sdd/config.local.yaml` over the project's own, closing 20261110-213711-d-tac-rgd, in commit `529f4986`, merged into `fza-fork` in `bace6f29`.

`ReadConfigLayers` merges the project's own local file under the work repository's, which may now set any machine-local key: the check limiting it to `project_dir` and `hooks` is gone. For a pointed project, `LocalConfigPath` makes `sdd config set --local` write the work repository's file, `sdd config` names its values `work local`, and a `--local-config` file stands in for both local files. The graph-repository guide (`website/src/content/docs/guides/graph-repository.md`) documents the layer order. The committed work config keeps its pointer-key check, and the contribution guard still judges the project checkout's branch; neither changed.

Tests: `internal/meta/work_local_test.go` (`TestReadConfigLayersLaysTheWorkLocalOverTheProjectLocal`, `TestProjectLocalConfigPathIsTheWorkLocalOfAPointedProject`, `TestResolveConfigRefusesAWorkLocalLoweringVerify`) and `internal/cliapp/work_local_test.go` (`TestWorkLocalLiesOverTheProjectLocal`, `TestPointedServeFollowsTheProjectLocal`).

Compatibility: sdd builds before this change, fork `fza.44` and older, refuse a work repository local file holding any other key, with an error that the file "may set only project_dir, hooks".
