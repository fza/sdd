Entry ID and WIP marker timestamps are now parsed in local time, which fixes the UTC misread in 20261101-001925-s-tac-4id. Commit 5f31e8ed on branch `pr/fix-entry-writes` makes `ParseID` and `ParseWIPMarker` read the stamp with `time.ParseInLocation` in `time.Local`; formatting stays local, so IDs already on disk keep their meaning. Those are the only two places that parse the stamp.

This is the gap's candidate remedy, applied unchanged.

A new test generates an ID and a marker name at a fixed instant under a UTC+1 local zone and checks that both parse back to that instant. Reverting either parse site to `time.Parse` turns its subtest red. The branch is merged into `fza-fork` (merge dd96bb0a, not pushed).
