A pre-flight model call that runs past `llm.timeout` during a capture puts a retry or a skip to the user beside revise and abort: the retry sends the same request again and is billed again, and the skip follows `verify.skip` as for a pre-flight answer cut at the token cap (20261112-200239-d-tac-lh0).

Today the timeout fails the capture's pre-flight step as a plain operation failure, served with the failure text of 20260919-141340-d-tac-qws and only its retry and cancel references. `verify.skip` never applies, so a model that is slow on every call leaves the user two choices: pay for the same call again, or drop the capture. Unlike a cut answer, a timeout can be transient, such as provider load, so a retry may succeed where a cut answer's retry would run away again.

What the timeout does:

- The error carries its own code, assigned where the deadline is known, so the capture tells it apart from other failures.
- The capture goes to the user step a cut answer takes (20261112-203435-s-tac-air), `preflightUnjudged` in the capture procedure (20260703-094500-d-prc-cap), which today offers revise, skip and abort and speaks of the cut alone. For a timeout it also offers a retry and names the timeout, as the procedure's `deepFailed` step already offers a retry beside skip and abort. Under `verify.skip: failure` or `weighed` the user may skip, and the entry is written with `verification: skipped` and low confidence, as after a cut answer. Under `never` the skip is held, and retry, revise or abort remain.
- The served text names the cause and the setting to raise: `sdd config set llm.timeout <duration>`.

The gollm adapter replaces a deadline error with a plain "timed out" message that drops the cause, so the timeout wrapper never names `llm.timeout` for the `anthropic`, `openai` and `ollama` providers, which all run through it, though 20261029-210859-s-tac-x9d reports every provider naming it; its tests cover only `claude-cli`. Keeping the cause is part of this work: the error code above depends on it.

Rejected:

- Taking the cut path unchanged, without a retry: one path for both, but a one-off slow call then ends in a skip or a hold where a retry would have worked.
- Fixing only the message: a model that is always slow still leaves the user only retry-and-pay or dropping the capture.
