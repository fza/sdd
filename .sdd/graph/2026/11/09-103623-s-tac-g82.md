A connected repository whose remote is a local path runs a full sync round of its sdd-owned clone on every write-access resolve, about six times within one capture confirm call. Each resolve goes through `connectedDependencies.resolveWritable` to `EnsureReposFresh`, and the git gate admits a local target every time, so no cooldown holds it back. The flaky-test investigation (20261109-055405-s-tac-6xd) measured about 420 git subprocesses for one confirm call and about 2.5 s extra unloaded; it was measured in the test fixture, not on a real project.

Expected, from the per-machine git gate (20261107-095427-d-tac-yux): a repository's fetch runs at most once per cooldown, and a refresh never blocks the operation that started it. A local-path remote needs no network limit, but one call has no reason to sync the same clone more than once.

Candidate, unsettled: a per-call refresh scope shared across the resolves of one application call, or a cooldown for local targets too.
