`sdd config set` now refuses a value a setting does not allow: commit `898e3bfb` on branch `pr/feat-config-set-values`, merged into `fza-fork` as `a5f97768`. It closes the value-set directive (20261110-015917-d-tac-yc6) and the gap where `sdd config set` wrote `verify.mode bogus` and similar values (20261110-015054-s-tac-k8y).

Criteria:
- Values outside a declared set are refused, naming the allowed values, and nothing is written. On the `fza-fork` build `verify.mode`, `verify.runner`, `verify.skip`, `dialogue.mode` and `llm.structured_output` set to `bogus` each exit 1 with a message such as `verify.mode "bogus" is not off, grounding, prose or deep`, and the local file stays without them. Tests cover the fixed-value keys, among them `verify.claude.effort`, `embedding.provider`, `llm_prefilter.protocol` and `skill_scope`.
- A machine-local `verify.mode` below what the shared files resolve to is refused on write with the message loading gives; the check runs on the files as they would be after the write and judges only the key being set.
- An empty value is refused for every key: `participant` set empty now exits 1 naming `sdd config unset`.
- A guard test walks `BaseConfig`, `PerRepoConfig` and `repos.GlobalConfig` and fails on a named string type that declares neither its allowed values nor free text; it failed with the `Scope` declaration removed and with the `RepoID` free-text marker renamed.
- A file holding an unknown key still takes a valid write to another key.

Deviations: `llm.provider` stays a plain string, since its set includes the providers the gollm library brings; `hooks[].event` and `supported_agents` sit in lists `sdd config set` cannot write. `language` counts as free text, so `xx-bogus` is still written. `RepoID` gained a `FreeText()` method on the public `pkg/application/types` surface, and `verify.claude` became its own `ClaudeAgent` type so its effort levels can be declared apart from codex's.
