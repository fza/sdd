The engine refuses a user chooser answer whose `userWords` repeat the user's words from the latest answer at the same chooser when that answer took another choice. In Codex capture eval runs on `fza-fork` (two batches of three runs, builds `369cb6fe` with fixes and `719cfd12`), an agent reused the user's adjust message ("say an explicit error ...") as the confirm of the revised draft, in the same turn it first showed that draft. The same words for the same choice still stand, as when a user says "Yes, write it." at each playback. The check covers one pattern of agents answering user choosers (20260924-232456-s-tac-f09); that gap stays open.

`Instance.lastWords` holds the latest words per chooser; the engine records them on each answer and replays them from the session log, so the refusal holds across a resume. Commit `af168037` on branch `pr/fix-eval-defects-2`, merged into `fza-fork` at `1b04d01e`, with tests in `internal/engine/repeated_words_test.go`. The tests failed before the change and pass after; breaking the guard made them fail, and the file was restored. One existing proctest gave every playback answer the same canned user message; commit `29afbc08` gives each answer its own words.

Open: no real-agent run has shown it yet. The eval login hit its usage limit until 2026-12-09, so no Codex rerun was possible.
