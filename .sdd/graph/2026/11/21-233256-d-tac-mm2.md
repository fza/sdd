On each step of a dialogue sdd sends a framing block only when it is new or changed, a short landing when a move ends, a running move's small collected values whole and its large ones by name on `resume_session`, and a checker finding in full once, and after an adjust at playback the agent shows the person the change.

None of the five rules below asks the agent for a proof. The anchor proofs of 20261112-075604-d-tac-t4r, built in 20261112-195218-s-tac-day, cover the text this plan leaves out, and 20261121-230157-d-tac-ym8 replaces them with a required question about a served text.

## Measured basis

A recorded dialogue on another project's graph holds 140 sdd calls and 1,157,000 characters of sdd results. At about 2.5 characters per token that is 450,000 to 470,000 tokens, 48% of the agent's context when its host compacted it.

- Framing blocks: 149,600 characters, 13%.
- Text at a move's end: 51,000 characters, 4%.

A replay applied the framing rule and the landing rule to that dialogue as accounting, with the agent's calls unchanged. It removed 122,500 characters of framing, 82%, and 32,600 characters of move-end text, 64%.

Repeated checker findings and repeated playbacks are not measured in that dialogue. A report on a second dialogue on that graph estimates them at about 35,000 and 20,000 tokens of the main agent's context. The code confirms each repeat, as the sections below state.

The branch `next/cut-serve-repeats` (commits `c2be41d8`, `eb467e41`) holds an earlier build of the framing rule, the landing rule and a `collected` field that lists names only, beside cuts to the unproved list and the report schema. It was merged into `fza-next` and `d8b6bdb3` took it off again before the fork release 20261120-194054-s-prc-3oo. That build keeps its record of sent framing per session, so a second agent on the same session gets no framing from it.

Applied to the recorded dialogue as accounting, that build removes 295,300 characters, 25.5%. About half was expected, since repeats are 572,000 characters, 49% of the dialogue. The other 286,000 characters of repeats are step text and report schema blocks sent again unchanged, 133,500 and 152,500 characters. Each shrinks to a pointer only on a proof, and agents do not send the proofs. The recorded agent sent a median of 3 tags per call while it held about 35 it could prove, and its proofs avoided 28% of the text a proof can avoid. 20261112-195218-s-tac-day names the repeat cost for agents that send no proofs as open, and 20261114-185019-s-tac-8aa records that Codex and Sonnet main agents mostly skip them. The check for a text the agent's host has lost, which the proof is today, is the subject of 20261121-230157-d-tac-ym8. That plan serves repeated step text and report schema short after a right answer to its question. This plan changes neither.

## Framing blocks

sdd sends a framing block the first time and again only when its content changes. A caller sdd has not served yet, such as a subagent that starts on a running session, gets every block in full. `resume_session` sends every block in full.

Today a subagent on its parent's session gets the full text because it sends no proof. Without the proof sdd needs a mark that tells a second caller on a session from the first. The earlier build had none, and 20260828-171826-s-cpt-ox6 records that sdd cannot tell two callers on one session handle apart. The mark is part of this work, and its form is open.

Point 37 of 20261119-013237-d-cpt-fu4 keeps the proofs optional so that an agent that sends none gets everything in full. The framing rule and the landing rule depart from that point for the framing blocks and the base step. As for 20261121-230157-d-tac-ym8, an entry revising point 37 is owed.

The framing blocks are the session info, the lanes the session shell declares (20260704-100000-d-prc-dlg), and the parked and graph health blocks. The shell's lanes are working principles, aspirations, guiding directives, focus, participants and recent graph movement. Today a step carries every block unless it declares a shorter list, and a move end, a park and an abandon carry all of them. A block shrinks to a pointer only while the call proves its tag (`composeFraming` in `pkg/mcpapp/pieces.go`).

Accepted cost: when the host compacts the agent's context and the agent does not call `resume_session`, the agent works without the framing until a block changes.

Rejected:

- A block shortened only on a proof, as today. Agents do not send the proofs, and the 13% stays.
- Every block on every step in a shorter wording. The text is rewritten and still repeats.

## Landing at a move's end

When a move ends, the session returns to its base step with a short landing: the move's outcome and the choices for what comes next. The landing names the base step and does not send its text again. `resume_session` sends the base step in full.

20260704-000621-d-tac-bfc nested the base step's current serve in every move-end result, so that each result says where the dialogue stands and the agent need not remember it. It counted on the served-once memory to keep the base step's long text cheap. That memory now shortens a text only on a proof. The landing keeps what that directive wanted on every result, where the dialogue stands and what can come next, and leaves out the long text. That directive rejected a landing that glues open threads and a goal line onto a move's end, because it relies on the agent remembering the base step's text. This landing takes that reliance on, as the accepted cost below states, because the served-once memory that directive counted on now needs a proof. Today `ServeShell` in `pkg/application/workflow.go` serves the shell after a move ends, and `toBaseServeResult` in `pkg/mcpapp/tools.go` puts the base step's instruction lanes and every framing block into the result's `base_junction`. In the recorded dialogue that is about 7,500 characters per completed move unless the agent proves the tags.

Accepted cost: when the host compacts the agent's context and the agent does not call `resume_session`, the agent picks its next move from the listed choices alone.

Rejected:

- The full base step again after a long move. sdd would guess what the host still holds.
- The full base step at every move end, as today.

## Resume

`resume_session` sends the step text of every running move and the framing in full. It is the way back for an agent whose host dropped what the framing rule and the landing rule no longer repeat (20260709-163921-s-tac-68a). A collected value of a running move comes whole when it is up to a few hundred characters long, such as a capture's kind, layer and topics, and a short list of references. A larger value, such as the draft body, the search notes or the findings, comes by name with its size. Its text comes in full, never cut off, when the agent asks for it.

Today `resumeServe` in `pkg/application/workflow.go` adds every collected value of every running move to the resume (20260719-190406-s-tac-y9a). `capValues` in `pkg/mcpapp/tools.go` cuts each value at 2,000 bytes and replaces the values past 8,000 bytes per move with an omission notice. A capture past its deep verifier steps holds the findings and verdicts as collected values, so a resume sends them cut. 20260719-124405-d-cpt-0tm asks that a move's durable state reaches a resuming agent, or that sdd names what it left out. This plan meets the first for a small value, which the resume carries whole. It takes the second for a large value, which the resume names with its size and the agent fetches. Against the resume that 20260719-190406-s-tac-y9a built under that directive, a large value loses the cut text it has in the resume today and gains its full text on request. The failure behind that directive, recorded in 20260719-123138-s-tac-76e, was a handoff whose result carried none of the collected values, so the new agent derived them again. Small values that carry a move's intent, such as its anchor, stay in the resume whole, so a resuming agent that fetches nothing still holds them.

Accepted cost: the rule needs a size limit, and the build has to choose it. A large value's text costs one more call, and a resuming agent that does not fetch it works without it.

Rejected:

- Names only for every collected value. Every value the agent needs costs one more call, and an agent that skips the call works without the value.
- Values in full for the continued move only. A large value is still cut.
- Every value of every running move cut at a size cap, as today.

## Checker findings

sdd sends a finding of the deep verifier in full once. Once the finding is settled, sdd sends it as one line: its label, its severity and axis, whether it was applied or withdrawn, and the note. The proposal shows only the changed span with a few words around it. Playback and the summary check show the settled findings once, not on every round.

Today the capture procedure (20260703-094500-d-prc-cap) sends a finding in full up to four times, and again on every further playback round:

- `deepAnswer` lists each finding with its verdict, basis, every pointer quote and every source quote (`readDeepFindings` in `pkg/application/workflow_deep.go`).
- `deepProposal` labels a hunk with its finding only, but `BuildDeepProposal` in `internal/model/verifier_deep.go` gives each hunk the whole old line and the whole new line. A body paragraph is one line, so the paragraph goes out twice. The open points, which `buildDeepProposal` in `pkg/application/workflow_deep.go` writes, repeat the verdict in full, and `deepUser` serves them again.
- `playback` injects the findings accepted without an edit and the withdrawn ones with the verdict in full. 20261113-205441-s-tac-e87 added the one replayed playback that shows them, and 20261113-222213-s-tac-qvt the instruction to show each in full, never a paraphrase. Only `prepareDeep` clears the two lists, and the inject does not ask whether the replay has run. Every later playback round, each adjust included, carries them again.
- `verifySummary` injects both lists again.

Accepted cost: a person who wants a finding's full text again asks the agent.

Rejected:

- One line for a settled finding with the proposal as it is. The doubled paragraphs stay.
- Findings in full at each step, as today.

## Playback after an adjust

After an adjust at playback the agent shows the person what changed.

- Guided mode: the change with a line of context. The full draft comes on request, and once before the final confirm when anything changed since the person last saw the draft in full.
- Assisted mode (20261117-213336-s-tac-hlw), and auto mode where the agent shows anything: the change only. The full draft comes only on request.

sdd already serves a diff after an adjust (20260826-230218-s-tac-7yr, `renderDraft` in `internal/engine/draftserve.go`), and that diff stays as it is. The `playback` text of the capture procedure asks for the full draft in both branches. The guided branch already shows the served delta after an adjust and offers the complete entry on request, but it says to show the full description verbatim again before asking whenever the body changed since the user last saw it in full, so every round that changes the body shows it whole. It also says to mark inferred sentences in every revised draft. The assisted branch says to present the description verbatim and to wait for the person's answer to the draft shown in full, with no rule for a change.

Consequence: in assisted mode an approval after an adjust rests on the person's first full view and the changes shown since.

Rejected: the full draft after every change, as today.

## Not measured

- No agent has run under these rules. The replay changes the accounting of a recorded dialogue, not the agent's behaviour.
- The recorded dialogue holds no resume. The size of a resume's collected values is read from the code.
- Whether the agent still held a text after its host compacted the context. The replay counts such a text as sent once.

## Not decided here

- Which call returns a collected value. The call itself is part of this work.
- The size limit up to which a collected value comes whole, within a few hundred characters.
- Whether a parked move's result, which carries the base step the same way, gets the landing too.

## Layers

No new command or query is needed, since no graph write or read changes:

- **Model** (`internal/model`), pure: a proposal hunk cut to the changed span with a few words around it (`BuildDeepProposal`), and a settled finding rendered as one line.
- **Engine** (`internal/engine`): the record of framing blocks sent per caller, with the mark that tells a second caller on a session from the first.
- **Application** (`pkg/application`): the landing after a move ends (`ServeShell`), the resume carrying small collected values whole and listing large ones by name with their size (`resumeServe`), the call that returns one collected value whole, and the settled-finding lists of `workflow_deep.go`.
- **MCP shell** (`pkg/mcpapp`): framing composed without a proof (`composeFraming`), the landing in place of the full base step in `base_junction` (`toBaseServeResult`), and whole small values with a name and size for each large one in place of the cuts of `capValues`.
- **Procedures**: the capture spec's playback text for each mode, and the injects of the settled findings at `deepAnswer`, `deepProposal`, `playback` and `verifySummary`.

## Acceptance criteria

Tests over served results check each criterion: `internal/proctest` for the capture procedure's steps, `pkg/mcpapp` for framing, landing and resume. A second caller on a running session checks the criterion on a caller sdd has not served.

- [ ] A result carries a framing block only when sdd has not sent that block to the caller or the block's content changed since.
- [ ] A caller sdd has not served yet receives every framing block in full.
- [ ] No framing block needs a proof to stay out of a result.
- [ ] The result that ends a move carries the move's outcome and the choices for what comes next, names the base step and does not carry the base step's text.
- [ ] `resume_session` carries every framing block and the step text of every running move in full.
- [ ] `resume_session` carries a collected value of a running move whole when the value is within the size limit.
- [ ] `resume_session` lists a collected value past the size limit by name with its size and carries none of its text.
- [ ] A collected value the agent asks for arrives whole, not cut at a size cap.
- [ ] sdd sends a deep verifier finding in full once.
- [ ] A settled finding goes out as one line with its label, severity, axis, outcome and note.
- [ ] A hunk of the proposal carries the changed span with a few words around it, not the whole line before and after.
- [ ] Playback carries the settled findings on one round only, and the summary check carries them once.
- [ ] After an adjust in guided mode the playback text tells the agent to show the change with a line of context, the full draft on request, and the full draft once before the final confirm when anything changed since the person last saw it in full.
- [ ] After an adjust in assisted mode the playback text tells the agent to show the change only and the full draft on request. In auto mode the same holds wherever the agent shows the draft.
