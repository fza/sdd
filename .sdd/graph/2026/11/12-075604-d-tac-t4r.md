sdd serves each agent context every piece of text once and replaces a repeat with a pointer whose anchor proof shows the agent still holds the text, on every host and without hooks, and the deep verifier works a changed draft from the reading it already holds. About half of all MCP result bytes repeat a part the same agent context already received, because `sessions.token_saving: off` (20261101-164201-d-tac-sj4) switched sdd's served-once memory (20260705-010751-d-tac-dbk, made per lane by 20260826-120330-d-tac-8f8) off for an external hook that no longer runs. That memory is kept per sdd session and cannot see a compaction, so switching it back on unchanged would point at text the agent lost. Measurements, host facts and every alternative weighed are in the [design record](./12-075604-d-tac-t4r/serve-token-cost-record.md).

**Anchor proof.** Every piece served in full carries a short tag at a random point, placed before a content word. A later call lists, for each piece it still holds, the tag and the word right after it. sdd sends a pointer only for a listed piece whose word matches; a missing or wrong proof gets the full text, so a mistake costs tokens, never quality. A summary keeps no such word, so after a compaction the proofs fail and the text serves in full; a fresh subagent holds no tags and gets full text. An agent that cannot see a piece's text says so in a field of its own instead of guessing a word, and gets the piece again in full. The proof asks nothing of the host, so it works the same in Claude Code, Codex and Chat, and sdd installs no hooks, runs no settings checks and asks the user nothing; Codex is not yet in the spike below. In a spike with lossy compaction, no proof passed for text the agent had not re-read on Claude Code and simulated Chat, at 0.75x the output tokens of a pointer without proof. A pointer without proof let the Chat agent judge 43 of 50 entries from its summary. The `sessions.token_saving` key and the object result forms that existed only for its `off` value (20261101-165616-d-tac-qtk, joined by `view` under 20261101-194502-d-tac-r3f) go. An entry served in full keeps the pointer the grounding design settled (D34 of 20261109-004506-d-cpt-udz): id, brief and the way back. D34 rejected a check word the agent quotes, at 6 to 16 times the output tokens, and accepted that an agent judging from memory after losing the text goes uncaught, because no lossy compaction had been tried; the spike above produced that loss, so this plan reverses D34's "no check word" and serves the pointer only on its anchor proof, and an entry the session read in full counts as served (20260827-224141-s-tac-6uf). Gather brief lines stay in full.

**Trims at the source.** These shrink first serves and every serve on a host that serves in full: a reading page holds at most 40,000 characters of the whole result, in place of the deep verifier design's 50,000 characters of page text alone, since Claude Code saves results over 50,000 characters to a file; the pre-flight rules page, today one page of about 120 KB that bypasses the page bound and is cut at serve so the verifier loses most of it, is paged like the rest and drops its copy of the draft and referenced entries and the sections whose guard the draft fails; steps that only await carry no report schema; revise schemas leave out fields a dispatch receives or one option collects, and `procedureSpec` unless the draft is a procedure; the verifier's fixed rules serve as their own lane; the sync notice serves once per change; the report schema's invariant properties block becomes its own piece, apart from the per-step required list that kept every gate step's schema from collapsing (20260827-224111-s-tac-vz9). Four cuts that change what an agent reads land only once evals show unchanged quality: field descriptions the lanes already carry, only the failing fields' schema on a repeated step, framing declared per step, and a cap on recent graph movement.

**The verifier on a changed draft.** A deep exchange today replaces the waiting verifier and forks a fresh one that reads every page again, 180 to 360 KB, even for a one-line change. This contradicts the child session lasting across rounds that the deep verifier design (20261109-004729-d-cpt-xs5) states. The capture instead sends the live verifier a revision with the changed passages and any entries read since. The verify procedure (20261109-010000-d-prc-vfy) waits for answers or a revision and judges the revision's passages. The harness continues the same subagent. A fresh verifier stays the fallback when the child ended, it took three revisions (counted apart from the three deliveries in which the verifier answers the drafter's contested findings), or the harness cannot continue it. Accepting the verifier's proposal without draft fields makes sdd write the proposal into the draft itself (capture procedure 20260703-094500-d-prc-cap); the proposal serves its diff only.

Results stay JSON with the structured copy (20260831-193805-d-tac-ngj): plain text saved 0.6% of input tokens. Not covered: a Claude or Codex plugin for sdd, and prose checks a project runs in its own agent hooks.

## Layers

The work splits across the layers the CQRS contract (20260413-142536-d-cpt-ah1) names; no new command or query is needed, since no graph write or read changes:

- **Model** (`internal/model`), pure: placing a tag before a content word from a supplied random source, reading the word after a tag, matching a proof, splitting a reading into pages bounded by the whole result, and paging the rules page like any other reading.
- **Engine** (`internal/engine`): the served memory keyed by piece, recording each issued tag and word as session events so a restarted server keeps them; checking the proofs a call carries before choosing full text or pointer; counting an entry read in full as served.
- **Application** (`pkg/application`): the deep exchange sending a revision to the live verifier and falling back to a fresh one; accepting a proposal by writing it into the capture's store; the rules page built from the paged reading.
- **MCP shell** (`pkg/mcpapp`): the tool input carrying held proofs and the re-read field, the tag rendered into served text, the pointer text; the object result forms and their result fields removed. The full-or-pointer choice the shell makes today (`servedBefore` in `pkg/mcpapp/session.go`) moves to the engine, so the shell formats only and decides nothing.
- **Config** (`internal/model` config, `internal/cliapp` serve): the `sessions.token_saving` key and its resolution removed; a config naming it reads as an ignored setting.
- **Procedures**: the verify spec's answer step awaits answers or a revision; the capture spec's deep steps send revisions and apply an accepted proposal.

The rules page cut is a bug, so its fix lands with a regression test that fails before it (20260416-141340-d-prc-8vh).

## Acceptance criteria

- [ ] An agent context receives each served piece in full once; a later serve of the same piece is a pointer only when the call proves the piece with its tag and the word after it.
- [ ] A missing, wrong or unissued proof gets the piece in full.
- [ ] After a compaction on Claude Code, Codex and Chat, no proof passes for text the agent has not re-read, in a spike of at least 5 runs per host.
- [ ] A subagent sharing a session handle gets full text for every piece it holds no proof for.
- [ ] `sessions.token_saving` and its object result forms are gone; a config naming the key reads as an ignored setting.
- [ ] No sdd command installs a hook, and no serve asks the user anything about token saving.
- [ ] Exact repeats fall from about half of all sdd result bytes to under 15% on a capture with a deep verifier.
- [ ] No sdd MCP result exceeds 50,000 characters.
- [ ] The pre-flight rules page carries neither the draft nor its referenced entries, nor sections whose guard the draft fails, and reaches the verifier whole across pages, never cut; a regression test covers today's cut.
- [ ] Await-only steps serve no report schema; revise schemas carry no dispatch-received or single-option fields, and `procedureSpec` only for a procedure draft.
- [ ] The sync notice serves once per change of its text.
- [ ] A report schema whose properties block an agent context already holds re-serves only its per-step required list.
- [ ] An entry the session read in full is served as its pointer in later serves, subject to the same proof.
- [ ] The four quality-touching cuts land only with specimen and capture evals, 3 runs each, unchanged against the baseline.
- [ ] A change after a deep verdict reaches the live verifier as a revision with the changed passages, and the same subagent continues.
- [ ] A fresh verifier starts only when the child ended, three revisions were taken, or the harness cannot continue it.
- [ ] Accepting the verifier's proposal without draft fields writes the proposal into the draft, and the proposal serve carries its diff only.
- [ ] Verdicts, findings and the user's dialogue in a capture are unchanged against the current behaviour on the capture evals.
