The per-machine gate on the git operations sdd starts (20261107-095427-d-tac-yux) is built on `pr/feat-git-limits` and merged into `pr/core` and `fza-fork`, closing the decision, the connected-read gap (20261107-050758-s-tac-c2j) and the engine-refresh gap (20261027-145612-s-tac-2n5).

Delivered in these commits:

- `258d1b91`: package `internal/gitgate` with the JSON record, cooldowns, hourly buckets, concurrency slots, retries and the trace-based login detection.
- `d4f03fe9`: the global `sync:` limits with defaults, minimums and host entries; the retired project keys stay silent; `sdd init` asks nothing about sync.
- `73e62418`: every git network command refuses to run outside the gate; automatic sync runs only in sdd-owned clones; `sdd serve` checks the gate every minute.
- `c17b8976`: the pull rules of automatic sync inside a code repository are removed.
- `b55e78ba`: each connected repository is read and written through one sdd-owned clone, and its old cache clone is removed on first use.
- `9f8fb4d9`: the serve timer syncs due connected repositories, and the MCP tool `sync_repos` reports an outcome per repository.
- `1197628c`: a bare `sdd sync` in a code repository fetches and prints the status.
- `98845cbb`: two handlers sharing one record fetch once within the cooldown.
- `7a5e9d48` and `79cea25d` on `fza-fork`: the merge, and cache pruning of sdd-owned clones, which removes a clone only when no connected repository names it, it holds no unpushed commits, its sync lock is free and the record shows no git operation for it within `cache.retention`.

Every acceptance criterion has a test in the commits above, and the full suite passes on `pr/core` at `98845cbb` and on `fza-fork` at `79cea25d`. On this machine `sdd repo sync` cloned every connected repository into its sdd-owned clone and removed the cache clones, and a second run within the cooldown skipped each repository with its next allowed time.

Deviations from the decision: `retries: 0` is accepted and means no retries; `sync_repos` without repositories syncs every connected one and needs write access; `sdd repo sync` exits non-zero when a repository failed or was refused; the failure notice of a connected repository lives in the serving process until a round succeeds; a withdrawn `inbound.accept` reaches a writer only once its fetch cooldown allows; the title backfill waits a fixed 15 minutes between runs; cache pruning of the sdd-owned clones exists on `fza-fork` only, because cache pruning is not on `pr/core`.
