A pre-flight model call that runs past `llm.timeout` during a capture now puts retry, revise, skip and abort to the user instead of failing the step, as directive 20261112-230842-d-tac-o8j commits: two commits on `pr/fix-preflight-timeout`, merged into `fza-fork` at a6135331.

- a7c7fc06: the gollm adapter keeps the deadline cause, so a timed-out `anthropic`, `openai` or `ollama` call names `sdd config set llm.timeout <duration>` (`TestGollmTimeoutNamesTheSetting`).
- 1d1b1a05: pre-flight returns a call past its bound with code `timed_out` and the mechanical findings; a deadline the caller set itself stays uncoded. The capture goes to a new user step, `preflightTimedOut`, offering retry, revise, skip and abort; its text names the timeout and the setting, and says a retry is billed again. Skip follows `verify.skip` as for a cut answer: `never` holds it, and an open high finding refuses it. The configuration reference and the working-modes page say `verify.skip` covers a timeout.

Deviation: the directive put the timeout on `preflightUnjudged`, the cut answer's step, with a retry added. A step's options are fixed in the procedure spec, so one step cannot offer a retry for a timeout and none for a cut; the timeout got the sibling step `preflightTimedOut` with the same skip and findings plus a retry, and `preflightUnjudged` is unchanged. A condition on single options was not built: it extends the procedure spec format and its documentation.

Each new test failed before its fix, and ten new guards were broken, caught by their own tests and restored.

Open: no test covers a timeout in the fallback pre-flight after a skipped deep exchange, which runs through the same step. With the real provider stack the `llm.timeout` hint shows twice, in the quoted error and in the step text.
