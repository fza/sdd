sdd checks whether an agent still holds a text it was served by asking one question about that text, which the next call that advances the session must answer, in place of the optional anchor proofs. A right answer lets sdd serve repeated text short. A wrong answer or `lost` makes sdd send the text again in full.

## Problem

sdd serves a piece of text in full once and repeats it as a short pointer only when the call proves that the agent still holds the text, so that no pointer names text a compaction removed. The proof is the anchor proof of 20261112-075604-d-tac-t4r, built in 20261112-195218-s-tac-day. Each piece carries a tag, and a later call lists the tag and the word after it in the optional `held` argument. 20261117-093307-d-tac-5mq removed the hold-next line, made the rule that an agent proves every tag it still sees the only proof rule again, and restored the list of unproved pieces on every result.

The anchor proof detects a compaction when an agent sends it. After a compaction no proof passed for text the agent had not read again, on Claude Code and simulated Chat in the spike behind the plan and on Codex in 20261112-212344-s-tac-mm8. The proof fails on uptake, because the argument is optional.

- In three Codex captures a call proved 7 to 11 percent of the tags served in earlier results (20261113-121039-d-tac-ca2, the directive that introduced the list of unproved pieces as a reminder).
- Main agents on Codex and on Sonnet skipped most proofs under the every-tag rule and under the hold-next line that named the tags to send (20261114-185019-s-tac-8aa).
- In a recorded dialogue of 140 calls the agent sent a median of 3 proofs per call while it held about 35 provable tags. Proofs avoided 28 percent of the text that could have been served short. Of 572,000 repeated characters, 286,000 stayed behind proofs the agent did not send. The list of unproved pieces took 12 percent of all result characters. The record of that dialogue belongs to another project and is not attached.
- In the build's own capture run an agent that sent no proofs got 37.7 percent of its result bytes as repeats, against 8.8 percent for one that proved every piece.

## Decision

**The question.** Every response that starts, resumes or advances a session ends with one question about a text the agent should still hold when it makes its next call. That is a text an earlier response served, or for the first response of a session its own text. The question is as terse as it can be written, because every response carries it. The measured form is one line of 35 to 90 characters, such as `q s7: 2 words after "the draft must"? | lost`.

**The answer.** The next call that advances the session must answer in a required argument, with the words the question asks for or with `lost`. A call without the answer is refused with a message that names what is missing. After a right answer sdd serves short what the agent already holds: repeated step text, report schemas and the type-system overview. After a wrong answer or `lost` sdd sends the text again in full.

**Per call.** sdd decides full or short from the answer of the call in flight and keeps no verdict for the session. A fresh subagent that works on the same session handle holds none of the texts, answers `lost` and gets everything in full. The main agent's next right answer still gets the short forms.

**Made at call time.** sdd makes the question when it renders the response, from the text it stored at serving. No served text carries a tag or any other mark placed in advance. No question is asked twice, because an agent's earlier answer stays in its call history after the text is gone.

**Seven kinds, one drawn at random per question.** A phrase is a short run of words that occurs once in the text asked about.

1. The first words of the sentence that holds a phrase.
2. The last words of that sentence.
3. The word between two phrases.
4. The first words of the sentence that follows.
5. The number after a phrase.
6. The words after a phrase.
7. The words before a phrase.

**What goes.** The anchor proofs go: the tags in served text, the `held` argument and the proof guide. The list of unproved pieces (`unproved`) and the notice of failed proofs (`proof_notice`) go with them. The hold-next line does not return. This replaces 20261117-093307-d-tac-5mq, whose proof rule and list of unproved pieces rest on an argument agents leave out. Of the closed plan 20261112-075604-d-tac-t4r it replaces the anchor proof only. That plan's trims at the source and its handling of the verifier on a changed draft stay.

The plan addresses the open gap 20261114-185019-s-tac-8aa. An agent cannot leave out a required argument, so the short forms no longer depend on an agent choosing to send proofs. The gap stays open, since no sdd build has shown this yet for the Codex and Sonnet main agents it names.

**Difference from stock.** A call of stock sdd carries no answer, so a call in stock's shape that advances a session is refused. This departs from point 37 of 20261119-013237-d-cpt-fu4. That point keeps the markers in served text and the optional arguments `held` and `reread`, so that an agent that sends none gets everything in full as in stock, and the directive proposes both upstream. This plan does not revise the directive. An entry of its own that revises point 37 and its upstream proposal is owed.

**Left to a later decision.** Two rules hold until a decision of their own settles them.

- Which question an answer is checked against. Until then sdd checks an answer against each question of the session still unanswered, not only the one asked last, so a call of another agent in between does not turn a right answer wrong.
- How an entry read in full through `gather`, `show` or `search` is served again, and what becomes of the `reread` argument. Both rest on the anchor proof today. Until then an entry read in full serves in full again on a later read, never as a pointer without a check.

## Measured basis

Two measurements ran headless Claude Code against a probe MCP server, with 24 steps per run, about 2,000 characters of invented step text per response and a required argument on every call. The [measurement record](./21-230157-d-tac-ym8/text-question-measurement.md) holds the method, every run and the limits. Opus and Sonnet played the main agent in the runs the decision rests on.

**A code handed out beside the text.** Each response carried three numbered 6-character codes and named one earlier number whose code the next call had to give. Opus and Sonnet gave 144 of 144 codes right, so agents answer a required value on every call. After a `/compact`, in one run per model, both still gave all 6 codes from before the compaction. The summaries had kept the codes while the step texts were gone. A right code therefore does not show that the text is still in context, and the check missed the lost text.

**A question bound to the text.** Each response ended with one question about an earlier step's text, of ten kinds drawn at random. They were the seven above and three that count: the first words of paragraph K, the last words of paragraph K, and word N of a sentence.

- With the text in view Opus and Sonnet answered 137 of 144 right, 3 wrong and 4 `lost`. At 6,000 characters per step they answered 48 of 48 right.
- After a `/compact`, in two runs per model, Sonnet's summaries held none of the step texts. Sonnet answered `lost` to 10 of 12 questions about texts from before the compaction and answered all 12 about texts served after it right. The 2 right answers were the questions pending when the compaction ran. The summaries had already worked out their answers.
- Opus's summaries copied all 13 step texts word for word, 26,000 characters, so the texts were still in view and all 24 answers were right.
- No answer after a compaction was wrong or guessed.
- The seven kinds chosen had 97 of 99 right, 2 `lost` and none wrong. The three counting kinds had 40 of 45 right, 3 wrong and 2 `lost`. All 3 wrong answers were paragraph questions. One was off by a paragraph. Two were answered on the current step's text, since a paragraph number holds no phrase that ties the question to its step.
- The question cost Opus 5 and Sonnet 13 more output tokens per call than the code. Its cost against a call with no check is not measured.

**Aside.** Haiku also ran as the main agent. A main agent is a costly model by design, so these runs do not carry the decision. With the code, Haiku's summary kept 1 of 39 codes and Haiku answered `lost` for the other 5 asked. With the question, Haiku answered `lost` to all 12 questions about texts served after a compaction, although those texts were in view.

## Rejected

- **A code handed out beside the text.** Summaries carry the codes across a compaction, as measured above.
- **All ten kinds.** The three counting kinds produced 5 of the 7 answers of Opus and Sonnet that were not right with the text in view, and every such answer costs a full resend.
- **Keeping the optional proofs.** Agents leave an optional argument out, as the Problem section shows. A line of tags named by sdd did not help. Codex and Sonnet main agents skipped it as well, and it raised the proof characters an Opus agent sent by 5.8 percent before 20261117-093307-d-tac-5mq removed it.
- **A tolerant path, where a missing answer counts as `lost`.** Stock's call shape would keep working. An agent that skips the answer then gets everything in full and saves nothing, which is what agents did with the optional proofs.
- **The same tolerant path after one more test run.** The runs with optional proofs already show what agents do with an argument they may leave out.
- **Building without measuring.** Each unreliable answer would count as a compaction and resend text, so the answer rate had to be known before a build. The measurement also showed that the code design misses lost text, which a build without it would have shipped.

## Accepted costs

- sdd notices a compaction one call late at most. The question pending at the compaction can be answered from the summary.
- `lost` with the text in view costs a full resend. One Sonnet run answered `lost` 4 times in its first 6 steps with the text in view, and its output shows no reason.
- Every call carries the question line and the answer, 5 to 13 output tokens more than a code.
- Fork and stock differ in one more place, the shape of a call that advances a session. A call in stock's shape, without the answer, is refused.

## Limits

- No second agent host is measured. The Codex run failed on a usage limit before its first answer.
- Automatic compaction is not measured. Every compaction was a manual `/compact` on a conversation of about 15,000 tokens.
- Real step texts are not measured. The probe texts were invented sentences filled from word lists, more uniform than procedure text and free of repeated boilerplate.
- The agents had no file tools. An agent with file tools can read a lost text back from its transcript file.
- Each result rests on few runs: two per model after a compaction, one per model and text size without.
- A summary that copies the texts frees less context. Opus's compaction went from about 14,400 to 6,900 tokens with the question and to about 1,300 with the code.

## Layers

The split follows 20260413-142536-d-cpt-ah1. No graph write or read changes, so no command, query, handler or finder is added.

- **Model** (`internal/model`), pure: finding a phrase that occurs once in a text, building a question of one of the seven kinds and its answer from a supplied random source, matching a given answer. The tag placement and proof matching of `internal/model/anchor.go` go.
- **Engine** (`internal/engine`): the text of each served piece, the question a response asked and the questions already asked, recorded as session events so that a restarted server still checks the answer, and the choice between full text and short form from the call's answer. The served memory in `internal/engine/pieces.go` keeps a piece's hash, tag word and challenge answers today, not its text.
- **Application** (`pkg/application`): the call's answer passed to the engine and the question passed to the serve. The unproved list and the failed proofs leave the workflow serve.
- **MCP shell** (`pkg/mcpapp`): the required answer argument on the tools that advance a session, the refusal that names it when a call leaves it out, and the question line on every response that starts, resumes or advances one. The `held` argument, the `unproved` and `proof_notice` result fields and the proof guide are removed.
- **Docs**: the guide `website/src/content/docs/guides/working-with-coding-agents.md` describes the anchor proof and changes with it.

## Acceptance criteria

- [ ] Every response that starts, resumes or advances a session ends with exactly one question, of one of the seven kinds, about a text that an earlier response served or, for a session's first response, about its own text.
- [ ] A call that advances a session without the answer argument is refused with a message that names the missing argument, and `lost` is a valid answer.
- [ ] After a right answer the call gets repeated step text, report schemas and the type-system overview in their short form.
- [ ] After a wrong answer or `lost` the call gets them in full.
- [ ] A second agent on the same session handle that answers `lost` gets every text in full, and the first agent's next right answer still gets the short forms.
- [ ] No question is asked twice within one session.
- [ ] No served text carries a tag or other mark placed for the check.
- [ ] sdd asks no question that counts paragraphs or words.
- [ ] The `held` argument, the `unproved` and `proof_notice` result fields and the proof guide are gone.
