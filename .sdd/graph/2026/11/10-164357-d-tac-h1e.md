A capture whose verification resolves to `deep` skips the LLM pre-flight, the deep verifier's brief (20261109-010000-d-prc-vfy) carries pre-flight's rubrics instead, and a new `llm.debug: true` key writes a transcript of every LLM call, so a weak pre-flight model can no longer block a deep capture and the verdict of any check sdd itself sends to a model can be traced to the prompt that produced it (20261110-150803-s-tac-9u1).

**Deep without pre-flight.** In fork release `v0.18.0-alpha.3.fza.43` a deep capture runs the prose pre-flight before every deep round and again after every draft change (20261109-054916-s-cpt-mn7): one edit costs pre-flight, deep, pre-flight, deep. The deep verifier is a tool-using agent on its own model (default `sonnet`), commonly stronger than the pre-flight model, so the pre-flight call before it adds a weaker second opinion that can block the write with invented findings. Under `deep` the capture goes from drafting straight to the deep exchange; the mechanical write checks (refs resolve, body-edge IDs, schema) stay, and hooks on `capture.preflight` still run at that point with their findings channel, so a blocking hook keeps blocking. Every rubric pre-flight applies joins the deep verifier's brief: the per-kind checks (closing a done, a decision or a signal, decision refs, short loops, dissolution, aspiration, signal, supersedes, actor, role, annotation and focus captures) and the universal ones (unrelated refs, durability, attachment claims, unusual closes, ref-kind fit, settled-intent justification, language, contracts), so no check is lost. A `deep` capture whose deep exchange is skipped under `verify.skip` falls back to the pre-flight before its write, so `deep` never checks less than `prose`. A capture resolved to `prose` keeps the pre-flight as today.

**`llm.debug`.** Default `false`. When `true`, every LLM call sdd makes (pre-flight, its extraction call, writing guide, summarize, relevance) writes one transcript file under the project's `.sdd/tmp/llm-debug/`: the purpose, provider and model, the rendered system and user prompt, the raw response, duration and token counts. The key is machine-local: allowed in `config.local.yaml` and the user-global config, refused in the committed config, since transcripts hold graph content and belong to the one machine that asked for them.

The replay of the failing call stays with the gap and uses the transcripts this directive adds. The gap's stats-log item does not hold: after a switch to a graph repository the rows land in the `sdd`-owned clone's `.sdd/stats/llm.jsonl`, which `sdd stats` reads, and the failing call's row is there.

Rejected: running pre-flight once before the first deep round and never after edits (the weak model still runs once per capture and can still block with invented findings); keeping the loop as it is (every edit costs a pre-flight and a deep round, and the loop is the path that failed); a transcript switch in an environment variable (`llm.debug` sits beside the provider settings it explains and follows the config layering). Accepted costs: a longer deep brief; the per-kind rubric checks now depend on the deep runner's model; transcripts grow without bound while the switch is on.

## Acceptance criteria

- [ ] A capture resolved to `deep` makes no `preflight` or `preflight-extract` LLM call; one resolved to `prose` makes them as before.
- [ ] The deep verifier's brief carries every pre-flight rubric the draft's shape selects, the universal ones included.
- [ ] A `deep` capture whose deep exchange is skipped runs the LLM pre-flight before its write.
- [ ] With `llm.debug: true`, each LLM call writes one transcript holding purpose, model, both prompt parts and the raw response; with the key unset, none is written.
- [ ] `sdd config set` refuses `llm.debug` for the committed config, and a committed value turns no transcript on.
