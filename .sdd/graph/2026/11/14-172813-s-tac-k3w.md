Every verifier round sdd launches now runs in a detached `sdd delegate-round` process of its own, merged into fza-fork (8e7e2c0e). The round keeps running when the `sdd serve` that launched it exits, records its outcome in the verifier's child session, and the capture's next call through any server picks the findings up. A later round starts only once the round before it recorded its outcome. The round process enforces `verify.round_timeout` itself: it runs the round until its deadline (counted from its launch, or from the end of the round before it when that is later), then records the outcome, a timeout as the round's error, so a round stays bounded with no server alive.

The server records a launch (round, runner, launch time, timeout, log path) before starting the process, then the process's pid and start stamp once it runs. The wait step fails a round with no outcome to `deepFailed` when its process never started within a minute of the launch, when its process ended, or when it ran a minute past `verify.round_timeout`; each failure message names its cause (the round's process never started, ended without recording an outcome, or ran past `verify.round_timeout`) and the round's log file. Abandoning the capture, ending the verifier's session or a past-timeout lapse kills the round's process group. When the round's process is already gone, sdd kills the group only while the agent CLI the round recorded still runs in it with its recorded start stamp, so a reused group ID is never hit. Each round writes its output to a log file under sdd's state folder, per repository; the daily background run (`sdd cache prune`, which also sweeps the state folder) removes round logs older than `cache.retention`, and its table in the configuration reference lists them.

The configuration reference's `verify.runner` and `verify.round_timeout` rows describe the detached round, the ordering, every failure cause (never started, process ended, past timeout) with the log the message names, and the stop on abandon; the driver paragraph names the process-ended failure, and the `XDG_STATE_HOME` row names the round logs.

Tests cover each lapse, the restart of the launching server mid-round, round ordering, the group kill through a real subprocess, and every new guard was broken once to see its test fail. Not run: a real `claude` or `codex` round through `sdd serve`, and the Linux process probes beyond `go vet`.
