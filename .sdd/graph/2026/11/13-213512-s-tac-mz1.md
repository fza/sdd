The deep verifier can now raise an evidence finding that only the user can settle without citing a source: `DeepFinding.Validate` asks for sources on an evidence finding only when it is not marked `owner: true`. Commit 31a05ee7 on `pr/fix-owner-evidence-sources`, merged into `fza-fork` at c5114006.

The verify procedure (20261109-010000-d-prc-vfy) tells the verifier to mark as the user's a finding that turns on facts only the user knows, such as whether incidents were ever recorded. In two of three Codex capture runs on `fza-fork` at 719cfd12 the verifier did exactly that for the reason "Empty input hid upstream bugs twice", as an evidence finding with no sources, and sdd refused it with "an evidence finding names its sources". The verifier then delivered no findings, so the user never saw the question and the capture's handling of findings only the user can settle was never reached. A finding of that sort has nothing to cite: the missing evidence is what the user is asked for.

Felix Zandanel chose this over two alternatives. Telling the verifier to raise such findings on another axis keeps the rule strict, but labels the finding as something it is not, changes the verify procedure and the refusal text, and still refuses a verifier that misses the instruction. Leaving the rule keeps such findings from ever reaching the user. Accepted cost: an evidence finding marked as the user's may have nothing behind it, and the user settles it.

`TestOwnerEvidenceFindingNeedsNoSources` failed with the refusal before the change and passes after it; removing the exemption makes it fail again, and an evidence finding not marked as the user's is still refused without sources.

Open: no agent run has yet shown such a finding reaching the user. The Codex login used for evals hit its usage limit and resets on 2026-12-09.
