The hosted SDD project checked is backed by a git repository on a forge that also receives commits made outside the hosted server, so hosted SDD is not the only writer of its graph, contrary to the inference in 20261030-113340-s-tac-42t. Checked 2026-11-14, once the hosted connector answered: the newest entries one hosted project lists appear, with the same IDs and titles, as `sdd:` commits in that project's graph repository, and the same repository holds a hand-made config commit no sdd server writes, which Felix Zandanel confirmed making himself.

So the repository behind that hosted graph moves outside the hosted server too, and if the hosted server also writes back to it, which this check did not observe, the sync conflicts the question lists can reach a hosted graph as well. The entry commits do not show which side made them: the shared application runtime writes the same messages, `sdd: summarize <id> (manual)` included (`pkg/application/document_publication.go`). The hosted `info` names no storage, so how the server picks up commits made elsewhere, and whether it pushes its own writes, was not observed.
