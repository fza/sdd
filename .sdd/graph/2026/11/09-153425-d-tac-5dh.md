`sdd init` leaves alone every agent surface a project lists under `init.skip` in its committed `.sdd/config.yaml`, so a project that manages its own agent setup can run init for the rest.

The key takes a list of these values:

- `mcp`: the sdd server registration for every agent target, the `.mcp.json` entry for Claude Code and the `.codex/config.toml` block for Codex (20260706-180158-s-tac-vhh).
- `permissions`: the `mcp__sdd__*` allow rule in `.claude/settings.json`.
- `skills`: the skill renders at the configured scope, including the deletion of renders init no longer ships.

Init neither writes, refreshes nor deletes a skipped surface, and its commit carries none of its paths. Everything else init writes stays as it is. The install step `sdd move` runs for a `--project-dir` target (20261109-004100-d-tac-f8r) honors the key too. The ignore and attribute files already live under `.sdd/` and the graph folder since that move decision, so a commit hook admitting `sdd:` only under `.sdd/` accepts init's commit once the agent surfaces are skipped.

The key lives in the committed config only: which surfaces the project manages itself is a fact about the project, not about one person's machine. `sdd config set init.skip` refuses a value outside the three; a read ignores an unknown value and reports it, as every config read does (20260921-174543-d-cpt-tv9).

This answers 20261030-164247-s-tac-avs.

Rejected:

- An explicit empty `supported_agents` meaning no agent: all or nothing, so a project cannot keep the skills while managing its own registration, and telling a missing key from an empty list breaks as soon as a write drops the empty list.
- Leaving init as it is: such projects then write `.sdd/.gitignore` and the graph's `.gitattributes` by hand and miss every later change to them.
- Running sdd's git calls without hooks: already rejected in the gap, since it commits exactly the writes such a project reverts and skips every project's own commit checks.

Accepted costs: one more config key with its validation and tests; a project skipping `mcp` gets no engine unless its own setup registers the server.

## Acceptance criteria

- [ ] With `init.skip: [mcp, permissions, skills]`, `sdd init` leaves `.mcp.json`, `.codex/config.toml`, `.claude/settings.json` and the skill renders byte-identical, also when they lack sdd's parts, and its commit names none of them.
- [ ] Each value skips only its own surface; a project listing `mcp` alone still gets the allow rule and the skills.
- [ ] `sdd move --project-dir` honors the key in its install step.
- [ ] `sdd config set init.skip` refuses an unknown value; a config holding one still loads, with the value reported and ignored.
- [ ] In a repository whose commit-msg hook admits `sdd:` only under `.sdd/` and whose root `.gitignore` and `.gitattributes` hold no lines earlier builds derived, init with all three values skipped commits without the hook refusing it.
