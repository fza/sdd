The `sdd`-owned clones sync automatically only while a per-repository lease from recent engine calls holds; their fetch pace fits 90 percent of each bucket's hourly budget, and credits from unused fetch slices let a waiting push or a commanded sync run inside its cooldown.

## Problem

Under 20261107-095427-d-tac-yux, every running `sdd serve` checks the gate once a minute and syncs the project's graph and every reachable connected repository whose cooldown passed, read or not. Each idle repository costs 12 fetches an hour at the 5m default. A push of a connected graph write inside its cooldown waits with no way through. The gate counts per hour only, while hosts also limit per minute: GitHub asks for at most 6 pushes a minute per repository.

## Scope

The lease covers the `sdd`-owned clones under `$XDG_DATA_HOME/sdd/repos/`: those of connected repositories and the project's own `graph_repo` clone. A graph inside the code repository syncs as before.

## Lease

- Each covered repository has a lease in the gate's record (`remotes.json`), shared by every `sdd serve` on the machine.
- A lease starts or renews:
  - for the home project's graph, on `start_procedure` or `resume_session`;
  - for project X, on any engine call of an instance working in X;
  - for a repository a read names: `search` with `repos` or `all_repos`, `show` or `view` with `project`, a capture ref `<repo-id>:<entry-id>`, a capture writing into a dependency;
  - for the home project's graph, on a read naming no repository.
- A lease ends `lease_pause` (default 10m) after its last renewal. A `sdd serve` process that dies stops renewing.

## Timer

- The serve timer syncs a covered clone once per effective fetch cooldown, and only while its lease holds. Without a lease it fetches nothing.
- Waiting commits are always pushed.
- For `graph_repo` clones this ends timed sync. 20261028-175735-d-tac-k4y introduced it to keep idle sessions current, and 20261107-095427-d-tac-yux kept it as the once-a-minute gate check.

## Lease start

- `EnsureReposFresh` already runs a due sync of a connected clone before a read, and the read waits for it, unlike the rule of 20261107-095427-d-tac-yux that a refresh never blocks the operation that started it. This keeps the wait and adds a bound.
- When a lease starts and the clone's effective fetch cooldown has passed, one sync runs at once and the call waits at most `read_wait` (default 15 s). Past that, the call serves the clone as it stands with a notice that the refresh still runs and how old the clone is. The sync finishes in the background.
- Inside the effective cooldown, the call serves the clone as it stands and spends nothing.
- Automatic reads never spend credits.
- The wait stands in tension with 20260829-113416-d-cpt-nut, under which a call never waits long enough to look frozen.

## Slices

Per bucket (host and protocol, with HTTPS split by login as the gate splits it), A is the bucket's `per_hour` (`per_hour_unauthenticated` for HTTPS without login), and B the number of `sdd`-owned clones in the data directory in that bucket; a clone whose login is not yet known counts in both HTTPS buckets. Code repositories and removed clones do not count; idle clones do. The effective fetch cooldown is max(`fetch_cooldown`, 3600 s × B / (0.9 × A)). A slice is the one fetch a clone may make per effective cooldown. Automatic fetches stop once the sliding hour holds 0.9 × A operations of the bucket. The remaining 10 percent is kept for pushes and commanded syncs.

## Per-minute limit

Each bucket has a `per_minute` limit, by default `per_hour` / 10: 60 at 600 an hour, 6 at the 60 an hour without login. Once a minute reaches it, every further operation of the bucket is deferred to the next minute and reports that time as its next allowed time.

## Credits

- Each bucket has a wallet in the gate's record, counted per minute over the same sliding 60 minutes as the hourly budget.
- A slice that ends unused earns one credit. Credits age out of the window.
- A credit pays for one operation inside its cooldown, and only for a push of waiting commits or a commanded sync (`sdd repo sync`, `sync_repos`). 20261107-095427-d-tac-yux skips both inside the cooldown.
- A credit never shortens the cooldown that follows a failure: a rate-limit answer, a refused login, a rejected push.
- Operations a credit pays for count in the hourly and per-minute limits.
- Floors hold even with a credit: 1 minute between fetches and 10 seconds between pushes of one repository. The concurrency cap holds too.
- An empty wallet defers the operation, with the next allowed time.

## Configuration

`sync.default` and `sync.hosts.<host>` gain `lease_pause` (default 10m, minimum 1m) and `read_wait` (default 15s, minimum 1s). Their `ssh` and `https` blocks gain `per_minute` (default `per_hour` / 10), and `https` also `per_minute_unauthenticated` (default `per_hour_unauthenticated` / 10). A value below its minimum is ignored with a warning, per 20260921-174543-d-cpt-tv9. The push reserve is fixed at 10 percent and has no key.

## Rejected alternatives

- A read only marks the repository as needed, and the next tick fetches it. The first read after a quiet spell then serves a clone days old, so a capture's duplicate check runs on old data.
- Backoff polling at doubling intervals up to 60 minutes. Idle repositories still spend budget.
- A lease over the whole dependency closure, or over the leased repository plus the repositories its entries reference. Both fetch repositories no call reads.
- The serve timer syncing every covered clone while any lease holds. It fetches repositories no call reads.
- Keeping the project's own `graph_repo` clone on the timer. Idle sessions then still spend budget.
- B as every repository in the gate's record, expiring after 30 days. The record also holds code repositories and repositories no longer connected.
- B as the connected-repository registry. It leaves out the project's own `graph_repo` clone.
- Pushes served first instead of a reserve, or no reserve. At large B the fetch slices take all of A, and ordinary pushes hit the hourly limit.
- A fixed `per_minute` of 30. It allows half of the 60 an hour without login in one minute.
- No per-minute limit. Hosts limit per minute, and an hourly budget alone allows a burst past it.
- A `lease_pause` of 30 minutes, or of twice the fetch cooldown. A lease then keeps fetching long after the last call, and with many clones the pause stretches with the cooldown.
- A `read_wait` of 5 seconds, or no wait. The first read after a pause then mostly serves the old clone.
- Credits for automatic reads too. Busy sessions drain the wallet a push needs.
- Credits for pushes only. A commanded sync stays skipped while credits are left.
- A `push_reserve` key, or no keys at all. The reserve needs no tuning per host, while the pause, the wait and the per-minute limit do.

## Accepted costs

- The first read after a pause waits up to 15 seconds, silent inside the call.
- A read never sees data fresher than the effective cooldown unless a sync is commanded.
- With many clones the effective cooldown stretches beyond `fetch_cooldown`.
- An idle session no longer sees other participants' movement until its next call, which gives up part of the immediate feedback 20260817-162701-d-cpt-r8k aims at.

## Acceptance criteria

- [ ] Every `sdd serve` on the machine shares one lease per covered repository in the gate's record.
- [ ] `start_procedure` and `resume_session` start or renew the home graph's lease; an engine call of an instance working in a project renews that project's lease; a read naming a repository renews that repository's lease; a read naming none renews the home graph's lease.
- [ ] A lease ends `lease_pause` after its last renewal, and a dead serve process renews nothing.
- [ ] Leases cover connected repositories' `sdd`-owned clones and the project's `graph_repo` clone; a graph inside the code repository syncs as before.
- [ ] The serve timer fetches a covered clone only while its lease holds, at most once per effective fetch cooldown, and pushes waiting commits with or without a lease.
- [ ] A lease start past the effective fetch cooldown runs one sync at once; the call waits at most `read_wait`, then serves the clone with a notice that the refresh still runs and the clone's age, and the sync finishes in the background.
- [ ] A lease start inside the effective fetch cooldown serves the clone and spends nothing.
- [ ] B counts the `sdd`-owned clones in the data directory per bucket, idle ones included, code repositories and removed clones excluded.
- [ ] The effective fetch cooldown is max(`fetch_cooldown`, 3600 s × B / (0.9 × A)), and automatic fetches stop at 0.9 × A operations in the sliding hour.
- [ ] Once a bucket's operations in a minute reach `per_minute` (default `per_hour` / 10), every further operation of the bucket is deferred to the next minute with that next allowed time.
- [ ] A slice that ends unused earns one credit, and credits age out of the sliding hour.
- [ ] A credit lets a waiting push or a commanded sync run inside its cooldown, never an automatic read, and never inside the cooldown after a rate-limit answer, a refused login or a rejected push.
- [ ] Operations a credit pays for count in the hourly and per-minute limits and keep the 1 minute and 10 second floors and the concurrency cap.
- [ ] An empty wallet defers the operation with the next allowed time.
- [ ] `lease_pause`, `read_wait`, `per_minute` and `per_minute_unauthenticated` are read from `sync.default` and `sync.hosts.<host>`; values below the minimums are ignored with a warning on read and refused by `sdd config set`.
- [ ] The configuration docs describe leases, the effective cooldown, the push reserve, the per-minute limit and credits.
