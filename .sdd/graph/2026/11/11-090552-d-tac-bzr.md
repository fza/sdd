`sdd move` records `v0.18.0-alpha.3.fza.43`, the first fork release reading move records, as a moved graph's `minimum_version`, whichever build makes the move; a higher recorded version is kept. The floor exists so builds that cannot read move records refuse the graph instead of writing into its former location (20261109-004305-s-tac-mp1). A released build recorded its own full version, which also locks out every earlier fork release that reads move records, and a dev build recorded `v0.18.0-alpha.4`, which every current fork release sorts below. With the fixed floor, every fork release that has `sdd move` accepts a moved graph and stock `v0.18.0-alpha.3` stays out. This completes the scope the upstream-base floor left open (20261111-083548-d-tac-h9q).

Rejected: bumping `graph_schema_version` to 2 for moved graphs. Every stock build would refuse the graph, but upstream will define its own schema 2 with another meaning. Rejected: leaving the floor until `sdd move` is merged upstream, which keeps dev-build moves locking out every fork release.

Accepted cost: an upstream release of `alpha.4` or later passes the floor without reading move records, until upstream takes `sdd move` and sets the floor to its own release.
