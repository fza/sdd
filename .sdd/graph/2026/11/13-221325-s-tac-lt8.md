When a decision's reason is missing, the capture now tells the agent to ask the user openly and offer no reason of its own, not even as an answer option. The `userWordsHeld` gate, which holds the capture while the reason is missing, now says "ask the user for the decision's reason, offering none of your own". In Codex capture eval runs on `fza-fork` (two batches of three runs, builds `369cb6fe` with fixes and `719cfd12`), an agent offered a reason it wrote itself as an answer option. The change sharpens the guidance of 20261113-202045-s-tac-ab9, which tells the agent to ask when the user's words give no why.

The change is guidance only, pinned by `TestCapture_ReasonStatesWhyNeverWhat`. Commit `699fa310` on branch `pr/fix-eval-defects-2`, merged into `fza-fork` at `1b04d01e`. The test failed before the change and passes after; breaking the guard made it fail, and the file was restored.

Open: no real-agent run has shown it yet. The eval login hit its usage limit until 2026-12-09, so no Codex rerun was possible.
