Three defects in the staged-file freeing of 20261114-095140-d-cpt-ad4 and in the catch-up it relies on get one fix each, so publishing never deletes a staged file another capture still names, no report lands during another attach's unfinished write, and the sweep never deletes the staged files of an open session.

## 1. Publishing reads the log before it deletes

The staged files deleted after an entry is published are chosen from the session state the holder saw last. When another attach of the session (a CLI call with `--session` beside a serve, a delegate delivering) named a file in a capture meanwhile, that claim is not in the state yet, and the file is deleted; the second capture then fails with "attachment has not been staged". The append recording the deletion catches up only afterwards.

Fix: before deleting, publishing catches up with the session log and computes the claims again from the caught-up state. It records the release of the files no running capture names at the caught-up version first and deletes them only once that append lands; a conflicting append catches up and computes the claims again.

## 2. Every catch-up checks for an unfinished write again

A report is refused while an operation of the session is unfinished: only its retry or cancellation is accepted. A holder with a stale state passes that check, then meets the newer log at its append, catches up, and appends its report. When the folded events opened an operation in another instance, the report lands in the middle of that unfinished write.

Fix: after every catch-up, the unfinished-write check runs again on the caught-up state, before the append. A report the caught-up state refuses is refused with the message the check gives today.

## 3. The sweep reads in-repo session logs

Sessions of older versions log into the checkout (`.sdd/sessions`), and the sweep sees only the logs in the state folder. When it retires an unused project, it deletes the project's staged files once no log in the state folder owns them, including the files of an open in-repo session.

Fix: sdd records every checkout path it opens a project from in the state folder, since one project key stands for every clone sharing its `repo_id` and every linked worktree, each with its own `.sdd/sessions`. The sweep reads `<checkout>/.sdd/sessions` of each recorded checkout too and keeps the staged files of every open session it finds there. An in-repo log it cannot read counts as open, as rule 7 of 20261114-095140-d-cpt-ad4 keeps unreadable logs. A recorded checkout that no longer exists holds no open session.

## Rejected

- For 1, deleting nothing at publication: no race at all, but it drops the rule of ad4 that a staged attachment is deleted once the entry using it is published, and staged files stay for the whole session.
- For 1, leaving it: the second capture fails and the user stages the file again.
- For 2, a per-session file lock, one call at a time across attaches: it rules out every race of this kind, but a slow call blocks the other attach, and the lock needs timeout and crash handling.
- For 2, leaving it: with defect 1 fixed the refusal covers attachments, but other effects of a report written mid-write stay possible.
- For 3, a second retention period for staged files with no known owner log: an in-repo session left open longer still loses its files.
- For 3, never deleting staged files without an owner log: true orphans stay forever, against the purpose of the sweep.

## Accepted costs

- Publishing reads the session log once more.
- Each catch-up runs one more check.
- The detached sweep depends on recorded checkout paths, one small file per project in the state folder listing each checkout sdd opened the project from.

## Fulfilled when

- A test names a staged file in a capture through a second attach, publishes another capture from the first attach, and the second capture still finds its file.
- A test opens an operation through a second attach while a stale first attach reports into another instance; the report is refused with today's unfinished-operation message, and the log holds no report after the opened operation.
- A test sweeps an unused project whose recorded checkout holds an open in-repo session: its staged files stay. With that session ended, or the checkout gone, they go. An open in-repo session in a second recorded checkout of the same project keeps its files too.
