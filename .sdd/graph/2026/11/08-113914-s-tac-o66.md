The fetch of `sdd`-owned clones now brings full contents and keeps every connection inside the per-machine git gate of 20261107-095427-d-tac-yux, as 20261107-224549-d-tac-r9q and its refinement 20261108-104247-d-tac-k6f decide, in commit addbe4fb on `pr/feat-git-limits`, merged into `pr/core` and `fza-fork`. It closes both decisions and the gap 20261107-132320-s-tac-2za.

Every git command sdd runs in a clone goes through one helper that gives it the gate admission's environment while an admission holds and otherwise the lazy fetch bar `GIT_NO_LAZY_FETCH=1`, the bar only with git 2.55 or later. The fetch runs with `--no-filter` and `-c fetch.unpackLimit=1`, then `git backfill --sparse HEAD..<upstream>` inside the same admission; the merge runs with `--no-stat`. The checkout of a fresh clone runs with the admission's environment, and a cone change runs inside an admission: at clone time in the clone's own, later in a fetch admission the gate grants.

Acceptance criteria, each with a test in `internal/git`, `internal/repos` or `internal/model`:

- One connection per round: a fetch of entry changes in a clone starts no further fetch; missing delta bases of code files outside the sparse set arrive in one batch, the second connection 20261108-104247-d-tac-k6f names for a code repository.
- The merge after a fetch succeeds with the remote removed.
- Commands carry the admission's environment inside an admission and `GIT_NO_LAZY_FETCH=1` outside one: a merge lacking contents outside an admission fails with git's `lazy fetching disabled` and leaves HEAD and the working tree unchanged.
- The checkout of a fresh clone shows its content fetch in the gate's trace; a cone change outside an admission does not happen.
- A clone holding upstream commits fetched without contents merges after the next fetch's backfill.
- The git version check covers releases below and from 2.55, vendor suffixes and unreadable output. No test runs an older git end to end.

Two behaviors differ from the decisions' text:

- The upkeep that opens every operation follows a force push fetched before an interrupted round. When that rewrite was fetched without contents, by an sdd from before this change, the move fails under `GIT_NO_LAZY_FETCH=1`. The upkeep then restores the working tree and stops before replaying sdd's commits onto the rewrite, and the next fetch makes the move inside its admission. Without this the upkeep would fail on every run and the clone would never sync again.
- A cone change the gate defers, because the fetch cooldown runs, leaves the clone on its old cone until the next upkeep after the cooldown, instead of failing the upkeep.

One existing force-push test fetched by hand without contents to model an interrupted round; it now fetches with `--no-filter`, as sdd does, and a new test keeps the case without contents. `TestGraphRepoConnectedWriteFromTheCodeRepository` in `internal/cliapp` failed in full-suite runs: its `sdd serve` fixture allows 10 seconds, which the test exceeds under full-suite load. Run alone it takes about 4.8 seconds with and without this change.
