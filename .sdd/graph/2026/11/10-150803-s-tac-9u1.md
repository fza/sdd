Pre-flight on the fork release `v0.18.0-alpha.3.fza.43` accepted nine findings a small model invented, seven of them `high`, and nothing in sdd can tell such a verdict from a real one or show what prompt produced it. On a client project with `verify.mode: deep` and `llm.model: tensorx/z-ai/glm-5.3-flash` through an OpenAI-compatible endpoint, the third pre-flight call of one capture, the first after a deep exchange had settled, returned findings such as `missing-storybook` and `missing-paper-trail` that demand a "Canada-Family Conversation Storybook", "thirteen required findings" and "Review Dartboard sections" from an "extended turn". The same capture's first two pre-flight calls returned two real findings and none. The draft did cite real IDs the findings quote, so the model read the request; none of the invented terms appears in the draft, the session's grounding reading, the project graph or sdd's prompt templates. The project's stats log shows 154 earlier pre-flight calls on the same model, prompts up to 45703 input tokens, with no such output reported. The model's known defect on another endpoint, a response schema ignored (20261101-002900-s-tac-3q0), is not this one: here the response held schema-shaped findings.

Four gaps in the fork release let this happen unseen:

- Pre-flight findings carry a free-text `category`, which the prompt asks for as any short hyphenated tag and shows only by example, and no field for an excerpt: an excerpt is optional, set off in quotes inside `observation`, and may come from the draft or from a referenced or reading entry, though cited excerpts should locate a passage (20261005-170145-d-tac-gch). So no closed category set exists to check a finding against, and sdd never checks that a cited excerpt locates text the prompt holds, the provenance check the earlier phantom-quote gap (20260901-220355-s-tac-owp) already asks for. Seven invented `high` findings blocked the write until the user overrode them.
- The pre-flight call path changed in that release: pre-flight over the grounding reading, which deep mode runs too, and the deep exchange both shipped there (20261109-054916-s-cpt-mn7), and the call that failed is the first pre-flight after a deep exchange. Whether its prompt differs from the first two is unknown, because sdd records no prompts.
- A first response that does not parse goes to a second extraction call (`extractor.tmpl`), which a weak model can fill with findings of its own. The extraction call records its own stats row under op `preflight-extract`, so the stats log would show whether it ran, but this call's rows are lost with the rest (next point), and a first response that does not parse still records as a success (20260831-093815-s-tac-k7d).
- The project's `.sdd/stats/llm.jsonl` holds no row after the project moved to a separate graph repository, so the failing call's token counts and duration are lost too.

Done when: a pre-flight finding whose cited excerpts locate no text in its prompt, or, once the rubric names a closed category set, whose category falls outside it, is dropped or shown as unverified rather than blocking; sdd can record the rendered prompt and raw response of a checker call for diagnosis; the stats log keeps recording after a graph-repository move; and a replay of this capture's third pre-flight on the same model shows whether the prompt after a deep exchange differs from the first two.
