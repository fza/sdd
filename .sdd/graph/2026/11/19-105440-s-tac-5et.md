Recall-stage calibration, background calibration in `sdd serve` and the single `sdd grounding update` command are built on `fza-next` (7a51f57e, 333bfda2, ab8b7ac5, 57aadc3e, 51b2921c, 6556f6a5, 05e618e3, ce0e9de6).

## `sdd grounding update`

- 7a51f57e, 333bfda2: a terminal shows a progress bar named for the judge while it scores labelled pairs, counting pairs done and failed.
- ab8b7ac5: `scripts/relevancelabels` exports, imports and seeds labels as JSON Lines; it is never built into the binary.
- 57aadc3e: `sdd grounding update [--force]` labels each entry with every entry it refs, closes or supersedes as replayed labels, skipping pairs already labelled, then scores the unscored labelled pairs. It replaces `sdd grounding rescore` and `sdd grounding seed`; `--judge`, `sdd relevance export` and `sdd relevance import` are gone, `sdd relevance compact --drop-replay` stays, and `sdd grounding status` reads the ranking judge alone. `--force` replaces the judge's scores and needs a store that can replace them. A failing referencing entry does not stop the run; the failures are listed at the end with a non-zero exit (20261119-103312-s-tac-bxd). 51b2921c fixes a test of its last progress snapshot.

## Recall stages and background calibration

- ce0e9de6: thresholds rest on the highest of the stages 0.90, 0.95 and 0.98 the judge holds (`model.RecallStages`, `model.StagePositives`). Below 0.90, `gather` keeps the 100 top-ranked candidates to judge, lists the next 300 by title and counts the rest.
- ce0e9de6: `verify.auto_calibrate`, on by default, lets `sdd serve` run `Application.AutoCalibrate` from a minute after start. On a ledger without labels it first seeds the graph's refs. Each request holds one entry's unscored positive pairs with a sample of its other labelled pairs, up to 60, four requests at a time, and its scores are stored when it returns. Scoring runs at once until the next stage holds; past that, each request waits until no tool call reached the server for a minute; the run stops at 0.98. One server per repository on a machine scores at a time, and `sdd grounding status` names the running run.
- Already in place before these commits and kept: labels that carry over a judge switch, scores keyed per judge and per draft-text hash (b50edafa), and the deep reading's tiers before calibration (20261118-162919-s-tac-2t0). After a judge switch the new judge has no score for the labelled pairs, so the background run sends them.
- 6556f6a5: a cancelled `claude` CLI call kills its process group, so no `claude -p` child outlives a server quit. HTTP providers stop with the cancelled request context.
- 05e618e3: the configuration reference documents the stages, the uncalibrated tiers, background calibration and its stop on quit.

This delivers 20261119-103253-d-tac-vl9 and 20261119-103451-d-tac-7dx as written, including that the background run keeps scoring while the server is idle after a stage holds and stops at 0.98, so both close.

## Beyond the decisions

The background run also scores the pairs new captures label, not only those left after first use or a judge switch.
