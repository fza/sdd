The `sessions.token_saving` switch is implemented: commit `c79cb912` on `pr/feat-token-saving`, merged into `fza-fork` as `3738bc50`. It fulfills 20261101-164201-d-tac-sj4.

`sdd serve` reads the key from the user-global config only and passes `ServeInFull` to the MCP server when it is `off`. A session served in full ignores what its ledger records as already sent, so instruction lanes, framing, report schema, vocabulary and the view hint arrive in full on every call. It still records what it sent, so turning the key back on stubs only what the agent did receive, and a block repeated within one response is still sent once. `sdd config set` writes `on` or `off` to the global config, refuses any other value, and refuses the key in `config.local.yaml`; a value in a per-repo layer is reported as ignored.

Tests cover the value check and its default, the refusals in `sdd config set`, the per-repo report, a second capture served in full by the MCP server, and `sdd serve` honouring the global key while ignoring the local one. Each new check was broken once to confirm its test fails. Breaking the ledger check alone first passed, because skipping the ledger write masked it; the write skip was dropped as unneeded, and the check is now caught on its own. The full suite on `fza-fork` passes except TestConflictingUpstreamIsReportedAndNothingMerged, which also fails without this change.
