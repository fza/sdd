Every surface reaches only a project's directly declared dependencies; refs a dependency holds into projects further out resolve from the clones the machine already has, with a bounded fetch on a miss, the shared unavailable marker and a typed warning when they stay unresolved, and a recorded miss that allows the next fetch only once the clone moved or a day passed.

## Scope

From project A, every surface reaches A's directly declared dependencies only:

- CLI search and view;
- the MCP reads `search` with `repos` or `all_repos`, and `show`, `view`, `read_attachment` and `info` with `project`;
- moves, `start_procedure` with `project`;
- capture refs;
- export and lint;
- the dependency refresh and `sdd repo sync`.

A project C that A's dependency B declares, and A does not, is read only by projects that declare C. A move into C from A is refused.

This narrows the horizon of 20261026-194528-d-cpt-gcq, the transitive declared closure, to the direct dependencies, and with it the projects a session may work in under 20260903-152247-d-cpt-yjc. The transitive closure walk (`model.DependencyClosure`, `internal/model/crossrepo_selection.go`) is removed, and the MCP server instructions and the `project`, `repos` and `all_repos` descriptions of the tools in `pkg/mcpapp/tools.go`, which name the closure, change with it. CLI and server keep the one rule of 20261029-135448-d-cpt-olh, whose unavailable-member rules keep applying to direct dependencies; a project further out is no member a read can fail on. This removes the case of 20261028-155600-s-tac-4mz, where an uncloned second-level member fails every all-repos read.

## Refs into projects further out

When A reads B's entries, B's refs into C resolve their title and summary from C's `sdd`-owned clone when the clone holds the entry, shown with the clone's age and without a sync.

When the entry is not available, because C has no clone or the clone lacks the entry, one fetch on miss of C runs through the per-machine git gate, whose record (`remotes.json`) and budgets 20261113-232855-d-tac-1nz sets out, cloning first when C is connected and not yet cloned. The read waits for that fetch at most `read_wait`, like a read; past that the fetch finishes in the background. When C is inside its fetch cooldown and the wallet holds a credit, one credit pays to fetch now. With no credit, the ref shows as unavailable with the reason "fetch deferred until <time>". This extends the credit uses of 20261113-232855-d-tac-1nz, under which automatic reads spend none, to this fetch.

## Unresolved refs

Each ref that cannot resolve renders the shared unavailable marker of 20261029-135448-d-cpt-olh plus a short reason. Each case lands as one typed warning of a new kind, with olh's fields, who must act and the time:

- `not-connected`: C is not connected on the machine;
- `missing-after-fetch`: a completed fetch still lacks the entry;
- `fetch-deferred`: the gate deferred the fetch and no credit was left.

## Recorded misses

Only a completed fetch that still lacks the entry records the miss, in machine state beside the gate's record: C, the entry ID, C's clone commit and the time. The ref then shows the reason "not in C as of <time>". One more sync for it is allowed once C's clone commit has moved or 24 hours have passed.

## Rejected alternatives

- Narrowing reads only, while maintenance keeps the closure. `sdd repo sync` keeps fetching repositories no read here needs, and the CLI/server split that 20261029-135448-d-cpt-olh removed returns.
- Narrowing the MCP surfaces only. CLI and agent then see different graphs.
- Pointer only for refs into projects further out. They then show no title even when the clone exists.
- Resolving and syncing through B on every read. That is the transitive reach this removes.
- The fetch on miss under the rules of a read without credits, or with no wait. Without a wait, the first read never shows the entry.
- Retrying only when the clone moved. The entry stays missing for good when nobody on the machine reads C.
- Retrying at every lease start of B. That costs one fetch per pause, indefinitely.
- Displays of their own for these refs. That makes two displays for one situation, and surfaces collecting olh's warnings miss these.
- The marker without warnings. An agent never learns that connecting C would resolve the refs.

## Accepted costs

- What a read shows depends on which clones the machine holds.
- A resolved entry from a project further out may be old.
- When nobody reads C, an entry that landed late shows up to a day later.
- Export and lint no longer cover indirect dependencies; a project B depends on is checked only from B.
- Refs into projects further out can draw down the wallet a push needs; the 10 percent hourly reserve still keeps room for pushes.

## Acceptance criteria

- [ ] CLI search and view, the MCP reads, moves, capture refs, export, lint, the dependency refresh and `sdd repo sync` reach only the directly declared dependencies of the project at hand; a move into an undeclared project is refused; no transitive closure walk remains.
- [ ] A ref from B into C resolves title and summary from C's clone when the clone holds the entry, shown with the clone's age and without a sync.
- [ ] When the entry is not available, one fetch on miss of C runs through the git gate, cloning first when C is connected and not cloned, and the read waits for it at most `read_wait`.
- [ ] Inside C's fetch cooldown, a credit pays for that fetch when the wallet holds one; with none, the ref shows as unavailable with "fetch deferred until <time>".
- [ ] Each unresolved ref renders olh's unavailable marker with a short reason, and each case yields one typed warning of kind `not-connected`, `missing-after-fetch` or `fetch-deferred`, with who must act and the time.
- [ ] Only a completed fetch that still lacks the entry records the miss with C, the entry ID, C's clone commit and the time beside the gate's record; the ref shows "not in C as of <time>" and gets one more sync only once the clone commit moved or 24 hours passed.
- [ ] The MCP server instructions and the tool descriptions in `pkg/mcpapp/tools.go` name direct dependencies only.
