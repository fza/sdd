Three ranking-judge defects are fixed and merged on `fza-next`: the alternating batch size of 20261122-003230-s-tac-iid (fe9dd0b13), the replayed labels in the `precision:` line of 20261122-003437-s-tac-onq (2985e1ed9), and the `Halving` loop on unbounded scorers of 20261122-003533-s-tac-apk (a6e7cfc54).

## Fixed

- Batch size (fe9dd0b13): `BatchSizes.Broke(key, size)` records a size that broke, and `Raise` refuses a size at or above one that broke within the last hour (`FailedBatchRest`). `FilesystemBatchSizes` keeps the failures in `chat-batch-failures.json` beside the sizes file, whose format is unchanged, so older binaries still read it. A judge that fails above some size no longer doubles back into it on every second pass.
- Precision line (2985e1ed9): `RelevanceLedger.Calibration` counts passed-in-full and referenced pairs over live labels only, and the line reads "N of M live labelled pairs passed in full were referenced (x%); replayed labels not counted". The two differences the gap set apart stay: the count reads a stored score against the threshold as calibrated now, not whether a check served the pair in full, and it is unweighted where the threshold is weighted.
- Unbounded scorers (a6e7cfc54): `Halving` caps a split by `MaxBatch` only when it is above 0, so a scorer without a bound gets the request in one call.

## Tests

`TestCalibration_CountsLivePairsPassedInFull`, `TestRenderCalibration_NamesTheLabelsPrecisionCounts`, `TestHalving_TakesAnUnboundedScorersRequestInOneCall`, and the memory and filesystem tests of the raise bar and the `Broke` call in halving. Each failed before its fix. A full `internal/cliapp` run on an idle machine is still owed: the package hit its timeout under load, and its grounding, relevance, serve, gather and capture tests pass.
