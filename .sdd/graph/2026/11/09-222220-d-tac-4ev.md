The grounding and verifier settings form one `verify` block whose `mode` (`off`, `grounding`, `prose`, `deep`) says how far a capture is checked, with `prose` and the grounding prefilter on by default; the deep verifier picks how it runs with `verify.runner` and takes its model and effort from per-runner blocks with defaults of their own, never from `llm`; and `llm` gains a `codex` provider and an `effort`. It builds on graph grounding (20261109-004506-d-cpt-udz) and the draft verifier (20261109-004729-d-cpt-xs5), whose separate `grounding` and `verifier` blocks it merges.

**Mode.** `off` checks nothing; `grounding` enforces the grounding reading; `prose` adds the light verifier; `deep` the deep one. The default is `prose`. The committed and user-global configs set it, the committed value wins, and `config.local.yaml` may only tighten it.

**Runner.** `verify.runner` replaces `verify.launch`: `subagent` (the drafting agent starts a subagent in its own harness), `claude` (sdd runs `claude -p`), `codex` (sdd runs `codex exec`), `driver` (sdd runs `verify.driver.command` per round; formerly `custom_driver`). Default `subagent`. The machine-local value wins.

**Model and effort.** `verify.claude` and `verify.codex` each hold `model` and `effort`; defaults `claude: {model: sonnet, effort: medium}` and `codex: {model: "", effort: medium}`, an empty model leaving codex's own default. A subagent uses `verify.claude` in Claude Code and `verify.codex` in Codex, told apart by the MCP client name; the separate `verify.subagent` block is gone. Values pass to the CLI or the subagent tool as written: sdd ships no table mapping model IDs to aliases, so a default that any harness accepts (the alias `sonnet`) stands in for one.

**Prefilter.** `verify.prefilter` defaults to `true`. Without an `llm_prefilter` block it uses the `generate` protocol on the `llm` provider and model with effort `low`, since judging relevance needs no reasoning; values set in `llm_prefilter` win.

**LLM.** `llm.provider: codex` runs sdd's own LLM calls through `codex exec`, so a Codex-only person needs no Claude login or API key. `llm.effort` applies to `claude-cli` (`--effort`) and `codex` (`model_reasoning_effort`), default `medium`, passed as written.

Rejected, with the reasoning: inheriting the verifier's model and effort from `llm`, failing on a provider/harness mismatch (a Claude ID is no subagent alias, and translating needs a table in the binary); an ID-to-alias table in the binary or in config (it ages with every model release); a third `verify.subagent` block (in Codex its Claude default is no valid model); `llm.effort` for the API providers (a per-provider effort mapping, and no codex provider to inherit from); requiring `llm_prefilter` before the prefilter runs (the default would be off in practice); the names `launch`, `where`, `spawn` and metaphor names such as `carrier` for the runner key.

Accepted costs: `prose` by default means every capture runs grounding and the light verifier, slower and costlier than before; on `claude-cli` or `codex` the prefilter starts one CLI process per candidate; the `sonnet` alias follows each new Sonnet release; a codex adapter whose JSON event output sdd tracks.

## Acceptance criteria

- [ ] An unset `verify.mode` resolves to `prose` and an unset `verify.prefilter` to `true`; `sdd config` shows both defaults.
- [ ] `verify.runner` accepts `subagent`, `claude`, `codex`, `driver`; `verify.launch` and `custom_driver` are refused naming the new key and value.
- [ ] Unset `verify.claude` and `verify.codex` resolve to `{sonnet, medium}` and `{"", medium}`; a subagent dispatch names the block matching the MCP client; `verify.subagent` is refused naming the replacement.
- [ ] With the prefilter on and no `llm_prefilter`, the prefilter runs `generate` on the `llm` provider and model with effort `low`.
- [ ] `llm.provider: codex` runs summaries and pre-flight through `codex exec`; `llm.effort` reaches `claude --effort` and codex's `model_reasoning_effort`, default `medium`.
- [ ] No model or effort mapping table exists in the binary.
