A delegate dispatched for a multi-round child session (20261109-004845-d-cpt-ldx) keeps working across rounds: the harness continues the same delegate or relaunches a fresh one with the same child handles, and sdd itself may be the launcher. This refines 20260829-122157-d-cpt-zpe, which allowed one fresh-context launch by the harness per dispatch, enough for a delegate that answers once but not for the deep verifier's exchange (20261109-004729-d-cpt-xs5).

- **First launch** stays fresh-context, as 20260829-122157-d-cpt-zpe requires.
- **Later rounds** continue the same delegate through the harness's continue mechanism, listed in the per-harness launch configuration (the subagent definition 20260829-122157-d-cpt-zpe ships per harness), or relaunch a fresh one with the same child handles. The child's serve always carries the full exchange so far, so a relaunched delegate loses nothing.
- **sdd as launcher.** With a headless launch (`verifier.launch: claude | codex`), sdd starts the agent CLI itself, keeps the CLI's session id per child session and resumes it each round; with `custom_driver`, an external command does so. No harness subagent tool is needed.
- **The parent handle never enters a delegate prompt**, whoever launches.

Rejected, with the reasoning: only relaunching fresh each round (a harness that can continue would re-read everything for nothing); only continuing (a harness without a continue mechanism could not run the exchange); fork-context launches (the delegate would hold the parent handle by construction).

Accepted costs: the per-harness launch configuration lists a continue mechanism per harness; sdd owns the lifecycle of the CLI processes it launches.

## Acceptance criteria

- [ ] A child session's later rounds run either by continuing the same delegate or by a fresh delegate given the same child handles, and the child's serve carries the full exchange in both cases.
- [ ] With `verifier.launch: claude` or `codex`, sdd starts the CLI, stores its session id with the child session and resumes it each round.
- [ ] No delegate prompt carries the parent handle, for every launch value.
