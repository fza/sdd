`sdd grounding update [--force]` is the one command that brings the grounding prefilter's calibration up to date, replacing `sdd grounding rescore`, `sdd grounding seed --from-refs` and their `--judge` flag.

## The command

- It labels each entry with every entry it refs, closes or supersedes, as replayed labels, skipping pairs already labelled. It then has the ranking judge score the labelled pairs that judge has not scored, one request per referencing entry.
- `--force` scores every labelled pair again, the new scores replacing the judge's old ones.
- It scores with the ranking judge alone, the one `sdd grounding status` names, so `--judge` and its aliases `ranking` and `prefilter` go. `sdd grounding status` reads that judge alone too.
- On a terminal it shows a progress bar like `sdd index`, counting the pairs done.
- A referencing entry whose request fails does not stop the run. The command lists each failure with its cause at the end and exits non-zero; the next run scores the pairs left.

Label import and export leave the CLI: `sdd relevance export`, `sdd relevance import` and `sdd grounding seed --from <file>` move into `scripts/relevancelabels`, a development tool never built into the binary. `sdd relevance compact --drop-replay` stays.

## Why

`sdd grounding seed --from-refs` already scored the pairs it seeded and `sdd grounding rescore` scored the rest, so two commands did overlapping work. One command with one optional flag, like `sdd index`, leaves less surface to learn and document. Since one ranking judge serves both readings (20261118-162927-s-tac-pq5), `--judge` chooses among judges no reading uses. Moving labels between ledgers is a development task, not a user one.

This replaces the commands of 20261114-003118-s-tac-0vl, 20261118-162919-s-tac-2t0 and 20261118-162941-s-tac-450, and keeps the failure handling of 20261118-162941-s-tac-450.
