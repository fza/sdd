A user-global config key, `sessions.token_saving`, turns off sdd's served-once memory: with `off`, every serve carries its instruction lanes, framing blocks, report schema and vocabulary in full instead of a one-line stub. The default stays `on`, so every host keeps today's behaviour unless the key is set.

The served-once memory (20260705-010751-d-tac-dbk, made per lane by 20260826-120330-d-tac-8f8) remembers what it sent per sdd session. It knows nothing of the agent's own context, so after the agent's context is compacted it keeps sending stubs for text the agent no longer holds, until the agent calls `resume_session`. agentic-helpers adds a hook that collapses MCP output the agent already holds, keyed per agent and reset at compaction, `/clear` and resume. On a machine where that hook runs it does the saving more accurately than sdd can, and sdd's stubs only hide text the hook would have let through after a compaction. The key lets such a machine hand the job to the hook.

The key is accepted in the user-global config only, like `cache.retention`: the hook is installed per machine, not per repository. Values are `on` and `off`; any other value is refused by `sdd config set`.

Rejected:
- Detecting the hook automatically, for example from the session's memory setup. It couples sdd to one host's plugin.
- Removing the served-once memory. Hosts without the hook would lose the savings.
- Keeping both mechanisms with no switch. The post-compaction stubs would remain.

Accepted cost: two saving mechanisms to document, and one switch read in each place that stubs.

Fulfilled when `sessions.token_saving: off` makes framing, instruction lanes, report schema and vocabulary serve in full on every call, `on` and an unset key keep today's stubs, an invalid value is refused, and tests cover both settings.
