A code repository whose committed `.sdd/config.yaml` sets `graph_repo` and also carries a project setting is refused with one line per misplaced key, each naming the file where that key belongs.

The rule itself stands: such a config holds only the pointer keys `graph_repo`, `graph_dir`, `skill_scope`, `supported_agents` and `hooks`, as item 2 of the fork compatibility directive (20261119-013237-d-cpt-fu4) keeps `graph_repo`. The refusal used to read "<path> sets dialogue, but a repository with graph_repo may set only …; move the rest into the project's own .sdd/ config". A consumer project whose committed config set `dialogue` beside `graph_repo` read that as an sdd bug: it named the rule, not where the key goes.

The place of each key comes from the placement rules sdd already applies to each config layer under the placement directive (20260708-184318-d-cpt-6cq), not from a second list:

- settings only a person's own config honors (`dialogue.mode`, `llm.debug`): `.sdd/config.local.yaml` or the user-global config, worded as "your own non-shared config";
- settings only the user-global config honors (the git limits, `sessions.retention`, `secrets.rules_update`): the user-global config;
- settings only the committed project config honors (`inbound`, `events`, `recheck`, repository properties): the graph repository's `.sdd/config.yaml`;
- every other setting: the graph repository's `.sdd/config.yaml` for the team, or a person's own config;
- retired keys name what replaced them, and unknown keys get a line saying sdd does not know them.

A key whose settings belong in different places gets one line per place, naming the dotted settings. Example: `<path> sets dialogue, which belongs only in your own non-shared config, .sdd/config.local.yaml or the user-global config, not in a repository with graph_repo`.

Rejected: one fixed sentence naming both the local and the graph repository's config for every key, because it is wrong for keys only one place honors and would send a person to a file that ignores the key; leaving the message as it was, because it reads as an sdd bug.

Settled: built as `b45ed74f`, `808aafb8` (graph-repository guide) and `458e4d6b` (the "your own non-shared config" wording) on `next/fix-key-placement`, merged into `fza-next`. The `internal/model` and `internal/meta` tests, vet and lint pass.
