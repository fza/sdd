With a user present, findings the deep verifier left without a change to the draft now reach the user before the entry is written: the capture returns to playback once, shows each such finding, and only then writes. Commit 0a03e791 on `pr/fix-capture-eval-defects`, with the configuration reference updated in 8252baa6, merged into `fza-fork` at b03c41f0, extends the guided capture order that 20261109-054916-s-cpt-mn7 built, where a delta confirm followed only a verifier change to the draft.

In guided captures the verifier runs after the user approves the playback. When it changed the draft, the delta confirm sent it back through assemble and playback; when it changed nothing, the entry was written at once, and findings the agent accepted without an edit, or that the verifier withdrew, reached the user only in the summary check, when the draft could no longer change.

What changed:

- The `checked` step goes to a new `deepReplay` step when the playback was confirmed and `deepNotesUnplayed` holds: the draft equals the one the verifier judged and unedited or withdrawn findings exist. `deepReplay` marks the replay done and returns to playback, so it happens once per verifier round.
- Playback lists those findings and tells the agent to show the user each one before they confirm or adjust the draft.
- After the replayed playback, a confirmation writes the entry when pre-flight and the verifier verdict still match the draft.

Proctests cover the replay after an unchanged draft, no replay after a changed draft, and the settle path for findings only the user can settle, which now passes through the replay. In a Codex capture run on the merged build where the verifier left a finding unedited, the agent showed it at the replayed playback before the write; the two other runs left no such finding.
