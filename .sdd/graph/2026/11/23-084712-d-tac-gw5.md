`resume_session` serves one line naming the session's most recent ended move and how it ended, for example `Last ended move: capture i_3 (abandoned)`; the list of running moves stays as it is. Without the line, a resume lists running moves only, and an agent resuming a session has no record of how its last move ended: in a live test, a fresh agent resuming a session reported an open catch-up as the last outcome and missed the capture the session had abandoned. The engine records the order in which instances end, live and on replay, so the order is rebuilt from the session event log with no copy kept beside it (20260914-113737-d-cpt-qst), and the resume serves the latest. The line applies the handover fidelity directive (20260719-124405-d-cpt-0tm) to ended moves, and extends the resume's state projection (20260719-190406-s-tac-y9a), which covers running moves only. Like that projection, the line is a field threaded by hand into the resume, the pattern the open question on generic state projection (20260719-135225-s-cpt-m8n) records; it settles no part of that question.

Rejected: leaving the resume as it is, because a resuming agent then reports a wrong last outcome. Accepted cost: a few dozen characters on every resume.

Settled: commit `491727215` on `fza-next` builds it, with engine and MCP tests and the coding-agents guide updated; nothing follows.
