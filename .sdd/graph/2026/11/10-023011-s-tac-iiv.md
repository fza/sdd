`sdd sync --pull` in a repository the user works in now fetches and merges the upstream with `git merge -m "sdd: merge <upstream>"` instead of `git pull --no-rebase`, whose merge message git cannot be told: commit `234846d0` on branch `pr/fix-pull-merge-message`, merged into `fza-fork` as `d2a5093d`. It closes the merge-message directive (20261110-021124-d-tac-non).

Criteria:
- A pull of diverged history writes a merge commit whose subject is `sdd: merge <upstream>`, the message the graph clone's pull writes.
- A pull that fast-forwards moves the branch to the upstream commit without a merge commit.
- The pull only merges, never rebases, and the dirty-tree refusal in the handler is unchanged. A conflict stays in the working tree for the user to resolve, as with `git pull`.
- A test fails when the merge commit gets any other message: it went red with the `sdd:` prefix stripped and is green on the shipped code.
