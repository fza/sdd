sdd fills missing entry titles on its own: every sync round and every session start run a background backfill that titles each untitled entry with the title model and commits the batch as one `sdd: summarize N entries` commit. Entries written by stock sdd, which has no title field, arrive untitled, and stock `sdd summarize` drops the title of any entry it rewrites, since it writes the frontmatter back from a model without one. Such entries list by their first summary sentence, the fallback the titles directive (20261028-005411-d-tac-tit) accepted, until someone runs `sdd summarize --all`, the backfill the titles release (20261030-162329-s-tac-9il) left out.

**Triggers.** The backfill is a step of every sync round, after the pull, and covers every untitled entry in the graph, not only those just pulled. Session start and session refresh start it too, whatever `sync.mode` says, so entries from a manual `git pull` and clones syncing by hand are covered.

**Background.** The session is served at once and the backfill runs beside it. It writes under the graph lock every mutation already takes, re-reads each entry under that lock and skips one that gained a title meanwhile, so it never races a capture's commit. A backfill already running in the checkout turns a second start into a no-op. A failure, such as no LLM configured, a failed title call or a failed commit, is recorded like a blocked sync and carried by the sync notice in the next response of that session; the entries stay untitled and the next trigger retries them.

**Batch.** One run titles at most 10 entries, newest first, so a long backlog of untitled entries never turns one session into a long run of title calls; the rest wait for a later trigger. As `sdd summarize --all` does, one run writes one commit covering every entry it titled, and an entry whose call failed does not hold back the others. Under `sync.mode: auto` the next sync round pushes it.

**Concurrency.** Two clones titling the same entry both change its title; the entry merge driver (20261030-085158-d-tac-vyt) keeps the value whose bytes sort first, so the clones converge.

Rejected: agents titling the untitled entries they read, through a read flag and a title move (each agent spends tokens per entry, and a new procedure and read field to own); waiting for the backfill at session start (the first session after arrival waits one title call per entry); titling on every graph read (side effects and LLM calls on pure read paths); sync pull alone (a manual `git pull` and clones syncing by hand stay untitled).

Accepted costs: a backlog larger than 10 entries takes several triggers to title; title calls repeat across clones that backfill the same arrivals; the first reads of a session can still show untitled entries; a clone without an LLM configured carries the failure notice until it configures one or the titles arrive from another clone.

## Acceptance criteria

- [ ] A sync round that pulls untitled entries titles them and commits them in one `sdd: summarize N entries` commit.
- [ ] With more than 10 untitled entries, one run titles the 10 newest and leaves the rest for a later trigger.
- [ ] A sync round titles untitled entries already in the graph, not only pulled ones.
- [ ] Session start runs the backfill under `sync.mode: manual` too, and serves the session without waiting for it.
- [ ] A backfill and a capture in one checkout both commit, and neither loses its write.
- [ ] An entry titled between the backfill's scan and its write keeps its title.
- [ ] A backfill failure reaches the next response of its session as the sync notice; the entries stay untitled and the next trigger retries them.
- [ ] One failed title call leaves the other titles committed.
- [ ] Two clones titling the same entry merge without a conflict through the entry merge driver.
