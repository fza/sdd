Hooks may be declared by the project, so a project can ship tooling that sdd drives: prose linters, rule checkers and notifiers committed in the repository instead of set up by each person. The previous design (20261109-005138-d-tac-i61) refused a `hooks` key in the committed `.sdd/config.yaml`; this decision replaces it, keeping its payload, findings contract, parallel runs and failure rules.

**Who declares them.** The user-global config, and in every repository of the project (in a `project_dir` layout the work repository and the project repository, 20261028-115146-s-tac-15i) both `.sdd/config.yaml` and `.sdd/config.local.yaml`. Hooks of all layers run together; their order (user-global, work repository, project repository; committed before local) only orders `sdd hooks`. Hook and confirmation changes reach a running `sdd serve` on its next call (20261109-003723-d-tac-s0k).

**What a hook runs.** `command` plus an `args` list, executed directly without a shell, in every layer. `command` names a file inside the declaring layer's hooks folder: `<repo>/.sdd/hooks/` for the project files, `~/.config/sdd/hooks/` for the user-global config. Absolute paths, `..` and PATH lookups are refused when the config resolves; an interpreter goes in the script's shebang. Spaces in a file name are escaped with a backslash, discouraged. The hooks folder is the working directory, and `args` and `files` paths resolve from it. Scripts of machine-local hooks go in `.sdd/hooks/local/`, which `sdd init` gitignores; a committed hook pointing into `local/` is refused.

**Confirmation.** A hook from a `.sdd/` file runs only once the person on the machine has confirmed its hash; user-global hooks never need one. The hash is SHA-256 over the hook's normalized config (event, resolved command, args, timeout, findings, files) and the contents of the command file, of every `args` entry naming an existing file, and of every file an optional `files` list (paths or globs) matches. sdd hashes on every run: about 12 ms for a 40 MB binary, microseconds for a script; any changed file asks again. Confirming happens by `sdd hooks trust` (each pending hook with its event, command, args, hashed files and the head of the command file, y/N), by `sdd init` offering pending hooks, and over MCP by elicitation: the call reaching an unconfirmed hook shows the person that prompt and continues on accept. A decline, a client without elicitation, or a headless run fails the call naming `sdd hooks trust`. `sdd hooks` lists every hook as confirmed, pending or changed.

**Store.** `~/.local/state/sdd/hooks/<repo-key>.json`, mode 0600, keyed by `repo_id`, else `local/<hash of the checkout path>`; clones of one repository share confirmations, safe since the hash pins the content. Each entry holds the hash, the confirmation time, event, command and the checkouts it was confirmed in. The 24h background cache pruning (20261101-131514-d-cpt-9ci) drops hashes no recorded checkout's config still declares and checkouts gone from disk.

**Events.** `<procedure>.<step>` fires when a step is done and accepts findings on a findings-channel step; `<procedure>.<step>.done` is its alias. `<procedure>.<step>.start` fires on arrival. `capture.verify.round` fires per verifier round, its payload carrying the round number, and `entry.written` after a publish. `*` matches a procedure or step. A failing `.start` hook holds its step: it runs again on every call, and the step's work, such as the pre-flight LLM call or the verifier launch, never runs before it passes. Every step of every shipped procedure raises its events; supported, documented and tested are only `capture.assemble`, `capture.guide`, `capture.preflight`, `capture.verify` (findings) and `entry.written`. A prose linter such as Vale belongs on `capture.assemble`, the first point with a full draft and before any paid call.

Rejected, with the reasoning: hooks only in personal layers (a project cannot ship its tooling); a shell command line (its hash cannot cover the script it calls); confirming only a committed `config.local.yaml` (a git check on every config read, and a script-written local file would run unasked); confirming the hash only (a changed script runs unasked); a stat cache before hashing (more code for a cost of milliseconds); a separate `trust_hooks` MCP tool (an extra failed call per new hook); confirming over a plain MCP tool (the agent could confirm without the person); keying the store by checkout (more prompts, no added safety); `entered`/`left` event names (bare step name reads as the common case); an allow-list of events (each new need a code change); a `.start` hook that stops one call only (the retry runs the costly work anyway).

Accepted costs: a cloned repository's code runs on this machine once its person confirms it; files a hook script loads without listing them in `files` change unconfirmed; the person's own Claude Code `Elicitation` hook can auto-accept; hooks written for `sh -c` stop working and are refused at config time; a hook on an unsupported event may break when a procedure's steps change.

## Acceptance criteria

- [ ] A hook in `.sdd/config.yaml` or `.sdd/config.local.yaml` of either repository of a `project_dir` layout runs only after its hash is confirmed; user-global hooks run unconfirmed.
- [ ] `command` outside the layer's hooks folder (absolute, `..`, PATH) is refused at config resolution; a committed hook into `local/` is refused; the command runs without a shell in its hooks folder.
- [ ] Changing the command file, an `args` file, a `files` match or the hook's config makes the hook pending again.
- [ ] `sdd hooks` lists hooks with their state; `sdd hooks trust` confirms pending ones; `sdd init` offers them.
- [ ] Over MCP, an unconfirmed hook prompts by elicitation and continues on accept; a decline or a client without elicitation fails the call naming `sdd hooks trust`.
- [ ] Confirmations live in `~/.local/state/sdd/hooks/<repo-key>.json` (0600); the 24h pruning drops hashes no longer declared.
- [ ] Events are named `<procedure>.<step>` (alias `.done`) and `<procedure>.<step>.start`; a failing `.start` hook keeps the step's work from running on every retry.
- [ ] `sdd init` gitignores `.sdd/hooks/local/`; `sdd config list` shows hooks from every layer; the configuration reference documents hooks.
