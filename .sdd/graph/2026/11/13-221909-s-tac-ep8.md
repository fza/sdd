In `json_object` structured-output mode, the gollm adapter now drops properties a closed response schema (`additionalProperties: false`) does not declare before it validates the answer. In Codex capture eval runs on `fza-fork` (two batches of three runs, builds `369cb6fe` with fixes and `719cfd12`), a model added a `confidence` property to the summary answer; the call failed with `unexpected additional properties ["confidence"]`, and the entry write failed with it. No caller reads undeclared properties, and missing required fields and wrong values still fail, so the validation sdd runs itself in this mode (20261028-130825-d-tac-fah) keeps guarding what callers use. The mode came with branch `pr/llm` (20261028-115840-s-tac-4xr).

Commit `2427caa4` on branch `pr/fix-eval-defects-2`, with the configuration reference updated in `293435b9`, merged into `fza-fork` at `1b04d01e`. Test `TestJSONObjectAnswerDropsUndeclaredProperties` failed before the change and passes after; breaking the guard made it fail, and the file was restored.

Open: no real-agent run has shown it yet. The eval login hit its usage limit until 2026-12-09, so no Codex rerun was possible.
