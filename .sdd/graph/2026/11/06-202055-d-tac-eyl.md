The sdd-owned graph clone of 20261106-201216-d-cpt-aim works through these mechanics: config keys with per-repository overrides, merge routing local to the clone, fixed rules for every conflict the clone can meet, a sticky transport protocol, and a guard against stock sdd writing into a pointing code repository. The probes behind each measured claim are in the [probe record](./06-202055-d-tac-eyl/graph-clone-probes.md) with their scripts.

**Keys.** A code repository names its graph repository with `graph_repo: <repo-id>`, the logical id `host/path` without scheme, user or `.git`. The writing gate is `connected.write` in the layered config (global, project, local), the receiving gate `inbound.accept` in the graph's committed `.sdd/config.yaml` only; both default to false. Overrides are maps keyed by repository id, `connected.repos.<repo-id>.write` and `inbound.repos.<repo-id>.accept`. Layers merge per repository id, and after the merge a repository's own value beats the catch-all. `sdd config set --repo <repo-id> connected.write true` sets an override, since dotted key paths cannot address an id holding dots. When a code repository sets both `graph_repo` and `project_dir`, this sdd follows `graph_repo` and ignores `project_dir` wherever it is set; older fork builds keep following `project_dir`, so one config serves both during a transition.

**Clone upkeep.** Before every operation on its clone, sdd restores tracked files, removes untracked files, and drops every unpushed commit it did not make: it appends the hash of each commit it creates to `.git/sdd-commits`, and before a push resets the branch past any commit in `origin/<branch>..HEAD` missing from that list, replaying its own commits on top. All of this is silent. The marker `SDD_MANAGED__EDITS_ARE_DISCARDED.md` at the clone's root says so; its `/SDD_MANAGED__EDITS_ARE_DISCARDED.md` line in `.git/info/exclude` keeps it out of git, and sdd restores both silently whenever it finds either missing. `sdd repo path <repo-id>` prints the clone's path.

**Merge routing.** In its clone sdd keeps the line `<graph_dir>/[0-9][0-9][0-9][0-9]/[0-9][0-9]/[0-9][0-9]-*.md merge=sdd-entry` last in `.git/info/attributes`, rewriting it when `graph_dir` changes, and passes the driver on each of its own git calls with `-c merge.sdd-entry.driver=…`. The clone's `.git/config` holds no driver, and no `.gitattributes` is written. `.git/info/attributes` outranks committed `.gitattributes` files at every depth, and within the file the later line wins, so the routing holds whatever the repository commits. Other markdown files stay with git's own merge. The driver itself follows 20261030-085158-d-tac-vyt; that directive's `.gitattributes` and `.git/config` setup stays for graphs living in a code repository or a `project_dir` folder. It rejected `.git/info/attributes` because nothing in the repository shows the driver; in a clone only sdd works in, nobody needs to see it.

**Conflicts.** sdd's own unpushed commits contain only new files and changes to `title` and `summary`, so a remote change to any other line arrives one-sided and merges clean, and two people's clashing hand edits meet in their own clones, never in sdd's. Three cases remain:

- An entry deleted upstream while sdd changed its `title` or `summary`: the deletion wins, the local change is dropped, and a notice names the entry and the deleting commit. An upstream rename merges clean with the change landing at the new path.
- `.sdd/config.yaml` changed on both sides: a second driver, `sdd-config`, routed the same way, merges per key. A key changed on one side is taken; `dependencies` merges as a set of additions and removals from both sides; a scalar changed on both sides takes the upstream value with a notice naming the key. Comments and layout follow upstream.
- The remote branch rewritten by force push, detected when the fetched tip no longer contains the previously fetched one: sdd moves its branch to the new tip, locally and never by force push. `title` and `summary` changes are re-derived for entries that still exist and dropped for the rest. Unpushed new entries and attachments are set aside. An entry that supersedes another or carries a `refines` ref, whose refs resolve and whose mechanical pre-flight is clean, is re-added and pushed automatically. Every other set-aside entry reaches an agent through the claimed blocked-sync notice of 20261028-201909-d-tac-fxp: the agent re-captures it with the old entry as draft, or discards it with a reason. A notice names the old and new tip.

**Protocol.** The clone carries two remotes, `ssh` (`git@<host>:<path>.git`) and `https` (`https://<host>/<path>.git`), both derived from the repository id. The first choice follows the code repository's origin when it is on the same host, otherwise ssh. The clone's `.git/config` records the protocol that last worked, `sdd.remote`, and since when, `sdd.remoteSince`. sdd uses the recorded one first and switches only after a failure, or, after at least 24 hours on https, by trying ssh first once. Local repositories that disagree never switch it. An ssh attempt never prompts or hangs: `BatchMode=yes`, `ConnectTimeout=5`, `GIT_TERMINAL_PROMPT=0`.

**Init.** `sdd init` asks where the graph lives: this repository, a repository of its own on a remote, or a local folder without a remote. For a remote it asks the address, clones it into sdd's clone, sets up `.sdd/` there when the repository is empty and pushes, then writes `graph_repo`, the guard below and nothing else into the code repository in one commit. The local-folder choice keeps today's `project_dir` flow. `--graph-repo <url>` gives the same without the prompt.

**Stock guard.** A pointing code repository also commits `.sdd/GRAPH-ELSEWHERE.md`, naming the graph repository and how to work in it, and sets `graph_dir: .sdd/GRAPH-ELSEWHERE.md`; this sdd ignores `graph_dir` beside a pointer. Stock sdd, which knows neither pointer, then fails every capture with `creating directories: mkdir …/.sdd/GRAPH-ELSEWHERE.md: not a directory` and writes nothing, instead of growing a second graph in the code repository. Its reads still exit 0 on an empty graph, with only an `ignoring unknown config key` warning. Locking stock users out of the code repository against letting them grow an unseen graph there is a trade-off this fork could not settle; upstream maintainers have to decide it again.

Rejected alternatives:

- `core.attributesFile` per call. Any committed `.gitattributes` outranks it.
- A crafted `--attr-source` tree. It ignores every attribute file in the working tree, loses to `.git/info/attributes`, costs about 15 ms a call, and a tree removed by garbage collection silently yields no attributes at exit 0.
- The driver in the clone's `.git/config`. A stored command naming the sdd binary breaks merges once sdd moves.
- On deletion upstream, restoring the entry, which overrides a pushed commit and makes clones fight over it; on any of the three cases, stopping sync, which brings back the agent round-trip.
- For `config.yaml`, taking the upstream file and replaying sdd's command, which makes every config-writing command record its intent; or upstream winning whole, which silently loses a `sdd repo add`.
- After a force push, merging the histories, which undoes the rewrite on every clone; or re-adding every set-aside entry once its checks pass, which never judges whether a plain new entry is still accurate.
- Pushing a hand commit like any other, which lets an entry bypass every check.
- Probing ssh and https on every connect, which costs a timeout per call on unpredictable networks; retrying ssh after 7 days or only after failure, which leaves a clone on https long after ssh works again.
- Asking for the clone address once, which blocks background sync and the MCP server; flags only, or a path prompt deriving the id, which hides the new layout or keeps the hand-made clone.
- With both pointers set, a local `project_dir` winning, which brings back writes into a user folder; or refusing both, which blocks a team running two fork versions.
- Pointing `graph_dir` at the sibling folder, which leaves stock captures half done; or no guard, which lets stock sdd grow a second graph silently.

Accepted costs: a hand commit or edit in the sdd clone is lost without notice; a `git pull` run by hand in a person's own clone merges entries without the driver; a set-aside entry's content is not judged when its checks pass automatically; one connect timeout per day while ssh stays broken; local comment edits in `config.yaml` are lost on a clash; init needs the graph repository to exist on the remote and pushes to it.

## Acceptance criteria

- [ ] With `graph_repo` set and no clone, the first command needing the graph clones it blobless with `.sdd/` as cone, and adds `graph_dir` to the cone when it lies outside `.sdd/`.
- [ ] `connected.write` and `inbound.accept` default to false; a capture into a connected graph is refused unless both resolve to true for the pair; a repository override beats the catch-all after merging layers.
- [ ] `sdd config set --repo <repo-id> connected.write true` writes `connected.repos.<repo-id>.write`; `inbound.accept` set outside the committed project config is refused on write.
- [ ] An uncommitted edit, an untracked file and an unrecorded commit in the sdd clone are gone after the next operation and never reach the remote; the marker and its exclude line are present after every operation.
- [ ] Two clones changing `title` of one entry merge through `sdd-entry` without a conflict, with a committed `.gitattributes` setting another merge driver for `*.md`.
- [ ] Each of the three conflict cases resolves without stopping sync and prints the notice named above.
- [ ] After a force push, a set-aside `refines` entry with resolving refs is re-added and pushed; a plain new entry reaches the claiming agent's notice instead.
- [ ] A recorded `https` protocol is used first; after 24 hours one ssh attempt runs and is recorded on success.
- [ ] Stock sdd in a code repository written by `sdd init` with a remote graph fails `sdd new` and writes nothing.
- [ ] `project_dir` setups keep working unchanged; with both pointers set, this sdd uses the clone.
