In an sdd-owned partial clone, every merge that brings changed or new files makes git fetch their contents from the remote by itself, and that connection runs outside the per-machine git gate (20261107-095427-d-tac-yux), so the hourly buckets never count it.

Measured on a blobless sparse clone: a merge that brings changed or new files starts exactly one batched promisor fetch, one connection; `git log`, `git show` of an old revision, `git log -p` and `git status` start none. In the worst case, where every sync round brings changes, the real connection count of productive rounds is twice what the record shows.

Expected: every connection sdd causes counts against the host's bucket. One way is to run the merge inside the fetch admission with the gate's trace environment, so the trace counts the promisor fetch the same way it counts the fetch itself.
