Every surface now reaches only a project's directly declared dependencies, and refs a dependency holds into projects further out resolve from existing clones with one fetch on a miss; built on `pr/feat-direct-deps` and merged into `fza-fork` at e169d352, this completes 20261113-235859-d-cpt-l3m.

## Built

- 29f91c40: reads, moves, export, lint, the dependency refresh and `sdd repo sync` stop walking the transitive closure; a project or repository outside the direct set is refused with "X is not a direct dependency of HOME".
- 17d56e7e: a ref into a project further out resolves from that project's existing clone; on a miss one fetch runs, and inside the cooldown it may spend a credit; misses are recorded in `ref-misses.json` beside `remotes.json`, and a recorded miss allows the next fetch once the clone moved or after 24 hours.
- fa00fc93: docs for the direct-dependency horizon and refs further out.
- f54f7e74: lint fixes.

## Acceptance criteria

- Direct dependencies only on every listed surface, a move into an undeclared project refused, no closure walk left: met (29f91c40).
- A further-out ref resolved from the clone with the clone's age and no sync: met (17d56e7e).
- One fetch on a miss through the git gate, waiting at most `read_wait`: met (17d56e7e).
- A credit inside the cooldown, else "fetch deferred": met (17d56e7e), tested only at the handler level, because the git gate of the CLI and server tests always admits local remotes.
- Unresolved refs with a marker, a short reason and typed warnings `not-connected`, `missing-after-fetch` and `fetch-deferred`: met (17d56e7e) with the deviation below; each warning carries its kind, who must act and its time.
- Recorded misses and the retry rule: met (17d56e7e).
- MCP server instructions and tool descriptions name direct dependencies only: met (29f91c40).

## Deviation from the decision

The decision reuses the unavailable marker of 20261029-135448-d-cpt-olh, but that marker is built nowhere. The existing `[unresolved: repo X]` marker of 20260707-175137-d-tac-i6f is extended to `[unresolved: repo X: <reason>]` instead, with the typed warnings beside it.

## Choices the decision left open

- "Fetch deferred" covers a timeout and a skipped or failed fetch alike.
- Only refs a dependency holds directly resolve further out; a further-out clone does not resolve its own refs.
- `sdd repo sync` with no repository named fails in a project that declares no dependencies.
- A clone's age comes from the modification time of its `FETCH_HEAD`.
- Repositories further out get no lease renewal.

## The gap of the unreachable second-level member

The narrowing removes the case of 20261028-155600-s-tac-4mz in which an uncloned second-level member fails every all-repos read: `TestServeAllReposIgnoresUnreachableSecondLevel` reads around such a member in `sdd serve` and the CLI. The gap stays open. Its claim is that the CLI and `sdd serve` answer an unavailable member differently, and for a direct dependency they still do: serve's search and view fail when a selected direct dependency is unavailable, while CLI search skips it with a warning. The per-reference rules of 20261029-135448-d-cpt-olh that settle that side are not built.
