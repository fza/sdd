A CLI read or write with `--session` breaks the MCP server holding the same dialogue session. The grounding build (20261109-054916-s-cpt-mn7) lets `sdd show`, `search`, `view`, `gather`, `dismiss` and `new` join a session by its handle, and each such call appends to the stored session log; the server, still holding the session in memory at the older version, fails its next append with `session_conflict` and asks the agent to reorient with `resume_session`. The builder reported this from the code path; no live run of a CLI call beside a running serve confirmed it.

Expected, from the grounding directive (20261109-004506-d-cpt-udz): enforcement lives in the engine and application layer so CLI and MCP get it alike, which an agent mixing both surfaces in one dialogue can use only if a call on one surface leaves the other able to continue.
