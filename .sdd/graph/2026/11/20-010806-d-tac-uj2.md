Point 17 of the fork compatibility directive (20261119-013237-d-cpt-fu4) wrongly lists `dialogue` among the fork-only keys that stay in the committed `.sdd/config.yaml`: the fork itself ignores `dialogue.mode` in any committed config, with a warning, and reads it only from a person's own config, `.sdd/config.local.yaml` or the user-global config.

`secrets` in the same list has the same fault: its only setting, `secrets.rules_update`, is read from the user-global config alone, and a committed value is ignored with a warning. The rest of point 17 and of the directive stands. The cost point 17 names for stock, one `ignoring unknown config key` line per fork-only key on every command, does not arise for `dialogue`, because no team-wide value exists to keep in a committed config. A committed `dialogue` block is a placement mistake: beside `graph_repo` it is refused with the file where it belongs (20261119-193028-d-tac-2ap), and elsewhere it is ignored with a warning.

Rejected: superseding the whole directive with point 17 corrected, because it repeats every other point unchanged; leaving point 17 as written, because a reader then puts the mode into a shared config, where sdd does not use it and only warns, as happened in a consumer project.

Settled: the code already behaves this way (`internal/model/config.go`, `HonoredCommitted` and the per-person ignore reason); only the graph record changes.
