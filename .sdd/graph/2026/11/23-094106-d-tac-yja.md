An answer given while no check question is open leaves the held set standing: the call serves no repeated text as a short pointer on the strength of that answer, and the next response's questions decide which texts come as pointers. A response that yields no question, as a wait for the deep verifier often does, still takes `lost` as its answer under the served rule "saw no question, answer lost", and that `lost` emptied the held set. Each wait poll emptied it again, so the step after the wait came back with every instruction lane and the full report schema. With no question open an answer disproves nothing, and a call without a right answer serves no pointer by it, so keeping the held set lets no pointer reach text the agent lost. This refines the held-set rule of the linked-sessions plan (20261122-105026-d-tac-wl5) and refines the credit directive (20261123-092551-d-tac-ave), whose rule that `lost` credits nothing and empties the held set now holds only while a question is open.

Settled: commit `f8bb4e61c` on `fza-next` builds it in `BeginCall` (`internal/engine/pieces.go`), with a test and the coding-agents guide updated; nothing follows.
