A project's config cannot switch off the search by meaning that the user-global config's `embedding` block sets, and this stays so. The overlay merges each `embedding` field of the project config over the global one only where the project sets it (`mergeEmbeddingConfig` in `internal/model/config.go`), so an empty project block keeps the global embedder; stock sdd, upstream `main`, merges the same way.

The embedding config is set once per user: a single embedder indexes every connected repo, so a cross-graph search fuses comparable scores into one ranked list (20260606-003344-d-cpt-s6q), and the placement rule files embedding under user and machine preferences, not under the repository's own facts (20260708-184318-d-cpt-6cq). A project block can still override single fields such as provider or model, a choice the comment on `EmbeddingConfig` in `internal/model/config.go` calls possible but with consequences, while cross-repo search keeps the user-global embedder (`crossRepoEmbedder` in `internal/cliapp/search.go`). A switch-off per project would give one graph a different search than the others its user reads beside it.

Rejected: a new `embedding.provider: none` value a project sets for keyword-only search, since it adds a value to the shared schema, its docs and an upstream pull request, and stock sdd may refuse the value. Accepted cost: on a machine whose user config sets an embedding model, a project cannot get keyword-only search.

Settled: the code stays as it is; nothing follows.
