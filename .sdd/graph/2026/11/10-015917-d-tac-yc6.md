Every config setting with a fixed set of values declares that set once, on its type in the config model, and `sdd config set` refuses any other value, naming the allowed ones; a test walks every config schema and fails when such a setting declares no set, so no setting, existing or added later, goes without the check. This answers the gap where `sdd config set` wrote `verify.mode bogus` and similar values that fail only later (20261110-015054-s-tac-k8y) and completes the write-side schema enforcement of 20260921-174543-d-cpt-tv9 for values.

The rule is one sentence: a value sdd would refuse or read past later must already be refused by `sdd config set`.

- Fixed-value settings (`verify.mode`, `verify.runner`, `verify.skip`, `verify.claude.effort`, `dialogue.mode`, `llm.structured_output` and the other named string types with a closed set) answer their allowed values from the type itself. Load, use and `sdd config set` read the same list, so they cannot drift apart.
- `sdd config set` also runs the cross-file checks loading runs (a machine-local `verify.mode` may only raise what the shared files set, a `verify.driver` is refused in the committed file) on the files as they would be after the write, judging only the key being set, as 20260921-174543-d-cpt-tv9 requires: a foreign key elsewhere in the file never blocks a write.
- An empty value is refused for every key; `sdd config unset` removes a key. This covers an empty `participant`.
- Free-text settings with no fixed set (`language`, `participant`, model names, URLs) are not judged beyond the empty-value rule.
- Loading stays tolerant as 20260921-174543-d-cpt-tv9 sets it.

Rejected: making `sdd config set` run the full config load and refuse what loading refuses (loading judges only the verify values today, so `llm.structured_output` and others would stay open); adding the verify checks to `sdd config set` alone (every new setting would again need a hand-written check).

## Acceptance criteria

- [ ] `sdd config set` refuses a value outside the declared set for every fixed-value setting, naming the allowed values, and writes nothing.
- [ ] A machine-local `verify.mode` lower than the shared files resolve to is refused on write with the same message loading gives.
- [ ] An empty value is refused for every key.
- [ ] A test fails when a named string type in a config schema declares neither its allowed values nor that it is free text (such as `RepoID`); it was seen failing once on a type with the declaration removed.
- [ ] A config file holding an unknown key still accepts a valid write to another key.
