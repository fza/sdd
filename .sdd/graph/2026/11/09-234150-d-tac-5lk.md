A re-run `sdd init` that commits names in its subject what it changed: `sdd: init refresh: <surfaces>`, the surfaces taken from the committed paths in the order skills, config, ignore files, MCP registration, settings, and `other files` for a path matching none. A first run keeps `sdd: init .sdd/ metadata directory`.

Every commit after the first run read `sdd: refresh installed skills and metadata`, also when init only wrote `verify.mode` or an ignore line, so the log misnamed config-only runs. Naming the surfaces lets a reader of the log tell what moved without opening the commit.

Rejected, with the reasoning: one neutral subject such as `sdd: refresh sdd setup` (the log still says nothing about what changed); keeping the fixed subject (config-only runs stay misnamed).

Accepted cost: a pure path-to-surface mapping in `internal/model` with its tests, kept in step with the surfaces init writes.

## Acceptance criteria

- [ ] A re-run that changes only config commits `sdd: init refresh: config`.
- [ ] A re-run that changes skills and an ignore file commits `sdd: init refresh: skills, ignore files`.
- [ ] A path matching no surface adds `other files`; a first run keeps its subject.
