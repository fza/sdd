The deep verifier is to read the project's git history through sdd itself, the same way under every runner, and a finding about a draft claim it cannot check is to reach the drafter instead of being refused.

The verify procedure (20261109-010000-d-prc-vfy) tells the verifier it can check history through read-only git, but of the runners whose tools sdd sets, only the headless `claude` round has git (a `driver` runner's tools are its own command's): `Bash(git log:*)`, `Bash(git show:*)`, `Bash(git diff:*)` and `Bash(git blame:*)` in `internal/delegatelaunch/delegatelaunch.go`. The `sdd_delegate` subagent has no shell in Claude Code and none in Codex (`shell_tool = false`), so it cannot read stock `main` or any other revision. The prefix rules are not read-only either: `git log -p --output=<file>` writes a file. Every evidence finding must cite a source (20261117-134258-s-tac-x4u), unless only the person can settle it (20261113-213512-s-tac-mz1). A finding that a draft claim names no source, and that the verifier could not check, has nothing to cite: sdd refuses it with "an evidence finding names its sources", and the repaired finding cites a source that proves nothing. The refusal also numbers findings from 0, so "item 2" is `f3`.

## Decision

- `read_git` is an sdd MCP read tool that takes the session handle, like every read. Its operations: `file`, a path's content at a revision, paged within the calling host's result bound; `log`, the commits touching a path or in a revision range, capped, in a fixed format; `commit`, one commit's message and changed files; `diff`, between two revisions, optionally for one path. sdd builds each git command itself and takes no raw arguments. A revision must resolve to a commit and may not begin with `-`; a path stays inside the checkout; git runs with `--no-ext-diff`, `--no-textconv` and no pager, detached from any terminal, as 20261029-130137-s-tac-8bf asks of every Git call sdd starts. The tool reads the session project's checkout; a project without a checkout gets an answer that the tool is not available.
- A file source takes an optional `rev`, and sdd checks its quote against the file at that revision.
- An evidence finding not marked as the person's may come without sources when it carries no edits. It names the claim that lacks a source in a pointer whose quote sdd finds in the draft, and the drafter adds one or contests it. Accepted cost: such a finding may still have nothing behind it beyond the claim it points at, and the drafter weighs it.
- The headless `claude` round loses `Bash` from its tool list and its Bash git rules. Every runner reads history through `read_git`, and the verify procedure names that tool instead of git commands.
- A refused report numbers its array items from 1, and the source refusal names the allowed forms: sources, `owner: true`, or no edits.

Rejected: keeping the Bash git rules beside `read_git`, since that keeps two routes and the prefix rules still write files; offering only a file at a revision, since the verifier then cannot check a claim about history or about what a commit changed; a shell for the subagent, since no harness-neutral way limits a shell to read-only commands.

Out of scope: any write operation; repositories other than the session project's checkout, connected repositories included.

## Layers

The split follows the CQRS planning contract. `read_git` only reads, so it adds a query and no command.

- **Model** (`internal/model`): the operation, revision and path inputs with their checks (no leading `-`, a path inside the checkout), the answer types and their page bound; `DeepSource` gains `rev`, and `DeepFinding` validation admits an evidence finding without sources and without edits.
- **Query and finder** (`internal/query`, `internal/finders`): one query per operation carries the read intent; the finder builds the git command and runs it in the project checkout the handle names.
- **MCP shell** (`pkg/mcpapp`): the `read_git` tool parses its arguments, runs the query and pages the answer for the calling host.

## Acceptance criteria

- [ ] Under the subagent runner in Claude Code and in Codex, and under the headless `claude` runner, the verifier reads a file at `main`, a path's log, a commit and a diff through `read_git`.
- [ ] `read_git` refuses a revision beginning with `-`, a revision that resolves to no commit, and a path outside the checkout.
- [ ] No input to `read_git` makes git write a file or run an external diff or textconv program.
- [ ] A `read_git` answer stays within the calling host's result bound, with further pages beyond it.
- [ ] A session whose project has no checkout gets an answer that `read_git` is not available.
- [ ] A file source with `rev` passes when its quote is in the file at that revision, and is refused when it is not.
- [ ] An evidence finding without sources and without edits, with a pointer quoting the draft claim, reaches the drafter; one without sources but with edits, or without such a pointer, is refused.
- [ ] The headless `claude` round's tool list holds no `Bash` and its tool rules hold no Bash git rule.
- [ ] A refused report names its array items from 1, and the source refusal names the three allowed forms.
- [ ] The verify procedure names `read_git` and the finding that asks for a source.
- [ ] The coding-agents guide, `website/src/content/docs/guides/working-with-coding-agents.md`, names `read_git` and the finding that asks for a source.
