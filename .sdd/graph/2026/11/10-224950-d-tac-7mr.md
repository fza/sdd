`verify.kinds.<kind>` sets the verify mode for drafts of one entry kind, so a project checks the kinds whose claims a deep check can test more strictly and the rest more cheaply. A named kind gets exactly its mode, stricter or looser than `verify.mode`; an unnamed kind gets `verify.mode` from the unified `verify` block (20261109-222220-d-tac-4ev). While `verify.kinds` names no kind at all, `done`, `actor`, `role`, `focus`, `annotation`, `insight`, `question`, `activity` and `procedure` are checked at most at `prose`: they make no claim a deep check can test, or a deep run costs more than it finds. Naming any kind turns this default off for every kind, so each unnamed kind then gets `verify.mode` uncapped. Kinds merge one by one across the config layers, and `config.local.yaml` may only raise each kind's mode, as it may only raise `verify.mode`. The deep exchange, the verifier chosen and the grounding requirement follow the mode of the draft's kind, as does the deep capture's skip of the LLM pre-flight (20261110-164357-d-tac-h1e).

The drafting agent picks the kind, so a draft could dodge a stricter check by taking a looser kind. A draft whose kind is checked more loosely than another kind, whether through the default `prose` cap or through a mode named under `verify.kinds`, therefore gets a kind-fit check in pre-flight. With `verify.mode: prose` and `verify.kinds.directive: deep`, a draft labelled `done` gets the check against `directive`. The check tests whether the body answers its kind's question or that of a kind checked more strictly, and a misfit is a high `kind-fit` finding that blocks the write until the draft is relabelled, its body is rewritten to fit its kind, or the user overrides it.

Rejected: one mode for every kind, since a deep run on a done or an actor costs more than it finds. Accepted cost: one more config key, and one more pre-flight rubric for drafts of looser kinds.
