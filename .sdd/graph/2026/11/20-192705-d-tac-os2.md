`sdd serve` kills the `claude` CLI processes it started when it shuts down, and background ranking stops with the server and keeps its scores across a restart. Commit c010d7d9 on `next/fix-child-shutdown` builds both, merged into `fza-next` with d686f17c.

## What was wrong

Each `claude` CLI call runs in its own process group. 20261119-105440-s-tac-5et kills that group when the call's context is cancelled, which covers only a call on a context the stop signal ends, such as a background calibration request, and only while the server still runs. Other groups outlived the server:

- The background ranking passes of 20261118-162927-s-tac-pq5 ran on a context detached from cancellation. A stop signal never ended them, and shutdown did not wait for them.
- A title backfill runs detached for up to 10 minutes and may call `claude`.
- A server that exited, or was killed after a grace period, cancelled nothing more, so the groups still running stayed.

Ranking scores reached the session log only when the deep verifier's reading was built and collected them, so a restart lost the work of a finished pass. A consumer project that restarts the server after each sdd upgrade had `claude` processes left over.

## What holds

- `claude.Children` in `internal/llm/claude/children.go` tracks the running calls of one process by their process groups. It rides on the context. Each call is started and registered under one lock. `Kill` sends SIGKILL to every tracked group, refuses each later call, and returns once every killed call returned or its own context ended.
- `ApplicationOptions.OnShutdown` is a hook that application shutdown runs. Shutdown starts no more background work, ends the context the ranking passes run on, calls the hook, then waits for the background work, the ranking passes included.
- `sdd serve` passes the kill as that hook and runs it once more as serve returns. Each kill waits at most 3 seconds for the killed calls. A stop signal, the end of the stdio connection and HTTP shutdown all go through application shutdown.
- The kill runs before the wait, because the wait covers a title backfill that may itself be waiting on `claude`.
- A ranking pass that finished, or that shutdown cut short, appends what it scored to the session log as a `workflow_ranking_scores` event. The next ranking plan of that instance reads those scores back for the same judge and draft text, so a restarted server does not score those pairs again. When the deep verifier's reading is built, the scores a pass recorded and the scores collected then are credited to the capture together in one read event, so no score is credited twice.

The scores go to the session log because 20260914-113737-d-cpt-qst makes that log the one source of session state. The record is not an engine event. A pass ends outside the call that drives its instance, and an engine read event written on that instance from outside would make that call's next append fail as changed elsewhere.

## Accepted costs

- The record's append retries twice when another call of the session appended first. A record that still fails is logged, and the next server scores those pairs again.
- A failed kill is logged, not returned, so a cancelled serve still reports only that it was cancelled.

## Rejected

- The kill alone. A restart would still discard finished ranking work.
- Leaving both as they were. A project that restarts the server would have to find and kill the leftover process groups itself.

## Not covered

Nothing follows from this decision. Both parts are built and merged, and the limits below are known and carry no commitment.

- The codex runner starts its CLI without a process group and without tracking.
- `sdd delegate-round` passes no shutdown hook and tracks no calls, so its `claude` processes are not killed this way.
- The stdio server's shutdown waits for background work without a time limit.
- A server killed with SIGKILL runs no shutdown.
- No test fails when serve's own kill hook is removed. The process tests pass no shutdown hook and track no calls: their shutdown ends a hanging CLI by ending the ranking pass's context, so the cancelled call kills its own process group as in 20261119-105440-s-tac-5et. Only the unit test exercises `Children.Kill`.

## Proof

Two process tests failed before the change. In `TestCaptureDeep_ShutdownEndsABackgroundRankingsCLI` a hanging CLI outlived shutdown. In `TestCaptureDeep_ABackgroundRankingOutlivesARestart` the log held no ranking record after a restart. The unit test `TestKillEndsTheCallsOfItsChildren` covers the group kill and the refused later call. The full isolated suite passes.
