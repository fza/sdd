`sdd config` reports `sessions.token_saving` as effective only from the user-global config or its default: commit `25cecb0e` on `pr/feat-mcp-objects`, merged into `fza-fork` as `535e642b`.

Before it, a value in `config.local.yaml` showed as the effective setting in `sdd config` and `sdd config get`, although `sdd serve` reads the key from the global config alone (20261101-164201-d-tac-sj4, implemented by 20261101-170354-s-tac-f0g). A tool deciding from `sdd config get sessions.token_saving` would then have read `off` where serve stays on. The effective-config overlay now skips per-repo layers for global-only keys; a per-repo value is still reported as ignored. A test covering both layers was red against the old code and passes now.
