A capture body staged from a file by path is now read again before its playback is confirmed. `WorkflowSession.StageAttachmentFrom` keeps the source path, recorded in the staged-blob event and restored on resume. At a playback confirm, a changed file is staged again, the draft takes the edit, and the confirm plays the change back instead of confirming the older copy. A file gone since leaves the staged copy standing. The MCP `stage_attachment` tool stages a path through it, and its description says so. This extends the staged-file bodies of 20261030-154336-s-tac-me6, whose playback confirm binds to the staged file. Users edit the draft file in place while answering; before this, agents had to compare the file's hash with the staged copy themselves.

Commit `01e89eab`, with the formatting fix `c0f78af4`, on branch `pr/fix-eval-defects-2`, merged into `fza-fork` at `1b04d01e`. Test `TestCapture_ConfirmReadsAStagedFileAgain` covers the re-read, including after a resume; it failed before the change and passes after, breaking the re-read in the code made it fail, and the code was restored.
