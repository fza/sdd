Unknown verify config values are ignored on read, closing 20261110-215919-d-tac-yvq: since commit 1042234d on `fza-fork`, an unknown `verify.mode`, `verify.skip`, `verify.runner` or `verify.claude.effort` value falls back to the layer below or the default instead of failing every command.

`KnownValues` in `internal/model/verifier.go` drops each unknown value before the layers merge, and `ignoredVerifyValues` reports it, so the existing `ignoring config setting` warning names the key, the file and the allowed values. Writes still refuse such a value. Commit a08a563c, which added `verify.kinds`, applies the same rule there: an unknown entry kind or an unknown mode under `verify.kinds` is reported and left out.

Tests in `internal/model/verifier_test.go` and `internal/meta/verify_config_test.go` cover the fallback per layer, the warning report and the write refusal; they pass on `fza-fork`.
