The eval-codex skill drives Claude Code as well as Codex: `claude_driver.py` (commit dfc829a6, merged into the fork line on 2026-11-14) runs one headless `claude -p` per user turn against a scratch SDD repository, resuming the same Claude session by its id, so the turn-by-turn evaluation the skill runs with a Codex agent runs with Claude Code too.

Each run keeps its state beside the repository: the session id, each turn's output stream and a Claude config directory of its own, so transcripts, project list and memory stay out of the user's `~/.claude`. The user's login is shared, never copied. Only project settings load, so the repository's skills and the `sdd_delegate` agent apply and the user's own instructions, hooks and plugins do not. The only MCP server is the chosen `sdd serve`, `AskUserQuestion` is off so the agent asks in its final message, and background work the agent starts ends with its turn. The driver prints what the sdd tools returned per turn, subagent calls included, and lists the session's transcript files for measurement.

An earlier outer evaluation (20261029-212753-s-tac-5ab) had to drive Claude Code by hand, because the skill's driver then expected Codex.
