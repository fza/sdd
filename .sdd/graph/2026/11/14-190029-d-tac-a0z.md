sdd serves the hold-next line of 20261114-121534-d-tac-qdb, and the instructions to prove exactly its tags, only to agents running an Opus or Fable model, learned from the model the agent reports; every other agent gets the rule of 20261112-075604-d-tac-t4r from before hold-next, that it proves every tag it still sees, with no hold-next line and without the 20-newest reminder of 20261113-121039-d-tac-ca2. This replaces 20261114-181553-d-tac-xvr, which gated by the MCP client name: that name is `claude-code` for every Claude model, and Sonnet, sdd's default, skips the proofs as Codex does (20261114-185019-s-tac-8aa).

**How sdd learns the model.** `start_session` and `resume_session` take an optional `model` field, the model the agent runs on as its harness names it; the field's description asks the agent to fill it. A model name holding "opus" or "fable", in any case, gets the line; any other, or none, gets the every-tag rule. A verifier subagent's model is the one sdd named in its own dispatch, unless the subagent reports one. sdd stores the model per agent context, so a main agent and each verifier keep their own; later calls read it from there. A resume that reports a model replaces the stored one; a resume without one keeps the last. Over HTTP this works as over stdio, since the report travels in the tool call.

**Rejected.** Gating by proof behaviour, a context getting the line while it sends valid proofs: it is not limited to Opus, and Sonnet main agents that prove early and then stop would flip it on and off. Hooks writing each session's model to a file sdd reads: hooks were dropped as a mechanism for anchor proofs, and it works only where they are installed. The MCP handshake and tool calls carry no model name, so the agent's own report is the only source.

**Measured on Opus.** The fourth criterion of 20261114-121534-d-tac-qdb is judged on three deep-verifier captures with an Opus main agent on the gated build, against three on the build before hold-next; Sonnet and Codex agents no longer get the line, so runs with them would measure only the every-tag rule.

**Accepted costs.** One optional field on two tools; sdd trusts the agent's word on its model; an agent that reports no model gets the every-tag rule; verifier subagents on the default `sonnet` model, or on Codex with no model named, get the every-tag rule too, although Claude and Codex verifier subagents sent most proofs in the runs of 20261114-185019-s-tac-8aa; an agent of another model that resumes without reporting one keeps the previous model's rule.

## Fulfilled when

- An agent reporting an Opus or Fable model gets the hold-next line and its proof instructions; one reporting another model or none gets the every-tag rule and no line; a verifier dispatched with an Opus model gets the line without reporting.
- A resume reporting a model switches that agent context's guide; a resume without one keeps it.
- Three Opus deep-verifier captures on the gated build meet the fourth criterion of 20261114-121534-d-tac-qdb against three on the build before hold-next.
