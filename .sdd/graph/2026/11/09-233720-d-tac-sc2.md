When `sdd init` finds nothing to change, it prints one line, `sdd: everything up to date, nothing changed`, instead of its per-surface report; the detail moves behind `--verbose`, and a run that changes something keeps its report.

A run that changed nothing printed only the skills block (`skills: 2 file(s) at <path>`, `up to date`), which reads like a skills report and says nothing about the config, ignore files, MCP registration and settings init also checked. One line tells a newcomer that init ran to its end and that the setup already matches.

Rejected, with the reasoning: printing nothing (a person cannot tell a no-op from a run that stopped early); keeping the skills block and adding a closing line (three lines for a no-op, still reading like work was done); keeping the output as is.

Accepted cost: the per-surface detail of a no-op run is visible only with `--verbose`.

## Acceptance criteria

- [ ] A second `sdd init` in a set-up repository prints exactly `sdd: everything up to date, nothing changed` and makes no commit, on every init path.
- [ ] With `--verbose` the per-surface detail appears too.
- [ ] A run that writes, refreshes or deletes anything keeps its current report.
