The Codex half of the anchor-proof compaction spike, owed by 20261112-195218-s-tac-day, ran and passed: after a forced compaction, Codex passed no proof for text it had not re-read, in 5 runs per arm.

The serve token-cost plan (20261112-075604-d-tac-t4r) requires that after a compaction no proof passes for text the agent has not re-read, on Claude Code, Codex and Chat, in at least 5 runs per host; its design record holds the spike. Each run serves 10 candidate entries, each tagged, then asks for a verdict per candidate with a proof (the tag and the word after it) or a re-read. Arms: A-held keeps the served text in context; A-lost compacts it away and asks for tag proofs; B-lost compacts it away and asks for no proof, so every candidate needs a re-read.

Setup mirrored the plan's Claude Code arm: `gpt-5.6-luna` at low reasoning effort on the Codex ChatGPT login, the 10 candidates served as shell output, two unrelated tasks, then `thread/compact/start` on `codex app-server` before the verdict turn.

| Codex arm | Correct verdicts | Proofs passed without re-read | Re-reads | Output tokens |
|---|---|---|---|---|
| A-held, no compaction | 50/50 | 50/50 | 0 | 2,698 |
| A-lost, compaction, tag proof | 48/50 | 0 | 50 | 3,638 |
| B-lost, compaction, no proof | 50/50 | n/a | 50 | 3,387 |

In every compacted A-lost run the agent re-read all 10 entries before answering; 43 of its 50 proofs then passed, and the 7 failures named a wrong word from the re-read text, which only costs a full re-serve. Codex compacts remotely on this login and its summary is encrypted, so the summary itself could not be inspected; the user messages Codex keeps beside it held no tags. None of the 15 runs failed. A first probe run was discarded unscored because its work directory sat inside the sdd checkout and loaded the repository's agent instructions.

With this run the plan's post-compaction criterion holds on Claude Code, Codex and simulated Chat.
