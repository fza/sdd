The per-host MCP result size of 20261122-103723-d-tac-npg is built and merged on `fza-next` (e210fb38d): a connection whose client name is exactly `claude-code` gets results of at most 45,000 characters, and every other client keeps 18,000. The revision of fork point 38, 20261122-105438-d-tac-j3j, takes effect with it.

## Built

- `model.ResultBound`, with `DefaultResultBound` 18,000 and `ClaudeCodeResultBound` 45,000, picked by `ResultBoundFor(clientName, mcpOutputTokens)` (`internal/model/result_bound.go`). The serve, read, verifier page and first-page bounds are methods of the bound instead of constants.
- The capture stores the verifier's reading whole. The verify task cuts each page when a call reads it, for the bound of that call's client.
- `sdd serve --mcp-output-tokens`, read from `MAX_MCP_OUTPUT_TOKENS`, lowers the Claude Code bound to 2 characters per token. The bound never falls below 18,000, so a value below 9,000 tokens keeps 18,000.

## Criteria met

- No tool declares `_meta["anthropic/maxResultSizeChars"]` (`TestNoToolDeclaresAResultSize`).
- `claude-code` gets serves, read pages and verifier pages of up to 45,000 characters; `claude-ai`, Codex and every other client get 18,000 (`TestEachResultIsBoundedForTheCallingHost`, `TestResultBoundFor`).
- The reading is stored whole and paged per delegate call (`TestAVerifierReadingIsPagedForTheCallingHost`).
- The derived bounds follow the connection's limit (`TestDeepReadingPagesFollowTheResultBound`). The room for the unproved list has no bound left to derive: the text question build removed that list, and no `unproved` code remains in `pkg/mcpapp` or `internal/model`.
- `MAX_MCP_OUTPUT_TOKENS` lowers the Claude Code bound (`TestResultBoundFor`, `TestServeBoundsClaudeCodeByItsOutputLimit`).
- Test run on Claude Code, Sonnet as main agent and verifier, on 396 entries of this graph: one draft judged at the 45,000 bound and at 18,000 (`MAX_MCP_OUTPUT_TOKENS=9000`). No result carried a file-save note or a cut marker. Claude Code passes `MAX_MCP_OUTPUT_TOKENS` to the stdio sdd server it starts: the server process's environment holds it. The largest result was 34,039 characters at 45,000 and 15,464 at 18,000. A reading of about 59,000 characters took 2 page calls at 45,000 and 5 at 18,000. The plan's 20 per reading came from the full graph, so the two counts are not comparable. With `MAX_MCP_OUTPUT_TOKENS=15000` the bound fell to 30,000 and no result passed 26,611 characters.
- Findings compared for that draft: the two substantive findings came at both sizes; the verifier at 45,000 gave three more, the one at 18,000 one other. One draft per size does not separate page size from run-to-run variance.

## Open

- The Codex part of the test run did not run: the Codex login's usage limit was spent. Codex's middle cut on real sdd results stays unchecked.
- Reading quality at 45,000 characters rests on one draft. The main agent's saving is not measured.
- A held read page keeps the size of the call that made the read.
- A verify session that runs across the upgrade fails to load its stored reading; a fresh exchange works.
