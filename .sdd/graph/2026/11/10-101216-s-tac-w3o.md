`sdd init` now commits only the paths it touched that differ from the last commit, built on `pr/fix-init-commit-changed` in bcafe996 and merged into `fza-fork` in 51d57a97; this delivers the directive 20261110-092213-d-tac-sdq and fixes the gap 20261110-000819-s-tac-q3a.

- A deleted, tracked skill file is restored and init exits 0 without a commit (`TestInitRestoresASkillIdenticalToHeadWithoutACommit`). With the filter removed the test fails with `nothing to commit`, the failure the gap describes.
- Paths init creates or changes are still committed; the existing init and retry tests stay green.
- Retry-record paths already passed through the same `git status` check before this change, so a leftover a later commit holds clears the record without a commit (`TestInitDropsRecordedPathsCommittedMeanwhile`).
- No init code path reads git's message text: the filter decides from `git status --porcelain` output alone.

`TestInitLeavesTheUsersOwnEditsOutOfARetriedCommit` deleted a skill identical to HEAD to force a commit the hook could refuse. With the fix that run commits nothing, so the test now removes the skill in a commit first, which makes the restored file differ from HEAD.
