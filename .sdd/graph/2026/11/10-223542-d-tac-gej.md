`llm.preflight.params` sets LLM params for every LLM pre-flight call, laid key by key over `llm.params`, while every other call keeps `llm.params`. The calls it covers are the plain pre-flight and the prose verifier with their extraction call, the purposes `preflight` and `preflight-extract`. sdd builds a second runner from the same provider and model with the merged params and routes those purposes to it (`llm.ByPurpose`), so a project on an API provider can tune pre-flight's reasoning effort apart from the writing guide, summarize and the other calls. The `claude-cli` and `codex` providers take their effort from `llm.effort` rather than from params, so this key does not reach them. The `llm.preflight` block leaves room for more keys later, such as a model or `max_tokens`.

Rejected: `verify.prose.params`, since the plain pre-flight under `verify.mode: off` takes these params too and that name hides it; `llm.purposes.<purpose>`, since it brings config surface, name checks and docs for every purpose. The per-operation selections that 20261106-162723-d-tac-31y plans for generate would cover this case among others; this key stays narrower and does not wait for that change. The two are separate layers: a per-operation selection replaces a provider's settings whole, while `llm.preflight.params` lays params key by key over `llm.params` for the pre-flight calls only. Accepted cost: a second runner to build and test, and one more config key to document.
