When `sdd init` keeps a skill file the user edited and changes nothing else, it prints its full report, as a run that changes something does, not the one line `sdd: everything up to date, nothing changed`.

20261109-233720-d-tac-sc2 made a run that changes nothing print that one line, with the per-surface detail behind `--verbose`. A run that only keeps a user-modified skill counted as unchanged, so its notice `preserved: N modified file(s) left untouched` showed only with `--verbose`, and the one line claimed the setup matched while an installed skill differed from the bundle (found in 20261110-000718-s-tac-xco).

Rejected, with the reasoning: the one line followed by the notice (a third output shape for one case); leaving the notice behind `--verbose` (the one line then states "up to date" while a skill differs from the bundle).

## Acceptance criteria

- [ ] A run that keeps a user-modified skill and changes nothing else prints the full report, the `preserved:` line included, and makes no commit.
- [ ] A run that keeps no modified skill and changes nothing still prints the one line.
