The daily sweep never removes an open session, however long it is idle and whether or not a move is in progress in it; only ended sessions go, `sessions.retention` after they ended. This takes back the sweep rule of 20261121-223858-d-tac-cg2, built in 20261122-230021-s-tac-2u6. That plan's sessions on a topic change stay. Point 28 of the fork compatibility directive reads again as before its correction in 20261121-234844-d-tac-156: in a project both binaries use, the fork removes old ended sessions stock wrote and keeps every open session, as stock does. Rules 2 and 3 of the daily sweep directive, 20261114-095140-d-cpt-ad4, which keep every open session, hold again, and so does the clause of the session collection rule, 20260914-113911-d-tac-wgw, that leaves unended sessions untouched.

An open session is a dialogue its handle can still resume, and removing an idle one loses work its person may return to.

Built on `fza-next` (8008a9b38, merged at 09d7b7689): `collectSessions` in `pkg/application/collect.go` selects ended sessions only. The session shell's text again says a session nobody ended stays resumable by its handle. The help text of `sdd cache prune`, the configuration reference and the coding-agents guide state that an open session stays. `TestCollectKeepsOpenSessions` failed on the earlier rule for open sessions past the retention.

Rejected:

- A long `sessions.retention`. It keeps ended sessions longer too.
- A separate state folder per binary on a machine that also runs stock sdd. The fork's own idle sessions would still go.

Accepted cost: sessions left behind on a topic change, and abandoned drafts, stay on disk until resumed or concluded.
