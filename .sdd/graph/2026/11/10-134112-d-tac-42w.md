`sdd init --graph-repo` switches a code repository that points at its graph through `project_dir` to `graph_repo` in one run, with three fixes that answer the three failures of 20261110-112750-s-tac-a31 and make the two-pointer transition of 20261106-202055-d-tac-eyl work without hand steps.

1. **Resolution from the flag.** Under `--graph-repo`, init resolves the code repository as a `graph_repo` project named by the flag, before any pointer is written, so the `project_dir` check on the machine-local config does not apply: that file is where a `graph_repo` project keeps its settings. Every other command keeps the check, since a repository that only points through `project_dir` must not carry project settings it would never read.
2. **Sync before refresh.** When sdd's clone of the graph repository already exists, init runs the clone's sync round (fetch and merge under the git gate) before it refreshes the setup there, so the refresh builds on the remote's state. A fetch the gate skips within its cooldown is acceptable, since the clone was then fetched minutes before. A freshly made clone needs no round.
3. **Push only with commits waiting.** Publishing the clone pushes only when the clone is ahead of its upstream, as 20261107-095427-d-tac-yux requires of every push, so an init that changed nothing in the clone never meets the push cooldown.

Rejected alternatives:

- A clearer refusal naming the hand step for the first failure. It keeps a manual edit in every switch.
- Relaxing the `project_dir` check for every command. A pointing repository would then carry settings no layer reads, silently.
- Treating a cooldown-deferred push as success without looking at the clone. A clone with commits waiting would then report success with nothing pushed.

Accepted cost: a second way to resolve a project, used only by `init --graph-repo`.
