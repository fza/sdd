`sdd move` now carries the graph's runtime folder `.sdd-runtime/` to the new graph folder and removes the former graph folder once it is empty: commit `2b89cabe` on branch `pr/fix-move-runtime-dir`, merged into `fza-fork` as `5142e9f0`. It closes the runtime-folder directive (20261110-083100-d-tac-f48).

Criteria:
- After `sdd move --graph-dir graph` the former `.sdd/graph` is gone, and `graph/.sdd-runtime/` holds the former lineage record, its ignore file and both lock files, released; `git status` stays clean.
- A move out to a project dir and back, and out to a graph repository and back, carries the folder the same way in both directions.
- A former graph folder holding an ignored `notes/draft.txt` stays with that file untouched; the runtime folder still moves out of it.
- A lock file whose lock another holder keeps is not renamed: it stays in the former folder, still held, while the free titles lock and the lineage record move. The move takes no graph lock of its own, so the test holds the graph lock from outside while the move runs.

When the new folder already holds a runtime file of the same name, the move keeps the new folder's copy and leaves the former file where it was, so the former folder stays. Each file is probed with a lock taken and released before its rename; a lock taken by another process between that release and the rename cannot be reached by a test. Breaking the probe's release left both lock files held after the move and failed the release check. Breaking the non-empty check before removing a folder failed the move itself, since the operating system refuses to remove a folder with content.
