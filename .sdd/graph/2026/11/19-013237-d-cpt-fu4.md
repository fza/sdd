The fork stays compatible with stock sdd on a shared graph, a shared project config and shared machine folders; where the fork keeps a deviation or accepts a loss, it is named here with its cost.

Stock sdd is upstream `main`, compared at commit `ca555fd1`. Both binaries meet on the same committed files (`.sdd/config.yaml`, the graph, the installed skills) in a team that uses both, and on the same folders under `~/.cache/sdd/` and `~/.local/state/sdd/` on a machine that switches between them. The owner set the goal in these words: "The goal: 100% compatibility." and "the fork MUST NOT lead to stock sdd breaking".

Each numbered item below is one difference between the fork and stock, with its outcome. An item ends one of three ways. The fork returns to stock's behaviour. The fork keeps its behaviour and makes it harmless to stock. Or the fork keeps a deviation or accepts a loss, and the item names its cost. An item that names no change keeps the fork as built. The outcomes are built on `fza-next`, the fork line of 20261117-092355-d-prc-3vb.

## Where the graph lives

1. `graph_dir` behaves as in stock. It may be relative or absolute and may lead into another repository. The code repository's settings apply, the graph repository's own `.sdd/` is ignored, and the commit runs as stock runs it, so it fails when the graph sits in another repository. `project_dir`, which 20261028-115146-s-tac-15i delivered, is removed without migration and becomes an unknown key. The code that existed only for it is removed with it, which includes what 20261110-215001-s-tac-mxt delivered. `sdd init --project-dir` and the `--project-dir` target of `sdd move` are removed with the key; `sdd init` and `sdd move` keep `--graph-dir` and `--graph-repo`. Accepted cost: no command sets up a graph in a second local repository, and a graph that `graph_dir` places there by hand is read but every commit into it fails, as in stock, until upstream takes the fix proposed below. Rejected: keeping both flags and letting them write `graph_dir`. One test confirms that a project opened through a symlinked folder yields the participant of its `config.local.yaml`. Cost: a checkout that reaches its graph through `project_dir` loses the link.
2. `graph_repo` stays a committed, fork-only key. Where a config sets it, that config's `graph_dir` is ignored. A graph repository whose own config sets `graph_repo` is an error. The fork no longer writes or checks the guard file `.sdd/GRAPH-ELSEWHERE.md`. Cost: stock warns about the unknown key and works on `graph_dir` (default `.sdd/graph`), so a stock `sdd init` there starts a graph in the code repository.
3. The search for `.sdd/` walks up to the filesystem root, as in stock. The fork's stop at the first `.git` is reverted. Cost: a repository nested in an sdd project uses the enclosing project again, and a capture there writes its file into that graph and fails at the commit.

## Entries and graph

4. The fork does nothing about stock's rewrites of entries. Accepted loss: a stock `summarize`, `rewrite` or `lint --fix` on a fork-written entry drops the fork's entry fields `reason`, `decided-by`, `run-by`, `approves`, `approved-by`, `reason-by`, `intent-by`, `grounding`, `verification`, `actor_kind` and `rounds`. Rejected: a repair after each stock rewrite, which adds commits the other binary undoes, and moving the content into the body, which changes the format of every entry.
5. `title` stays a field in the entry file. Cost: until upstream knows the field, a stock rewrite drops a title and the entry shows its first summary sentence again.
6. The automatic filling of missing titles (session start, serve timer, tool calls, sync) runs only where `titles.backfill: true` is set. The default is `false`. Cost: one more fork-only key, and where it is on, stock drops titles and the fork adds them again.
7. `sdd summarize --all` keeps filling missing titles along with summaries. `sdd sync --pull` only pulls unless `titles.backfill` is on. Cost: a user who knows stock's `summarize --all` also gets titles and a large commit.
8. A procedure entry that uses fork-only step keys (`delegable`, `unattended`, `deliver`, `await` and others) is written as before. The fork does nothing here and neither refuses nor warns at such a capture. Accepted cost: stock cannot load such a procedure entry, and when the entry replaces a shipped procedure, stock cannot run that procedure in the project. Rejected: refusing the capture, and warning and then writing.
9. The two citations of entries that neither ship with sdd nor exist in upstream's graph leave the shipped procedure texts, which state the rule themselves. The base procedures edited under unchanged IDs and the fork-only `verify` procedure stay, since each binary reads its own.
10. The fork keeps reading the time in an entry ID as local time. Deviation: stock reads it as UTC, so its entry ages, "recent" windows and focus time windows are shifted by the UTC offset. The order of entries is the same.
11. The fork's health check keeps accepting a participant that matches an actor alias. Deviation: stock shows health warnings the fork does not.
12. `sdd move` no longer raises a graph's `minimum_version` to a fork version, so stock can write to a moved graph. This removes the fixed floor that 20261111-090901-s-tac-voa delivered and that 20261111-084026-s-tac-8o3 left unchanged. Values that older fork releases wrote stay. Accepted loss: a graph whose `minimum_version` an older fork release raised to a fork version, such as the move floor `v0.18.0-alpha.3.fza.43`, refuses a stock build of the same upstream version, because that version sorts below the fork version, and a later stock release that raises the minimum locks the fork out until the fork is rebuilt on that version. Cost of the change: an old fork build without move records can write to a moved graph's old location again, and the fork finds such entries as strays.
13. The fork keeps writing `<graph>/.gitattributes` (`merge=sdd-entry`) and the `merge.sdd-entry.driver` line in `.git/config`. Cost: an extra committed file in a stock team's graph folder and a config line the fork rewrites. Stock merges entry files as plain text.
14. The fork keeps refusing a repository ID with a `.` or `..` segment, because such an ID could make it clone into, or delete, a folder outside its storage. Deviation: the fork refuses a config stock accepts. No real repository address produces such an ID.

## Config

15. A missing `verify.mode` keeps meaning `prose`. Deviation: in a project stock set up, the fork refuses a plain `sdd new` without grounding, a capture needs the reading step and a draft check, and model spending is higher than in stock. A project opts out with `verify.mode: off`.
16. `sync.cooldown` stays retired. The machine's global config alone paces fetches (`sync.default.fetch_cooldown`, default 5 minutes). Deviation: a project's longer cooldown has no effect on fork machines, and `sdd config` lists the key as ignored.
17. The fork-only keys (`verify`, `hooks`, `dialogue`, `connected`, `inbound`, `llm_prefilter`, `secrets`, `graph_repo`, `titles.backfill`) stay in the committed `.sdd/config.yaml`. Stock reads a config tolerantly under 20260921-174543-d-cpt-tv9, so it works on. Cost: stock prints `ignoring unknown config key` once per such key on every command and applies none of them.
18. In a terminal, the fork's `sdd init` keeps asking for the dialogue mode, for `verify.mode` and, under `deep`, for the verifier runner while they are unset, and writes `verify.mode` into the committed config. Cost: the first fork `init` in a stock project changes its committed config, and stock then warns about the `verify` key.
19. The fork keeps its model-call timeouts and sets its effort defaults per provider. `llm.timeout` is 5m for the claude-cli provider and 2m otherwise, and the pre-flight and summarize limits follow it. With `llm.effort` unset, the effort is `medium` for the claude CLI, codex and anthropic, and `low` for openai and ollama. The effort is wired through to anthropic, openai and ollama for that, and a model that refuses the parameter gets none. Deviation: timing and spending differ from stock, which passes no effort. Nothing on disk differs.
20. The fork keeps refusing a config that carries `dialogue.mode: autonomous`, `verify.runner: codex` or a `verify.codex` block, values of older fork builds. The message names the fix, and `sdd config set` or `unset` repairs the file. Stock is not affected.

## What `sdd init` writes

21. The fork keeps its committed `.sdd/.gitignore` and no longer removes the lines stock's `init` adds to the root `.gitignore`. Cost: in a project both binaries use, the same rules stand in two files.
22. The stamps `sdd-version` and `sdd-content-hash` sit where stock writes them: at the top level of the frontmatter in the Claude render of a skill file, under `metadata:` in the Codex render. Stock reads either placement. Cost: the Claude render fails the Agent Skills standard check, so `devbox run validate-skills` covers the Codex render only and the `AGENTS.md` rule that names `metadata:` changes. Each binary's `init` still replaces the other's skill files, with a commit each.
23. The "Contribution mode" section leaves the `SKILL.md` template, because it names a command stock does not have. The server tells the agent about contribution mode at session start. The fork keeps removing stock's `references/vocabulary-de.md` at `init`, so no agent reads a vocabulary that differs from the served one. Cost: one more text served at session start, and the vocabulary file changes in the same commits as `SKILL.md` when both binaries run `init`.
24. The fork's `init` keeps installing `.claude/agents/sdd_delegate.md` and `.codex/agents/sdd_delegate.toml`, committed under project scope, with their stamps under `metadata:`. Cost: two extra committed files in a stock team's repository and a helper in the agent list that stock does not use.
25. The fork keeps its refresh commit subject `sdd: refresh sdd setup` and its one-line output for a run that changed nothing (`--verbose` prints the full report). Deviation: two subjects for one kind of commit in a mixed team's history.

## Machine state

One rule covers this area. The fork creates no folder of its own beside one of stock's, and after a switch from the fork back to stock, stock does not break on anything the fork wrote. Stock uses `~/.cache/sdd/<repo-id>/` for clones, `~/.cache/sdd/index/`, `~/.local/state/sdd/sessions/` and `~/.local/state/sdd/staged-blobs/`.

26. The fork no longer deletes stock's clones under `~/.cache/sdd/<repo-id>/`, the removal on first use that 20261110-092504-s-tac-grp records. It keeps its own under `~/.local/share/sdd/repos/`. Cost: on a machine that moved from stock to the fork, an unused clone per connected repository stays on disk until someone removes it by hand.
27. `~/.cache/sdd/index/` stays shared. The fork's index clean-up works only on stores the fork has a record of using. Cost: in a project both binaries use with a rune-capped index, each may drop the other's stored versions after the retention time, and the other embeds them again.
28. `~/.local/state/sdd/sessions/` and `~/.local/state/sdd/staged-blobs/` stay shared. The fork's state sweep skips a project it has no record of using. Cost: in a project both binaries use, the fork removes old ended sessions stock wrote, by the machine's global retention instead of the project's.
29. Each line of the fork's checkout record (`~/.local/state/sdd/checkouts/*.list`) reads `<path>\t<RFC 3339 last seen, UTC>[\t<missing since>]`, split at the last tab. This is the format proposed upstream for the scheduled cache prune, and a stock build with that proposal would fail `sdd serve` on path-only lines. The fork rewrites a path-only line as an old record. Cost: an older fork build reads the new lines as paths that do not exist and removes less in that project, never more.

## Commands

30. The fork reaches a project's whole dependency chain, as stock does. Every repository down the chain is loaded, searchable and usable as a session's project. The resolver for refs beyond the direct dependencies and its miss record go. Cost: every fork machine clones and indexes every repository down the chain. This ends the direct-dependency rule of 20261113-235859-d-cpt-l3m, which a decision of its own replaces.
31. Plain `sdd sync` stays: fetch and report, or a full round where sdd keeps its own graph clone under automatic sync. `sdd sync --pull` merges as in stock. Deviation: a command that fails in stock succeeds in the fork.
32. The fork keeps its text output of `view`, `search` and `show`: titles on entry lines, a heading per connected repository, a pointer for an entry already printed, the fork's fields in the `show` header. Deviation: a script that parses stock's text needs adapting. The `--format json` shapes are not compared field by field.
33. The fork keeps refusing `sdd new`, `sdd wip start` and `sdd summarize` on text that looks like a credential, and keeps failing every command while the global config holds a refused value. Deviation: an entry stock wrote with such text cannot be summarized or titled with the fork.
34. A fork capture commit keeps its subject `sdd: <type> <layer> <title>` and names the entry in an `Entry: <full id>` line of the message body, before `SDD-Mutation:`, so `git log --grep` finds the commit by entry ID. Cost: one more line in each capture commit.
35. The fork-only commands (`cache`, `dismiss`, `events`, `gather`, `grounding`, `hooks`, `move`, `recheck`, `relevance`, `repo path`) stay and fail in a script run with stock. `sdd hooks trust` gets no alias beside `sdd hooks allow`. Every command of stock's help listing exists in the fork.

## MCP server

36. `stage_attachment` also accepts stock's call shape, `name` with `content`, `path` or `patches` at the top level, as one file, and answers such a call with stock's top-level `handle` beside the fork's `files` list. The tool listing shows only the `files` shape. Cost: a second input shape to keep working and to test.
37. The server keeps its markers in served text and the optional proof arguments `held` and `reread`. An agent that sends none gets everything in full, as in stock. Deviation: the markers are visible in all served text, and a program that sends these arguments to stock's server gets an unknown-argument error.
38. The cap of 18,000 characters per tool answer (`model.MaxResultChars`) and the pages stay. When the same call arrives again without `page` right after a paged answer, the answer opens with a line saying that this is page 1 again and how to get page 2. Cost: one more special case in the server.
39. The tool list keeps leaving out the reply schema by default, and `sdd serve --output-schema` turns it on. Deviation: a program written for stock's tool list needs the flag.
40. No capture is refused or held for a missing reason, and the person's own words for a directive's intent are no longer demanded. The intent value stays required, as in stock. Three checks stay in every project: reading before writing (`verify.mode`), the hold until the agent's client matches an actor in auto mode, and the delegate check under `verify.mode: deep`. This ends the per-kind reason rule of 20261118-173349-d-tac-8jh, which a decision of its own replaces.
41. The fork keeps its own MCP server instructions. The sentence that limits work to directly declared dependencies changes with item 30. Deviation: the two servers introduce themselves in different words.
42. Every exported function and type of stock's `pkg/` stays usable in the fork beside the fork's own. What the fork removed or changed is restored, as a wrapper where the new code can serve it. A symbol no wrapper can restore, such as a changed interface method or a struct field of another type, goes to the owner before the build continues. Cost: a second public surface to keep and test.
43. The server keeps refusing every tool call while a config layer holds a refused value, and while the config points at a place the graph was moved away from. Each answer names the fault and the repair. Deviation: a session stops in two situations stock does not know.

## Sessions and procedures

44. Stock skips a session log that holds fork-only events with a warning and works on. The fork does nothing more. Accepted loss: a session log with fork-only events cannot be resumed or abandoned under stock and stays on disk.
45. Each binary's sessions stay with that binary. Both ship the capture procedure under one ID, with 9 steps in stock and 40 in the fork, so a capture one binary started loops or parks under the other. The fork writes a fork-only event at the start of every session it opens, so stock skips each fork session as unreadable. For a move a stock session started, the fork lists it and offers only `abandon`. Cost: no session crosses between the binaries.

## Install

46. The fork keeps the program name `sdd`, the cask name `sdd` in its own tap and the version scheme `<upstream version>.fza.N`. Cost: the two cannot be installed side by side with Homebrew.

## Rejected alternatives

- Own folders for the fork beside stock's, such as `index-fza/`, `sessions-fza/` and `staged-blobs-fza/`. The fork shares stock's folders by name and limits its clean-up to what it has a record of using (items 27 and 28).
- A second committed config file that stock never reads. It adds a config layer, moves the keys of every project, and moves a key back once upstream adopts it. Uncommitted files alone were rejected too, because a team could no longer share `verify.mode` or `hooks`.
- Another program name for the fork. Every script, hook, skill text and agent setup that calls `sdd` breaks, and committed files would name a program stock users do not have.

## Also proposed upstream

These outcomes are proposed to upstream as well, so that the proposals and the fork behave alike: the two `graph_repo` rules of item 2, the `title` field with `titles.backfill` and the `Entry:` line (5, 6, 7, 34), the local-time reading (10), the alias acceptance (11), no `minimum_version` raise after `sdd move` (12), the merge helper (13), the repository ID refusal (14), `prose` as the default (15), per-host fetch pacing with `sync.cooldown` retired (16), the `init` questions (18), `llm.effort` with its per-provider defaults and the 5-minute limit (19), the delegate files (24), the refresh commit subject (25), the checkout record format (29), plain `sdd sync` (31), the credential refusal (33), both `stage_attachment` shapes (36), markers and proof arguments (37), the "page 1 again" line (38), the `--output-schema` flag (39), no reason and no intent words (40), and `abandon` alone for a capture started under the 9-step procedure (45). A new proposal lets stock keep unknown frontmatter fields on a rewrite, the only real fix for item 4. Two fixes are proposed upstream that the fork itself does not carry, because the fork behaves as stock there: the commit into the repository that holds the graph (1) and the stop at the first `.git` (3). Every proposal passes the `pkg/` comparison of item 42.

No proposal makes stock read past unknown procedure step keys (8), because a step key changes how a procedure runs and a binary that ignores it would run the procedure wrongly. The outcomes of items 9, 21, 26, 27 and 28 and the session start event of item 45 stay on the fork alone. The proposals keep removing the root `.gitignore` lines, deleting the former cache clones and cleaning every index store and session, because inside upstream those are the same program's own older files.

## Acceptance checks

- Switch-back test: the fork writes machine state (index stores, session logs with fork-only events, staged attachments, checkout records), then stock runs `sdd serve` and `start_session` against it without failing.
- An API comparison of `pkg/...` between upstream `main` and the fork reports no incompatible change.
- Stock's `examples/extendingsdd` compiles unchanged against the fork.
