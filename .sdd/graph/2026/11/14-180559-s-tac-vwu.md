The hold-next anchor proofs of 20261114-121534-d-tac-qdb are not shown to work for Codex: Codex main agents mostly skip the proofs, so they get every repeated piece in full again, and the mechanism needs rethinking for them.

## Actual

In a live round on fza-fork at 8e7e2c0e (three deep-verifier captures with `gpt-5.3-codex` through Opper), the Codex main agents sent few proofs: one sent an empty `held` list on all 18 calls, the others proved 99 of 412 and 22 of 183 named tags, mostly only tags from the latest result. So the playback step's instruction text (about 2.9 KB) and the working-principles framing block sdd serves beside it (about 2.6 KB) came back in full at every playback. The Codex verifier subagents in the same runs proved most of their tags (19 of 19, 31 of 49, 12 of 15). On the build before hold-next, the Codex main agents in three baseline runs never sent `held` at all, though told to list every tag on every call. The proof-character figure (92% below the every-tag count) looks like success only because an agent that proves nothing scores best on it; total result bytes fell 5.4% against the baseline, 12% for the main agents, with 1 wrong proof against 0 (the baseline main agents sent none). The measurements are attached: [Codex hold-next round](./14-180559-s-tac-vwu/codex-hold-next-round.md).

This round does not settle 20261114-121534-d-tac-qdb: its fourth criterion is met on its letter, but the figure rests on agents that prove little, so the directive stays open until runs with Claude agents report.

Claude agents behave differently: Claude Code main agents and headless Claude verifiers in recent transcripts send proofs on most calls, on the hold-next build and on the one before it.

## Expected

A Codex main agent sends the proofs the hold-next line names, so repeated pieces serve as pointers, as they do for Claude agents.

## Not settled

Why Codex main agents skip `held` while its subagents send it: the served wording, the tool schema, the length of the main dialogue, or Codex's tool-call habits. The branch `pr/hold-next-codex-rethink` keeps the hold-next state the rethink starts from.
