The carry-over of held texts across linked sdd sessions, per 20261122-105026-d-tac-wl5, is built and merged on `fza-next` (c12747eaf): `start_session` takes an optional `link` with an earlier session's handle, and the new session's text question and short serves count the texts that session still holds. Thirteen of the plan's fourteen criteria are met; the live probe of texts 66k to 147k tokens back is not shown, so the plan stays open. The point 37 item of 20261122-105438-d-tac-j3j takes effect with this build.

## Built

- `model.SessionNeutral` replaces a session handle with a stand-in, so stored texts compare without the handle.
- A `lost` or wrong answer empties the held set; a right answer to a question from before the reset holds only later texts.
- The fork-only `linked` event records a snapshot of the linked session's held texts, oldest latest copy first. A chain carries through the linked session's own `linked` event, so a later sweep of the earlier log changes nothing.
- `resolveLink` refuses an unknown handle and authorizes the link as a resume does. A log with no served texts, one stock sdd or an older fork build wrote, opens the session unlinked with a one-line notice.
- The session shell's topic-change rule tells the agent to pass the earlier handle in `link`.

## Criteria met

Thirteen of fourteen: the optional argument (`TestToolContractSnapshot`); the opening question on the oldest carried text (`TestALinkedSessionCarriesTheTextsItsEarlierSessionHolds`); right answers short and handle-neutral (`TestALinkCarriesHeldTextsMatchedWithoutTheHandle`, `TestStartSessionLinkCarriesTheEarlierSessionsTexts`); the reset on `lost` or a wrong answer (`TestLostEmptiesTheHeldSet`, `TestAnAnswerFromBeforeLostHoldsOnlyLaterTexts`, `TestHeldTexts`); one full response after many lost (`TestOneFullResponseAfterLostServesShortAgain`); chains (`TestLinksChain`); no link for a delegate (`TestADelegateChildSessionCarriesNoLink`); the oldest held text within one session (`TestTheQuestionAsksAboutTheOldestTextByItsLatestCopy`); `reread` and resume in full (`TestALinkedPieceServesInFullOnRereadAndResume`); the unknown handle (`TestAnUnknownLinkIsRefused`, `TestStartSessionRefusesAnUnknownLink`); a log without texts (`TestALinkToALogWithoutServedTextsGoesUnused`, `TestStartSessionLinkToAStockLogGoesUnused`). No exported signature in `pkg/` changed: the build adds a field, a method and an engine type.

## Live probe, partly run

Claude Code with Opus and with Sonnet as main agent, on 396 entries of this graph, through two signal captures, a new session for a new topic and a compaction. Opus reached 160k tokens of context and Sonnet 142k.

- Opus answered 19 questions: 15 right, 2 wrong, 2 `lost`. Sonnet answered 16: 15 right, 1 `lost`. Past 66k tokens of context Opus answered 9 of 10 right and Sonnet 9 of 9.
- Opus passed `link` with the first session's handle when it opened the second session; Sonnet did not. With the link, the opening question asked about the oldest text still held.
- Every `lost` came while the asked text was still in context, at most 6k tokens back.
- After the compaction both models answered the first question right from the compaction summary, which held the pending question's text. Each then answered `lost` on the next question, and sdd reset the held set and served in full.
- Not shown: answers about texts 66k to 147k tokens back. The question targets the oldest held text, and each reset keeps the held set young; the largest distance asked was 37k tokens.
