The fork's structured output takes its response schema from the request (`llm.Request.ResponseSchema`), where upstream declares it (20261004-134853-d-cpt-sw8). In `json_schema` mode the gollm adapter passes that schema to gollm's own schema path (`WithResponseSchema`) unchanged. The fork keeps only what upstream lacks: `json_object` mode, `auto` mode and local validation for endpoints that refuse a schema (20261028-130825-d-tac-fah), all driven by the request's schema.

Removed:
- `WithStructuredOutput` and the per-purpose router `internal/llm/factory/mux.go`. The router built one gollm client per schema because gollm options were client-level; one client now serves every purpose.
- The schemas reflected from Go structs (`internal/llmops/schema.go`) and the `github.com/invopop/jsonschema` dependency, in the root and the example module. Schemas are JSON files under `internal/llmops/response_schemas/`, which keep property order.

Added:
- The extraction call, which reformats a pre-flight or writing-guide answer that does not parse, declares that check's schema (`preflightSchema`, `writingGuideSchema`).
- Summary and title requests declare `summary.json` and `title.json`.

Why: upstream carries the schema on each request. A per-runner schema beside it gives two schema paths that can disagree for one call, and the pre-flight schema would arrive twice. With one path, upstream changes to it reach the fork without merging two designs.

Rejected:
- Dropping the fork's structured output for upstream's path alone: endpoints that refuse `json_schema` for a model lose structured checks, against 20261028-130825-d-tac-fah, and configs that set `llm.structured_output` keep a key that does nothing.
- Keeping both paths, the fork's winning where a runner carries a schema: two schema paths per call, and a conflict in every later upstream merge.

Accepted costs: pr/llm is reworked and its tests rewritten, and the change flows through every branch stacked on it. `json_object` mode resolves a validator per distinct schema at first use rather than at construction, so a malformed schema fails its first call, not the command's start. The json_object layer stays tied to the gollm adapter; once upstream's own provider clients replace gollm (20261106-155245-d-cpt-eit), it moves to them.

Acceptance criteria:
- `llm.Request.ResponseSchema` is the only way a schema reaches a provider adapter; no runner option or router carries one.
- `json_object` and `auto` modes validate against the request's schema.
- Every request that expects structure, extraction included, declares its schema.
