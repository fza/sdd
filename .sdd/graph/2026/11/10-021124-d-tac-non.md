`sdd sync --pull` writes its merge commit with the message `sdd: merge <upstream>` in every repository, the message the pull in the sdd-owned graph clone already writes. In a repository the user works in, the pull runs a plain `git pull --no-rebase` (`MergePull` in `internal/git/git.go`), so git writes its default `Merge branch 'main' of ...` message. A commit-message hook that enforces a commit style refuses that message: the pull then stops with the merge half done, and the user finishes it by hand.

The merge is a commit sdd starts, so it carries the `sdd:` prefix reserved for commits SDD tooling makes. The automatic-sync directive (20260817-162701-d-cpt-r8k) already requires that message for the pull in the graph clone. Since automatic sync left graphs the user works in (20261107-095427-d-tac-yux), the merge-only `sdd sync --pull` (20260608-002510-s-tac-qk2) is the one way sdd merges there; both paths now write one message.

Rejected: keeping git's default message. Every pull of diverged history in a repository with such a hook stops mid-merge.

## Acceptance criteria

- [ ] `sdd sync --pull` merging diverged history writes a merge commit whose subject is `sdd: merge <upstream>`, the message the graph clone's pull writes.
- [ ] A pull that fast-forwards writes no merge commit.
- [ ] The pull still never rebases and still refuses on a dirty working tree.
- [ ] A test fails when the merge commit gets git's default message.
