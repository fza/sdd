sdd itself makes an agent read the graph before a capture, so a draft does not contradict a live decision, duplicate an entry, state something outdated or leave the graph inconsistent; when a reading shows two existing entries in such a strain, that becomes graph work. Enforcement lives in the engine and the application layer, never in agent hooks or a harness plugin, so CLI and MCP get it alike and every agent harness does. It is opt-in: `grounding.enforce` defaults to `false`. The full design, with every decision, its reasoning, rejected alternatives and accepted costs, is attached: [grounding design](./09-004506-d-cpt-udz/grounding-design.md).

**The reading.** Before a capture can be written, the agent runs at least one semantic search and one keyword search on the draft's topic and a full listing of it. A new read verb, `gather` (CLI and MCP), returns all of it in one call: relevant entries in full at the grounding depth (default down 2, up 1), the rest as briefs to judge, set-aside entries as counts. Only reads inside the capture instance count. Below `grounding.brief_all_below` (default 100 live entries) `gather` sends every live brief and runs no search; above it a `gather-query` operation of the `llm` block writes the queries. Grounding candidates are strictly live entries; `actor` and `role` drafts are exempt.

**Verdicts.** Every entry served in full ends in the draft's refs or in a `verdicts` report field, `[{ids, code}]`, with a fixed code: `topic-only`, `other-scope`, `term-clash`, `covered`, `meta`, `other`. The assemble gate refuses while an id stays open. The engine seeds `widenReport` from the reading. Entries that landed after the reading began join the candidates at assemble and are checked again at write.

**Prefilter.** From `grounding.prefilter_from` (default 30 pairs to judge), a cheap model in its own `llm_prefilter` block scores relevance first and the agent judges the band it leaves. The port is `pkg/llm/relevance` (`Scorer`), with adapters for Jev over Opper first and Cohere rerank second, and a generate bridge. It sets an entry aside only once the 95% Wilson lower bound of its recall reaches 0.98; 3% of set-aside entries return blind as audit lines. Verdicts are stored as segment files under `.sdd/relevance/`, committed only behind a setting; `relevance.content` chooses reader verdicts only or scores too.

**Healing.** Strains between live entries become `sdd.recheck` events in a project event store, kept until healed; a capture citing an entry with an unhealed strain is refused. `sdd catchup` names who heals. The CLI converts the verdict ledger and the event log to and from JSON, so the binary files stay inspectable and repairable.

**Bypass and CLI.** `--skip-grounding` records `grounding: skipped` and forces `confidence: low`. `.sdd/config.local.yaml` may set `grounding.enforce: true` only, never `false`. Under enforcement `sdd new` first refuses and names the engine capture; a session-aware CLI follows.

**No repeats, no cuts.** Every verb that returns entry metadata, title, summary or body serves an entry already served in the same MCP session as a pointer: id, brief and the way back (`gather` with the ids, or `resume_session`). The CLI never cuts. Nothing grounding serves is truncated; long lists are paged with a count and the call that fetches the rest.

**Verification.** The capture's reading feeds the graph-fit guide (20260810-141555-d-cpt-20r) as the draft's neighbourhood. Its light and deep variants are decided in their own directive.

Rejected, with the reasoning: enforcement in agent hooks or a plugin (harness-specific, refused upstream); enforcement on by default (every project would change behaviour on update); free-text dismissal reasons (no calibration labels); a fixed label minimum for the prefilter (recall unproven); truncating long lists (the agent reasons from what it never saw); a committed binary recheck file (replaced by the event store).

Accepted costs: a new read verb, an LLM block and a binary store to maintain; an event store built in this work; captures under enforcement take more reads; `sdd new` is unavailable under enforcement until the session-aware CLI lands.

## Acceptance criteria

- [ ] With `grounding.enforce: true`, a capture without the three reads, or with an entry served in full but neither referenced nor in `verdicts`, is refused at assemble, naming the open ids; with `false` nothing changes.
- [ ] `gather` returns relevant entries in full, briefs to judge and set-aside counts in one call, sends every live brief below `grounding.brief_all_below`, and truncates nothing.
- [ ] An entry landing after the reading began is listed at assemble and again at write, and the capture waits for its verdict.
- [ ] The prefilter runs only from `grounding.prefilter_from` pairs, through `pkg/llm/relevance` adapters, sets entries aside only past the recall bound, and returns the audit share blind.
- [ ] A strain between live entries becomes an `sdd.recheck` event, and a capture citing an entry with an unhealed strain is refused.
- [ ] `--skip-grounding` writes `grounding: skipped` with `confidence: low`; a local `grounding.enforce: false` is refused.
- [ ] In MCP mode every entry-returning verb serves an already-served entry as a pointer with brief and way back; the CLI serves in full.
