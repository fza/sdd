A re-run `sdd init` that commits uses one generic subject, `sdd: refresh sdd setup`; a first run keeps `sdd: init .sdd/ metadata directory`. This replaces 20261109-234150-d-tac-5lk, which named the changed surfaces in the subject, and takes back the code that shipped it (20261110-000718-s-tac-xco).

Naming surfaces needed a path-to-surface table (`model.InitSurfaces`) that every new file init writes must join; the delegate subagent file already fell through to `other files`. Labelling each write where it happens would remove the table but touch about 20 write sites in the init handlers, code shared with upstream. A generic subject keeps the change to the one string upstream already returns, and the old `sdd: refresh installed skills and metadata` misnamed runs that only wrote config or an ignore line.

Rejected, with the reasoning: the path table extended with an `agents` surface (the next new file falls through again); a surface label at each write site (wide change to upstream init code); keeping the upstream subject (misnames config-only runs).

Accepted cost: the log no longer says which surfaces a refresh changed; the commit's file list does.

## Acceptance criteria

- [ ] A re-run that commits uses `sdd: refresh sdd setup`, whatever it changed.
- [ ] A first run keeps `sdd: init .sdd/ metadata directory`.
- [ ] The path-to-surface table `model.InitSurfaces` and its tests are gone.
