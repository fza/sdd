Project-declared hooks, the unified `verify` block with the codex provider and `llm.effort`, and the `claude-cli` context-window probe are merged into `fza-fork`: hooks as `40a8267c` with `ea4956f9`, `c64d5d25` and `810c6745`, verify as `d50681df` with `77c0f535`, built on `pr/feat-hooks` (`fbf27eae` last) and `pr/feat-verify-mode` (`333df172`, `c0b16879`, `f8403906`, `c26a1155`). This closes 20261109-213250-d-tac-bve, 20261109-222220-d-tac-4ev and 20261109-230833-d-tac-uh2.

Hooks (20261109-213250-d-tac-bve): every criterion has a test. Changes against the directive's text, set by the owner: `sdd hooks trust` confirms only on a terminal and refuses on any other input, so an agent cannot confirm a hook; over MCP, `start_session` and every call carrying a session handle check all declared hooks before any work, asking about all unconfirmed ones in one elicitation, instead of asking when a call first reaches an unconfirmed hook. A hook that changes after that check fails its call naming `sdd hooks trust` and does not run. `.sdd/hooks/local/` is ignored through the committed `.sdd/.gitignore`, and the 24h cache prune sweeps confirmations of undeclared hooks.

Verify block (20261109-222220-d-tac-4ev): criteria 1 and 3 to 6 hold, each with tests. Criterion 2's and 3's refusals of `verify.launch`, `custom_driver` and `verify.subagent` are not built: the owner dropped them because no release ever shipped those keys, so they read as unknown keys. The MCP dispatch field, the hook payload key and the session records also use `runner`. A `pre-flight` run through `codex exec` was checked live.

Window probe (20261109-230833-d-tac-uh2): all three criteria have tests over a scripted `claude`; a live probe of `sonnet` through the real CLI returned 1000000 and 128000 from `modelUsage`. The probe runs isolated like every `claude-cli` call, at effort `low`.

The full suite passes on `fza-fork`, the example module included.
