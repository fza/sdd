An agent is to start a new sdd session by itself when the ground topic of a conversation changes, and the daily sweep is to remove an open session untouched for `sessions.retention` unless a move is in progress in it.

## Sessions on a topic change

The served instructions of the session shell (20260704-100000-d-prc-dlg) tell the agent to start a new session when the ground topic of the conversation changed. The agent judges when that is. It does not ask the person about session handling. This holds in every dialogue mode.

The agent keeps the earlier session's handle and does not conclude that session. When the topic returns, the agent resumes it. The earlier session still holds its parked moves and the record of what it read, so going back costs less than a new reading of the graph in a fresh session. The handle was issued to the agent, so the person does not have to supply it. This revises two passages of the shell's served text: the rule that other dialogues are the user's to name by handle, and the promise that a session nobody ended stays resumable by its handle, which the sweep below ends for an idle session with no move in progress.

## Open sessions in the daily sweep

A session left on a topic change stays open. Today the daily sweep, the background run of `sdd cache prune`, removes only ended sessions, once `sessions.retention` (default `14d`, `DefaultSessionRetention` in `internal/model/config.go`) has passed since they ended. It never removes an open session (`StateSweep` in `pkg/local/state_sweep.go`, `CollectSessions` in `pkg/application/collect.go`). Each session left on a topic change would therefore stay on disk for good.

Of the open sessions whose log holds no event younger than `sessions.retention`, the sweep removes those with no move in progress (the session shell's own instance does not count as a move), with their staged attachments, as it does for an ended session. A session with a move in progress stays, whether the move was parked or left mid-step. An open session inside the retention stays. So does a log the sweep cannot read.

sdd tells the cases apart from the session log. A `park` call writes a parked event into the log (`EventParked` in `internal/engine/session.go`). A move left mid-step writes no such event and is still a running move. sdd keeps no record of idleness: idle time is the time since the log's last event.

This revises two earlier rules. Rules 2 and 3 of the daily sweep directive (20261114-095140-d-cpt-ad4) kept every open session, and rule 2 rejected ending idle sessions while sparing parked ones. The session collection rule (20260914-113911-d-tac-wgw) left every unended session untouched. Both accepted that open sessions pile up. With a session left behind on every topic change, that growth becomes the normal case. The other safeguards of 20260914-113911-d-tac-wgw stand: resources a pending write claims stay, and the sweep completes no pending write.

## Structure

The sweep rule changes the existing collection command (`collectSessions` in `pkg/application/collect.go`), which today selects only ended sessions: it also selects open sessions past the retention with no move in progress, read from the session events it already loads. No CLI action, query or model type is added. The topic-change rule is served text of the session shell only.

## Rejected

- Keep only sessions holding an explicitly parked move. A draft left mid-step without `park` would be gone after the retention.
- Remove every idle open session. Parked work would be lost.
- Leave the sweep as it is. Every session left on a topic change would stay for good.

## Accepted cost

Every abandoned draft stays on disk until someone resumes or drops it. The sweep never removes a session whose move nobody returns to.

On a machine that also runs stock sdd, the session folders are shared (item 28 of 20261119-013237-d-cpt-fu4): the fork's sweep removes an idle open session stock wrote in a project the fork has used, where stock keeps every open session.

## Not covered

sdd does not check whether the ground topic changed. The judgement is the agent's. The plan adds no config key: the rule for open sessions uses `sessions.retention`.

## Acceptance criteria

- [ ] The session shell's opening serve, in every dialogue mode, tells the agent to start a new session by itself when the ground topic of the conversation changed, without asking the person.
- [ ] The same instructions tell the agent to keep the earlier session's handle, to leave that session unconcluded and to resume it when the topic returns.
- [ ] The shell's served text no longer says that a session nobody ended stays resumable by its handle, and its rule that other dialogues are the user's to name by handle admits the agent resuming a session whose handle it was issued.
- [ ] A test shows the sweep removes an open session with no move in progress whose log's last event is older than `sessions.retention`, with its staged attachments.
- [ ] A test shows the sweep keeps an open session past the retention that holds a parked move.
- [ ] A test shows the sweep keeps an open session past the retention that holds a move left mid-step without `park`.
- [ ] A test shows the sweep keeps an open session with no move in progress whose last event lies inside the retention.
- [ ] The help text of `sdd cache prune` and the configuration reference (`website/src/content/docs/reference/configuration.md`) state the rule for open sessions.
