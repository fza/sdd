When a gate step holds, the engine lists the failing predicates of every transition out of it, so the agent reads conditions of paths it is not on as things it owes. A guided capture with no hooks, refused at `assemble` before any `gather`, was served:

- the hooks' findings have not been weighed
- the capture has no credited reading: call gather with instance i_2 (only reads through gather inside the capture count), then report again
- predicate autonomousDialogue does not hold
- predicate verifyBeforePlayback does not hold

Only the second line names work the agent owes. The first concerns a project with hooks, the last two are conditions of the autonomous path and print internal predicate names. Seen three times in one live test run of the `fza-fork` build; the agent ignored the noise correctly each time, but a weaker agent may chase it.

The list comes from `transitionDiagnostics` in `internal/engine/instance.go`, used when a gate's guard holds and no collect field is missing: it names what holds each transition, without telling which transition the step is meant to take.
