title: Work repository local config overlay
summary: A command run in the work repository now overlays its `.sdd/config.local.yaml` over the project's config, and that file may set any machine-local key — not just `project_dir` and `hooks` — including `contribution`, while its committed config keeps only its pointer keys. This refines the placement directive's overlay order with the work-local layer (20260708-184318-d-cpt-6cq) and widens the project_dir layout's local file (20261028-115146-s-tac-15i), building on the hooks directive (20261109-213250-d-tac-bve). It retires the contribution-mode claim that the work repository's local file refuses `contribution` (20261027-113552-s-tac-1rb) while keeping its guard rule, and aligns with `graph_repo`'s local layer in the code repository (20261107-050702-s-tac-qgx) and the `--local-config` flag (20261028-113856-s-tac-sxc).

In a `project_dir` layout, a command run in the work repository lays the work repository's `.sdd/config.local.yaml` over the project's own, so a person keeps machine-local settings beside the checkout they work in. The layers then apply in this order, later over earlier: built-in defaults, the user-global config, the project's committed `config.yaml`, the project's `config.local.yaml`, the work repository's `config.local.yaml`. The work repository's local file may set any machine-local key, where the `project_dir` layout (20261028-115146-s-tac-15i) allowed only `project_dir` and, later, `hooks` (20261109-213250-d-tac-bve). `sdd config set --local` run in the work repository writes that file, and `sdd config` names its values `work local`. The global `--local-config` flag (20261028-113856-s-tac-sxc) keeps naming the one machine-local file a run reads and writes, in place of both local files. A `graph_repo` setup already keeps its local layer in the code repository (20261107-050702-s-tac-qgx), so both split layouts place machine-local settings where the work happens. The work repository's committed config stays limited to its pointer keys. The local file may now also set `contribution`, which 20261027-113552-s-tac-1rb records as refused there; the guard still judges the branch the project's checkout has checked out, where the graph's commits land.

Without this layer, a machine-local setting for runs in a work repository goes into the project's `config.local.yaml`, which sits in another checkout and applies to every run against the project.

Rejected: a per-graph machine layer in the user-global config, since it keeps the setting away from the checkout it applies to and needs a key per graph; keeping `project_dir` as it was, since its work repository then cannot hold a personal setting at all. Accepted cost: about 12 call sites read two local files instead of one, plus the provenance view and docs.
