MCP results come back as objects when `sessions.token_saving` is off: commit `905d3993` on `pr/feat-mcp-objects`, merged into `fza-fork` as `535e642b`. It fulfills 20261101-165616-d-tac-qtk.

`Application.Show` returns each shown entry as data (identity, derived status, full body, and both chains with edge, ref kind, description and depth), and `Search` returns each hit with identity, status, summary and score. The session framing comes as named blocks: `info`, each shell lane by its inject id, and `health`. With the key off, the MCP server fills `items` on `show`, `hits` on `search`, and `lanes` and `framing_blocks` on every serve, base junction and `resume_session`, and leaves `entries`, `results`, `instructions` and `framing` empty. Each new field is emitted as a list, empty or not, only in that setting, so its presence tells which shape a result carries. Resume instructions form a lane named `resume`, the gate's diagnostics a lane named `diagnostics`, and a serve without declared lanes one lane named `instructions`.

One shape differs from the decision's: show chains are flat lists in preorder with a `depth` on each item, not nested items, because the MCP SDK cannot derive an output schema for a recursive type. The size-budget cut of each direction sits on the entry as `upstream_truncated` and `downstream_truncated`. The agentic-helpers hook is built against this shape.

The application still renders the text beside the data, so 20260928-080143-d-cpt-kv4's move of text rendering into the shells stays open; `sdd show` on the CLI is unchanged and reads the finders directly.

Tests cover the structured application results and both result shapes over MCP. The tool-schema snapshot gains only the new fields. The full suite on `fza-fork` passes except TestConflictingUpstreamIsReportedAndNothingMerged, which also fails without this change.
