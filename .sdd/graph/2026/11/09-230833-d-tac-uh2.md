`claude-cli` reports its model's context window to sdd, read from the claude CLI's own JSON output, so the `prose` default of the unified `verify` block (20261109-222220-d-tac-4ev) works without `llm.context_tokens`; `codex` keeps requiring that key.

The light verifier sizes each call by the model's window (20261109-004729-d-cpt-xs5): `llm.context_tokens` when set, else what the provider reports, else the call is refused naming the key. Window detection covered `anthropic`, `openai` and `ollama` only, so on the default provider `claude-cli` every capture under `prose` was refused until the key was set by hand.

`claude -p --output-format json` returns `modelUsage.<model>.contextWindow` and `maxOutputTokens`. sdd runs one short probe call per process and model and caches both values; `llm.context_tokens` still wins when set. `codex exec --json` reports token use only, never a window, so `codex` stays on the key, and the refusal names it.

Rejected, with the reasoning: `sdd init` asking every CLI user for the window (a number to look up, stale after a model switch); init asking only codex users (an extra prompt and its tests for one provider); a model-to-window table in the binary (it ages with every model release); leaving it as built (the default install cannot capture).

Accepted costs: one small paid probe call per process and model on `claude-cli`; sdd tracks the CLI's `modelUsage` fields.

## Acceptance criteria

- [ ] On `claude-cli` without `llm.context_tokens`, a `prose` capture sizes its calls from the probed `contextWindow` and `maxOutputTokens`, probing once per process and model.
- [ ] `llm.context_tokens` set wins over the probe.
- [ ] On `codex` without `llm.context_tokens`, the call is refused naming the key.
