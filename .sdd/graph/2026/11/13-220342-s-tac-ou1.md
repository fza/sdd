A failed headless Codex verifier round now names the cause Codex reported in its JSON events, such as a spent usage limit, instead of Codex's first stderr line. Codex capture eval runs on `fza-fork` (two batches of three runs, builds `369cb6fe` with fixes and `719cfd12`) showed the capture's deepFailed step reporting "Reading additional input from stdin...", which hid the real cause. The failing rounds are the headless Codex rounds the token-cost build added (20261112-195218-s-tac-day).

In `internal/delegatelaunch/delegatelaunch.go`, `run` keeps stdout on a nonzero exit, and `runCodex` scans the events first and also reads `turn.failed`'s `error.message`. Commit `94939671` on branch `pr/fix-eval-defects-2`, merged into `fza-fork` at `1b04d01e`. Test `TestRun_CodexFailureNamesTheCauseFromItsEvents` failed before the change and passes after; breaking the guard made it fail, and the file was restored.

Open: no real-agent run has shown it yet. The eval login hit its usage limit until 2026-12-09, so no Codex rerun was possible.
